# 审核系统 — OpenAI、Perspective、Llama Guard

> 生产环境的审核系统将第12-16课中定义的安全策略实现为可操作的工具。OpenAI 审核 API：`omni-moderation-latest`（2024年），基于 GPT-4o，支持一次调用中对文本 + 图片分类；在多语言测试集上比之前版本提升42%；响应架构返回13个类别布尔值——骚扰、骚扰/威胁、仇恨、仇恨/威胁、非法、非法/暴力、自残、自残/意图、自残/指令、性相关、性相关/未成年人、暴力、暴力/图形；对大多数开发者免费。分层模式：输入审核（生成前）、输出审核（生成后）、自定义审核（领域规则）。异步并行调用隐藏延迟；标记时展示占位响应。Llama Guard 3/4（第16课）：14个 MLCommons 危害类别，代码解释器滥用，支持8种语言（v3），多图像（v4）。Perspective API（Google Jigsaw）：毒性评分系统，早于以大语言模型（LLM）作为审核器的浪潮；主要单维度毒性及其严重毒性/侮辱/脏话变体；内容审核研究的基线。废弃情况：Azure 内容审核器于2024年2月废弃，2027年2月退役，替代为基于LLM且与Azure OpenAI集成的Azure AI内容安全。

## 概念

### OpenAI 审核 API

`omni-moderation-latest`（2024年）。基于GPT-4o构建。一次调用即可对文本+图片分类。大部分开发者免费使用。

类别（响应架构中13个布尔值）：  
- 骚扰，骚扰/威胁  
- 仇恨，仇恨/威胁  
- 自残，自残/意图，自残/指令  
- 性相关，性相关/未成年人  
- 暴力，暴力/图形  
- 非法，非法/暴力  

多模态支持适用于`暴力`、`自残`和`性相关`，但不支持`性相关/未成年人`；其余类别仅限文本。

在 `code/main.py` 的代码框架中，为了教学简化，将 `/威胁`、`/意图`、`/指令` 和 `/图形` 子类别合并到其顶级父类别。生产代码应使用完整的13类别架构。

比上一代审核端点在多语言测试集上提升42%。各类别评分分开，应用根据阈值设定决定。

### Llama Guard 3/4

第16课覆盖。14个 MLCommons 危害类别（与OpenAI的13布尔类别组织不同）。支持8种语言（v3）。Llama Guard 4（2025年4月）原生多模态，12B参数。

OpenAI 和 Llama Guard 的分类法部分重合但又有差异。OpenAI将“非法”视为广义类别，Llama Guard将“暴力犯罪”和“非暴力犯罪”分开。部署方根据策略分类法适配选择。

### Perspective API（Google Jigsaw）

LLM作为审核器浪潮之前的毒性评分系统（2020年前）。分类：TOXICITY（毒性）、SEVERE_TOXICITY（严重毒性）、INSULT（侮辱）、PROFANITY（脏话）、THREAT（威胁）、IDENTITY_ATTACK（身份攻击）。主分数为单一维度（TOXICITY），带有子维度变体。

因API稳定、文档完善并拥有多年校准数据，广泛用作内容审核研究基线。对现代LLM相关用例，通常Llama Guard或OpenAI审核更合适。

### 三层模式

1. **输入审核。** 在生成前对用户提示分类。如被标记则拒绝。延迟：一次分类调用。  
2. **输出审核。** 在生成后对模型输出分类。如被标记则替换为拒绝响应。延迟：生成后一次分类调用。  
3. **自定义审核。** 领域特定规则（正则表达式、允许列表、业务策略）。可运行于输入或输出阶段。

三层顺序设计：输入审核必须完成后方能生成，输出审核在生成后运行。层内可并行——在同一文本上同时运行多个分类器（如OpenAI审核 + Llama Guard + Perspective）能隐藏单个分类延迟。可选优化是在输入审核完成前显示占位响应（“请稍候，正在检查...”），并推迟token-1流式输出。标记行为可配置为拒绝、净化或升级至人工复审。

### 失败模式

- **仅输入。** 无法捕捉输出幻觉（第12-14课编码攻击绕过输入分类器）。  
- **仅输出。** 允许任何输入达到模型；增加成本；将内部推理暴露给攻击者。  
- **仅自定义。** 各类别鲁棒性差；正则表达式易碎。

分层是默认配置。保险措施。

### Azure废弃计划

Azure 内容审核器：2024年2月废弃，2027年2月退役。由基于LLM且与Azure OpenAI集成的Azure AI内容安全取代。迁移为2024-2027年间Azure部署的现场项目。

## 使用方法

`code/main.py` 构建三层审核框架：输入审核器（关键词 + 类别分数）、输出审核器（同一分类器用于输出）、自定义审核器（领域规则）。你可以输入文本，并观察各层拦截情况。

## 发布

本课输出 `outputs/skill-moderation-stack.md`。针对某个部署，推荐审核堆栈配置：输入层使用哪分类器，输出层使用哪分类器，自定义规则，以及边缘案例的裁定方式。

## 练习

1. 运行 `code/main.py`。分别通过三层审核输入一个无害、边缘和有害的文本。报告哪层触发。

2. 用Perspective API风格的毒性评分扩展审核框架，对指定类别评分。比较其阈值表现与该类别分数。

3. 阅读OpenAI审核API文档和Llama Guard 3类别列表。将每个OpenAI类别映射到最接近的Llama Guard类别。找出三个无法准确映射的类别。

4. 设计一套代码助手（如GitHub Copilot）的审核堆栈。识别最相关和最不相关类别，并提出自定义规则。

5. Azure内容审核器将于2027年2月退役。规划迁移至Azure AI内容安全。识别迁移中风险最高的环节。
