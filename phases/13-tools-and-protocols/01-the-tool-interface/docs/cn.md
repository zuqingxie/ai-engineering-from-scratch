# 工具接口 — 为什么代理需要结构化输入输出

> 语言模型（language model, LLM）产生标记（tokens）。程序执行动作。两者之间的桥梁是工具接口：一个合约，允许模型请求动作，宿主执行它。每个2026年技术栈——OpenAI、Anthropic、Gemini上的函数调用；MCP的`tools/call`；A2A的任务部件——都是同一四步骤循环的不同编码。本课命名该循环，并展示运行它的最简机制。

**类型:** 学习  
**语言:** Python（标准库，无LLM）  
**先决条件:** 第11阶段（LLM完成API）  
**时间:** 约45分钟

## 学习目标

- 解释为什么只能生成文本的LLM本身不能对现实世界采取动作。
- 画出四步工具调用循环（描述 → 决定 → 执行 → 观察）并说明每步的负责方。
- 编写工具描述的三部分：名称，JSON Schema输入，确定性执行函数。
- 区分纯工具（pure tool）和副作用工具（side-effecting tool），并说明该区别对安全的重要性。

## 问题

LLM发出对下一个标记的概率分布，这就是它全部的输出。若询问聊天模型“班加罗尔现在的天气如何”，它可以写出合理句子，但它不能直接访问天气API。该句可能是巧合正确，也可能是三天前的数据。

架起这一桥梁就是工具接口的目的。宿主程序——你的代理运行时、Claude Desktop、ChatGPT、Cursor或自定义脚本——向模型公开可调用的工具列表。当模型判断需要动作时，发出结构化载荷，命名工具及其参数。宿主解析载荷，实际运行工具，将结果反馈回模型。循环继续，直到模型不再需要调用。

2023年6月，OpenAI率先发布此合约的第一版——“functions”参数。随后Anthropic在Claude 2.1中加入`tool_use`块，几个月后Gemini增加`functionDeclarations`。现在各供应商均提供同样格式：输入为JSON-Schema类型的工具列表，输出为JSON载荷的工具调用。Model Context Protocol (2024年11月)将该合约泛化，实现一个工具注册表为所有模型服务。A2A (2026年4月，v1.0) 在此基础上提供代理间委派原语。

这四步骤循环是其内核不变的核心。第13阶段的其他内容都是细节和扩展。

## 概念

### 第一步：描述（describe）

宿主用三个字段声明每个工具。

- **名称（Name）**。稳定且机器可读的标识符。如 `get_weather`，不是“weather thing”。
- **说明（Description）**。一段自然语言简述。“用于用户询问特定城市当前天气时。不要用于历史数据。”
- **输入模式（Input schema）**。JSON Schema对象（2020-12草案），描述工具参数。

模型接收该列表。现代供应商通过特定模板把这部分序列化入系统提示，所以调用者只需处理结构化形式。

### 第二步：决定（decide）

根据用户消息和可用工具，模型展开三种行为之一：

1. **直接文本回答**。不调用工具。
2. **调用一个或多个工具**。发出结构化调用对象。在`parallel_tool_calls: true`（OpenAI和Gemini默认开启，Anthropic为可选）时，模型能在一个回合内发多条调用。
3. **拒绝调用**。严格模式输出可以生成带类型的`refusal`块而非调用。

工具调用载荷有三固定字段：调用`id`，工具`name`，JSON格式的`arguments`。`id`方便宿主将之后的结果与具体调用对应，这在并行调用返回顺序不一时尤为重要。

### 第三步：执行（execute）

宿主收到调用后，校验参数是否符合声明的schema，然后运行执行函数。参数无效说明模型出现幻觉字段或使用了错误类型——这是弱模型常见故障模式。生产宿主针对无效参数采取三种措施之一：快速失败并将错误反馈模型，用受限解析器修正JSON，或带入验证错误重新调用模型。

执行器本质是普通代码。Python、TypeScript、Shell命令、数据库查询均可。它产生结果，通常是字符串，也可以是任意JSON值或结构化内容块（在MCP中为文本、图像或资源引用）。结果必须可序列化。

### 第四步：观察（observe）

宿主将工具结果附加至对话（以带对应`id`的`tool`角色消息），并重新调用模型。此时模型上下文中已有工具输出，能生成最终答案或请求更多调用。如此循环直至模型停止调用或宿主达到安全迭代限制。

### 信任分界

工具按安全性分两类：

- **纯工具（Pure）**。只读、确定性、无副作用。如`get_weather`、`search_docs`、`get_current_time`。可安全并发调用。
- **后果工具（Consequential）**。改变状态、花钱、处理用户数据。如`send_email`、`delete_file`、`execute_trade`。必须采取安全管控。

Meta 2026年提出的代理安全“二规则”指出，同一回合最多涉及两类：不可信输入、敏感数据、后果动作。工具接口即执行此规则的场所——拒绝调用、要求用户确认或提升权限分级。详见第13阶段·15完整安全章节，以及第14阶段·09代理权限策略。

### 为什么不直接让模型输出JSON？

“让模型输出JSON”是函数调用出现前的方案。它在前沿模型上失败率约5%-15%，更小模型甚至更高。失败原因包括遗漏括号、尾逗号、多余字段、类型错误。然后需修JSON、重试或使用受限解码器。

原生函数调用优势有三。首先，供应商端到端训练模型输出规范调用格式，严格模式下有效JSON率升至98%-99%。其次，调用载荷独立在协议槽中，不混入自由文本，调用永不泄露给用户回复。最后，供应商用受限解码确保输出符合schema（OpenAI严格模式、Anthropic`tool_use`、Gemini`responseSchema`）。输出必定校验通过。

### 断路器

循环在模型停止调用或宿主达到最大回合数时终止。生产宿主设置5 ~ 20回合之间。超过此数，模型极有可能陷入无法退出的循环。Claude Code默认为20，OpenAI助理为10，Cursor代理模式为25。

另一种是无限循环，每半年发布一次“代理一夜间API调用花费400美元”事后分析。务必设限。

## 使用指南

`code/main.py`实现无LLM的四步循环。模拟“决策者”函数用模式匹配用户消息充当模型；执行器、模式校验器和观察步骤皆真实实现。运行即可见带可打印中间状态的完整请求/响应流程，之后在后续课程中用实际供应商替换虚假决策者。

建议关注：

- 工具注册表存储每工具三字段：名称、说明、模式，以及执行器引用。
- 校验器为标准库实现的最小JSON Schema子集（类型、必填、枚举、最小/最大）。第13阶段·04将提供更完整版。
- 循环限制迭代次数为5。生产代理需要此类断路器。

## 发布产出

本课生成文件`outputs/skill-tool-interface-reviewer.md`。给定草稿工具定义（名称+说明+模式+执行器概要），技能审查其循环适用性：名称是否稳定、说明是否完整、模式是否正确使用2020-12版本JSON Schema、纯与后果工具类别是否明确。

## 练习

1. 在`code/main.py`中添加第四个工具`get_stock_price(ticker)`。写说明：“当用户询问特定股票代码当前股价时使用。不要用于历史价格或市场综述。”运行程序，确认模拟决策者把包含股票代码查询路由至新工具。

2. 故意弄坏模式校验器。传入缺少必填字段的调用，确认宿主执行前拒绝。然后传入多了未知字段的调用。决定宿主应该拒绝还是忽略，并用安全理由支持你的选择。

3. 将工具分类为纯工具或有后果工具。对需要的注册表条目添加`consequential: true`标志，并在循环中每当选中有后果工具时打印“将请求用户确认”提示。这是生产宿主确认门控的形态。

4. 纸上绘制四步循环，填入上表你喜欢的客户端（Claude Desktop、Cursor、ChatGPT或定制栈）的对应列。与第13阶段·06的MCP特定变体交叉验证。

5. 通读OpenAI函数调用指南。找出请求中存在但本四步循环中未出现的字段。说明它的作用及为何方便但非必要。

## 关键术语

| 术语           | 常见说法             | 实际含义                                     |
|----------------|----------------------|----------------------------------------------|
| Tool（工具）   | “模型可调用的东西”   | 名称 + JSON-Schema类型输入 + 执行函数三元组 |
| Function calling（函数调用） | “原生工具调用”       | 供应商级API支持发出结构化工具调用而非文本         |
| Tool call（工具调用）| “模型的请求动作”     | LLM发出的含`id`、`name`、`arguments`的JSON载荷  |
| Tool result（工具结果）| “工具返回值”        | 执行器输出，封装在带匹配id的`tool`角色消息中      |
| Parallel tool calls（并行调用）| “一次多调用”         | 一次模型回合中多个调用对象，独立且可排序            |
| Strict mode（严格模式）| “保证有效JSON”        | 受限解码保证输出校验通过声明的JSON Schema          |
| Pure tool（纯工具） | “只读工具”            | 无副作用，可重入安全调用                            |
| Consequential tool（有后果工具）| “动作工具”          | 变更外部状态，需门控、审计或用户确认               |
| Four-step loop（四步循环）| “工具调用循环”        | 描述（describe）→ 决定（decide）→ 执行（execute）→ 观察（observe） |
| Host（宿主）    | “代理运行时”           | 持有工具注册表、调用模型及运行执行器的程序          |
