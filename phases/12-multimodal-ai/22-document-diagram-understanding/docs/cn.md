# 文档与图表理解

> 文档不是照片。PDF、科研论文、发票或手写表单具有布局、表格、图表、脚注、页眉和语义结构，普通图像理解无法捕捉。预VLM时代的技术栈是一个流水线：Tesseract OCR + LayoutLMv3 + 表格提取启发式算法。VLM浪潮用无OCR模型取代了这一切——Donut（2022）、Nougat（2023）、DocLLM（2023）——直接输出结构化标记。到了2026年，前沿只需“将页面图像以2576px原生分辨率输入Claude Opus 4.7”，结构化标记输出随之而来。本课将介绍文档AI的三个时代发展轨迹。

**类型：** 构建  
**语言：** Python（标准库，支持布局感知文档解析器骨架）  
**先修要求：** 第12阶段·05（LLaVA），第5阶段（NLP）  
**时长：** 约180分钟  

## 学习目标

- 解释文档AI的三个时代：OCR流水线、无OCR、VLM原生。  
- 描述LayoutLMv3的三种输入流：文本、布局（bbox），图像块，并介绍统一掩码机制。  
- 比较Donut（无OCR，图像→标记）、Nougat（科研论文→LaTeX）、DocLLM（布局感知生成）、PaliGemma 2（VLM原生）。  
- 为新任务（发票、科研论文、手写表单、中文收据）选择合适的文档模型。  

## 问题背景

“理解此PDF”极具挑战。关键信息分布于：

- 文本内容（90%的信号）  
- 布局（页眉、脚注、边栏、双栏格式）  
- 表格（行、列、合并单元格）  
- 图形与图表  
- 手写批注  
- 字体与排版（标题与正文）  

原始OCR仅提取文本，丢失其他信息。关注发票时，系统需要知道“总计：$1,245”来自右下角，而非脚注。

## 核心概念

### 第一时代——OCR流水线（2021年前）

经典技术栈：

1. PDF → 每页图像。  
2. Tesseract（或商业OCR）识别文本及单词级bbox。  
3. 布局分析器识别文本块（页眉、表格、段落）。  
4. 表格结构识别器解析表格。  
5. 领域规则 + 正则表达式提取字段。  

适用于干净的打印文本。遇到手写、倾斜扫描、复杂表格、非英语脚本则表现差。每种失败场景都需定制异常处理路径。

### TrOCR（2021）

TrOCR（Li 等，arXiv:2109.10282）用transformer编码解码器替代了Tesseract经典的CNN-CTC，训练于合成与真实文本图像。对手写和多语言文本识别大胜。仍是流水线（先检测，后TrOCR，再布局），但OCR步骤显著提升。

### 第二时代——无OCR（2022-2023）

第一批无OCR模型主张：跳过检测，直接将图像像素映射为结构化输出。

Donut（Kim 等，arXiv:2111.15664）：  
- 编码解码transformer，编码器为Swin-B。  
- 输出为JSON（表单理解）、Markdown（摘要）或任何任务特定结构。  
- 无需OCR、无布局、无检测。  

Nougat（Blecher 等，arXiv:2308.13418）：  
- 专门训练于科研论文。  
- 输出LaTeX/Markdown。  
- 处理公式、多栏布局、图形。  
- 每个arXiv解析器的首选模型。  

它们是专业模型，非通用。Donut处理科研论文失败，Nougat识别发票失败。

### LayoutLMv3（2022）

另一种方案。LayoutLMv3（Huang 等，arXiv:2204.08387）保留OCR，同时增加布局理解：  

- 三输入流：OCR文本令牌、每令牌二维bbox、图像块。  
- 跨模态统一掩码训练目标（文本、图像块、布局均被掩码）。  
- 下游任务：分类、实体抽取、表格问答。  

LayoutLMv3是基于OCR的文档理解巅峰。对表单和发票表现强劲。依赖上游OCR。实现标准化文档基准的最佳预VLM准确率。

### DocLLM（2023）

DocLLM（Wang 等，arXiv:2401.00908）是LayoutLM的生成式兄弟。基于布局令牌生成自由形式回答。对文档问答更佳，仍依赖OCR输入。

### 第三时代——VLM原生（2024及以后）

2024年，VLM（视觉语言模型）足够强大，完全取代流水线。将整页高分辨率图像输入VLM，提问，得到答案。

- LLaVA-NeXT 336块AnyRes适合小文档。  
- Qwen2.5-VL动态分辨率原生支持2048+像素。  
- Claude Opus 4.7支持2576px文档。  
- PaliGemma 2（2025年4月）专门训练于文档+手写。  

VLM原生与OCR流水线的差距迅速缩小。到2026年，VLM原生在以下领域胜出：

- 场景文本（手写+打印，混合脚本）。  
- 复杂合并单元格表格。  
- 数学公式嵌入文本。  
- 带文本注释的图形。  

OCR流水线仍擅长：

- 静态海量扫描，关注单页延迟。  
- 流水线可靠性（确定性失败 vs VLM幻觉）。  
- 需要可审计OCR输出的监管环境。  

### Claude 4.7 / GPT-5 前沿

在2576像素原生输入下，前沿VLM具备近人类准确率的文档理解能力。2026年初基准数据：

- DocVQA：Claude 4.7 ~95.1，PaliGemma 2 ~88.4，Nougat ~77.3，流水线LayoutLMv3 ~83。  
- ChartQA：Claude 4.7 ~92.2，GPT-4V ~78。  
- VisualMRC：Claude 4.7 ~94。  

闭源模型差距主要在分辨率和基础LLM规模。开源7B模型落后几分，但正在追赶。

### 数学公式与LaTeX输出

科研论文需要精确LaTeX公式输出。Nougat专门训练于此。通过LaTeX目标训练的VLM（Qwen2.5-VL-Math、Nougat派生模型）生成可用LaTeX。未显式训练LaTeX的VLM产生可读但不精确的转录结果。

2026年科研流程建议：使用Nougat解析PDF公式困难页，再用VLM处理图形。

### 手写

依然是最难子任务。混合打印+手写（医生笔记、填表）时，OCR流水线在成本上更具优势。纯手写VLM持续改进（Claude 4.7、PaliGemma 2）。

### 2026年方案

新文档AI项目：

- 纯印刷发票大规模处理：LayoutLMv3+规则，成本效益高。  
- 混合文档（科研+手写+表单）：VLM原生（PaliGemma 2 或 Qwen2.5-VL）。  
- 全文arXiv摄取：Nougat处理数学，VLM负责图形。  
- 监管合规：OCR流水线作为主，VLM作二次交叉核验。

## 关键术语

| 术语 | 常见说法 | 实际含义 |
|------|----------|-----------|
| OCR流水线 | “Tesseract风格” | 阶段式堆栈：检测->OCR->布局->规则；确定性，脆弱 |
| 无OCR | “Donut风格” | 图像到输出transformer，跳过显式OCR；单模型 |
| 布局感知 | “LayoutLM” | 输入包含逐令牌bbox坐标；跨模态统一掩码 |
| VLM原生 | “前沿VLM” | 将页图像高分辨率输入Claude/GPT/Qwen VLM；无流水线 |
| DocVQA | “文档基准” | 文档视觉问答标准；引用率最高得分 |
| 标记输出 | “LaTeX / MD” | 结构化输出格式替代自由文本；支持下游自动化 |
