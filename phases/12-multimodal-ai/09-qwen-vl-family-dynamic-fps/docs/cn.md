# Qwen-VL 系列与动态 FPS 视频

> Qwen-VL 系列 —— Qwen-VL（2023）、Qwen2-VL（2024）、Qwen2.5-VL（2025）、Qwen3-VL（2025）—— 是 2026 年最具影响力的开源视觉-语言模型系列。每一代都做出了一个决定性的架构赌注，其余开源生态系统在十二个月内复制：通过 M-RoPE 实现本地动态分辨率，动态 FPS 采样带绝对时间对齐，ViT 中的窗口注意力，以及结构化的代理输出格式。到了 Qwen3-VL，配方已经稳定：采用原生宽高比输入的 2D-RoPE-ViT 编码器，连接到大型 Qwen3 语言基础的大型 MLP 投影器，训练阶段重点强调 OCR、定位和代理行为作为一级目标。本课按时间顺序讲解该系列，让你理解每个设计选择的原因。

**类型:** 学习  
**语言:** Python（标准库，M-RoPE 编码器 + 动态 FPS 采样器）  
**先决条件:** 阶段 12 · 06（patch-n'-pack）  
**时间:** ~120 分钟

## 学习目标

- 计算 M-RoPE 的三个轴向旋转（时间、宽度、高度），并解释为何需要这三者。
- 为视频选择动态 FPS 采样策略，并分析 tokens-per-second 与事件检测准确率的权衡。
- 按顺序列举 Qwen-VL 四代升级及其带来的功能。
- 连接一个 Qwen2.5-VL 风格的 JSON 代理输出格式，并解析来自 VLM 响应的结构化工具调用。

## 问题背景

Qwen-VL 于 2023 年 8 月发布，作为对 LLaVA-1.5 和 BLIP-2 的直接回应。Qwen 团队针对的差距有三点：分辨率、视频和结构化输出。

分辨率：LLaVA-1.5 运行时分辨率为 336x336。适合照片，不适合中文发票或密集的电子表格截图。Qwen-VL 首创 448x448 分辨率及带定位边界框输出，让模型能指向具体位置。

视频：Video-LLaMA 堆叠逐帧编码器，输入到 LLM。适用于短视频，不适合多分钟视频无法充分利用时间轴信号。Qwen 团队想要一个理解时间的单一编码器。

结构化输出：LLaVA 输出自由文本，无法满足代理对 JSON 格式的需求。Qwen-VL 训练时加入了明确的 JSON 输出格式，包括文本形式的边界框坐标。

每一代 Qwen-VL 都是在增强这三个轴线上。

## 基本概念

### Qwen-VL（2023 年 8 月）

第一代：采用 OpenCLIP ViT-bigG/14 编码器（25 亿参数），兼容 LLama 的 Q-Former（单步，256 查询），Qwen-7B 基础模型。贡献包括：

- 448x448 分辨率（当时开源视觉语言模型的 SOTA）。
- 定位：训练时带有图文对的明确坐标 token 输出，示例："The cat is at <box>(112, 204), (280, 344)</box>"。
- 中文和英文多语种训练。

当时基准测试：英文与 GPT-4V 竞争，中文领先。定位监督是最大亮点。

### Qwen2-VL（2024 年 9 月）— M-RoPE 与原生分辨率

Qwen2-VL 用原生动态分辨率 ViT 编码器取代了固定分辨率 + Q-Former 堆栈。关键变化：

- 原生动态分辨率。ViT 接受任意 HxW，且均需能被 28 整除（14-patch，空间合并 2x）。如 1120x672（40x24 合并 patch）生成 960 个视觉 tokens。无须缩放、分块或缩略图。
- M-RoPE（多模态 RoPE）。每个 token 带有 3D 位置 (t，h，w)，而非一维。图像时 t=0，视频时 t=帧索引。RoPE 以每轴频率旋转 query/key 向量，无需位置嵌入表。
- MLP 投影器。摒弃 Q-Former，使用两层 MLP 处理合并的 patch tokens。
- 支持动态 FPS 视频。默认采样 1-2 FPS，但模型可接受任意帧数。

结果：Qwen2-VL-7B 在多模态基准上匹配 GPT-4o，在 DocVQA 上超越（94.5 比 88.4）。架构变革是关键。

### Qwen2.5-VL（2025 年 2 月）— 动态 FPS + 绝对时间

Qwen2.5-VL 视频上的大跃进。动态 FPS 不只是“需要时采更多帧”。论文形式化：

- 绝对时间 token。非帧索引（0, 1, 2...），而是实际时间戳。“0:04 时猫跳跃。”模型看到 `<time>0.04</time>` token 与帧 token 交错。
- 动态 FPS。慢动作采 1 FPS，动作多时采 4+ FPS。由用户或训练者选定，M-RoPE 自动适配。
- ViT 中窗口注意力。空间自注意力限制在小窗口内以提速，局部层出现全局注意力。
- 明确 JSON 输出格式。训练含工具调用数据示例：`{"tool": "click", "coords": [380, 220]}`。开箱即用，支持代理。
- MRoPE-v2 缩放。位置信号根据最大输入尺寸缩放，避免十分钟视频频率溢出。

基准：Qwen2.5-VL-72B 超越 GPT-4o 多数视频基准，匹配 Gemini 2.0 文档能力，GUI 定位（ScreenSpot）达到 84% 准确率（GPT-4o 38%）。

### Qwen3-VL（2025 年 11 月）

Qwen3-VL 是渐进式升级，整合而非推翻：更大 LLM 主干（Qwen3-72B）、扩充训练数据、改进 OCR、通过 Qwen3 “思考模式”加强推理。ViT 和 M-RoPE 保持不变。重点在数据和训练改进。

系列启示：到 2025 年 Qwen-VL 架构已稳定，新增世代主要扩展算力和数据，而非基础组件。

### M-RoPE 数学原理

经典 RoPE 将维度为 `d` 的查询向量 `q` 按位置 `m` 用成对坐标旋转：

```text
q_rot[2i]   = q[2i]   * cos(m * theta_i) - q[2i+1] * sin(m * theta_i)
q_rot[2i+1] = q[2i]   * sin(m * theta_i) + q[2i+1] * cos(m * theta_i)
theta_i     = 10000^(-2i/d)
```

M-RoPE 将隐藏维度分成三组。举例 `d=96`，各占 32 维：时间、高度、宽度。每组按对应轴位置旋转。位置 (t=5, h=10, w=20) 的 patch 分别应用 `R_t(5)`、`R_h(10)`、`R_w(20)`。

文本 token 使用 `t=text_index, h=0, w=0`（或归一化选择），保持兼容。视频帧使用 `t=frame_time, h=row, w=col`。单张图片 `t=0`。

好处：一套位置编码同时处理文本、图像和视频，无需多叉代码与多个位置表。

### 动态 FPS 采样逻辑

给定视频长度 `T` 秒和目标 token 预算 `B`：

1. 计算可承受最大 FPS：`fps_max = B / (T * tokens_per_frame)`。
2. 从 `{1, 2, 4, 8}` 中选最接近且不超过 `fps_max` 的 FPS。
3. 若运动激烈（光流启发式或用户请求），选较高 FPS；低运动则较低。
4. 以选定 FPS 均匀采样，帧间插入 `<time>t</time>` token。

Qwen2.5-VL 隐式训练此逻辑，推理时用户通过 `fps` 参数控制。示例：60 秒动作序列，4 FPS，81 tokens/帧，共 19440 tokens，在 32k 上下文内可控。

### 结构化代理输出

Qwen2.5-VL 代理训练明确针对结构化工具调用：

```text
{
  "tool": "mouse_click",
  "coords": [1024, 512],
  "button": "left",
  "modifier": null
}
```

解析可由 JSON.parse 直接完成。相比自由文本 “click at (1024, 512)” 需做正则和歧义处理，此方案使 ScreenSpot 分数从 Qwen2-VL 的 55% 飙升至 84%。

## 关键术语

| 术语               | 俗称             | 实际含义                                              |
|--------------------|------------------|-------------------------------------------------------|
| M-RoPE             | “多模态 RoPE”     | 具有时间、高度和宽度三个轴向的 3D 旋转位置编码              |
| 动态 FPS           | “智能采样”        | 根据视频的运动、时长和 token 预算动态选择的帧采样率            |
| 绝对时间 token      | “时间戳 token”     | `<time>t</time>` 插入序列中，使模型看到真实秒数而非帧索引          |
| 窗口注意力          | “局部注意力”       | 限制在小窗口内的空间自注意力以提升速度，定期加全局注意力           |
| 结构化代理输出       | “JSON 模式”        | 训练监督使 VLM 能输出可解析的带坐标和工具名称的 JSON               |
| min_pixels / max_pixels | “分辨率界限”      | Qwen2.5-VL 控制单次请求的总像素数，进而限制 token 数量               |
| 定位（Grounding）   | “指向模式”         | 输出文本形式的边界框坐标；自 Qwen-VL v1 起采用                      |
