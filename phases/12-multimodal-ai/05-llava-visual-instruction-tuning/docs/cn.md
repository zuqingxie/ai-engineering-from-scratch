# LLaVA 与视觉指令微调（Visual Instruction Tuning）

> LLaVA（2023年4月）是地球上被复制最多的多模态架构。它用一个两层 MLP 替代了 BLIP-2 的 Q-Former，用简单的 token 拼接替代了 Flamingo 的门控交叉注意力，并在 GPT-4 从纯文本标题生成的 158k 视觉指令轮次上训练。任何在 2023 到 2026 年间构建视觉语言模型（VLM）的实践者，都构建了某种变体的 LLaVA。LLaVA-1.5 增加了 AnyRes。LLaVA-NeXT 提升了分辨率。LLaVA-OneVision 将图像、多图像和视频统一在一个方案中。本课件读取该方案，实现投影器，并解释为何“更简单获胜”。

**类型：** 构建  
**语言：** Python（标准库、投影器 + 指令模板构建器）  
**前置知识：** 阶段 12 · 02（CLIP）、阶段 11（大语言模型工程 — 指令微调）  
**时长：** 约180分钟

## 学习目标

- 构建一个两层 MLP 投影器，将 ViT 的 patch 嵌入（维度 1024）映射到大语言模型的嵌入维度（维度 4096）。
- 了解 LLaVA 的两阶段方案：(1) 在 558k 标题对上训练投影器对齐，(2) 在 158k GPT-4 生成的视觉指令轮次上进行视觉指令微调。
- 构造一个 LLaVA 格式的提示，包含图像 token 占位符、系统提示和用户/助手轮次。
- 解释社区为何从 Q-Former 转向 MLP，尽管 Q-Former 在 token 预算上占优。

## 问题背景

BLIP-2 的 Q-Former（第 12.03 课）将图像压缩成 32 个 token。干净、高效，适合基准测试。但有两个问题。

首先，Q-Former 可训练但其损失并非最终任务。第一阶段训练 ITC+ITM+ITG，第二阶段训练语言模型（LM）损失。Queries 学习的是中间表示，后续 LLM 需解码，中间瓶颈会丢失信息。

其次，Q-Former 拥有 1.88 亿参数，在 LLaVA 2023 年的规模下，你必须与目标 LLM 协同设计。更换 LLM，需重训 Q-Former；更换视觉编码器，需重新训练。每种组合都是一个独立研发项目。

LLaVA 的答案简单得令人尴尬：对 ViT 的 576 个 patch token，分别用 2 层 MLP（1024 → 4096 → 4096）处理，然后直接全部 576 个投进 LLM 输入序列。没有瓶颈，没有第一阶段的怪异预训练目标，直接用语言模型损失训练 MLP。

数据来自哪里？LLaVA 的第二个洞察：用 GPT-4（文本版）生成指令数据。给 GPT-4 输入 COCO 标题和边界框数据，让它生成对话、描述和复杂推理题。免费得到 158k 指令-响应轮次，无需人工标注。

结果：一个在 8 张 A100 上运行一天的 VLM，击败 Flamingo 在 MMMU 上表现，并发布了开放检查点，社区可扩展。到 2023 年底，衍生出 50 多个分支。

## 核心概念

### 架构

LLaVA-1.5，13B 版本：  
- 视觉编码器：CLIP ViT-L/14 @ 336（阶段 1 冻结，阶段 2 可选解冻）。  
- 投影器：两层 MLP，GELU 激活，1024 → 4096 → 4096。  
- LLM：Vicuna-13B（后续用 Llama-3.1-8B）。

图像+文本提示的前向过程：

```text
img -> ViT -> 576 个 1024 维 patch
patches -> MLP -> 576 个 4096 维 token
prompt: 系统 + "<image>" 占位符 + 用户问题
将 <image> token 替换为 576 个投影 token
将完整序列送入 LLM
解码回复
```

图像占用了 LLM 上下文的 576 个 token。在 2048 上下文下，文本剩 1472 个 token；在 32k 上下文中，这不过是个小数。

### 阶段 1：投影器对齐

冻结 ViT，冻结 LLM，只训练两层 MLP。数据集：558k 图像-标题对（LAION-CC-SBU）。损失：在给定投影图像 token 条件下，对标题进行语言建模。

单个 epoch，批大小 128，几小时内完成。投影器学习从 ViT 空间到 LLM 空间的映射，无需任务特定监督。

### 阶段 2：视觉指令微调

解冻投影器（仍可训练），解冻 LLM（通常完全解冻，有时用 LoRA）。在 158k 视觉指令轮次上训练。

关键是指令数据。Liu 等人生成方法：  
1. 取一张 COCO 图像。  
2. 提取文本描述（5 条人工标题 + 边界框列表）。  
3. 发送给 GPT-4，使用三种提示模板：  
   - 对话："生成一个用户与助手关于此图像的交互对话。"  
   - 详细描述："提供该图像的丰富详细描述。"  
   - 复杂推理："提问一个关于该图像需要推理的问题，并作答。"  
4. 解析 GPT-4 输出为（指令、响应）对。

未直接触及图像，仅用文本描述。GPT-4 会幻想合理图像内容。有噪声，但有效：158k 轮足够解锁对话。

### 社区复制原因

- 无需针对阶段 1 特殊损失调整，全程用语言模型损失。  
- 投影器可在几小时内训练完成，不是几天。  
- 可通过重训投影器轻松更换 LLM（如 LLaVA-Llama2，LLaVA-Mistral，LLaVA-Llama3）。  
- 视觉指令数据管道用 GPT-4，生成经济且易于新领域再生成。

### LLaVA-1.5 与 LLaVA-NeXT

LLaVA-1.5（2023年10月）增加：  
- 学术任务数据（VQA、OKVQA、RefCOCO）混入指令微调。  
- 更佳系统提示。  
- 2048 → 32k 上下文。

LLaVA-NeXT（2024年1月）增加：  
- AnyRes：将高分辨率图像分割为 2x2 或 1x3 的 336x336 裁剪格，加上一个全局低分辨率缩略图。每个裁剪转为 576 tokens；每图约 2880 视觉 tokens。OCR 和图表任务大跃进。  
- 用 ShareGPT4V（高质量 GPT-4V 标题）混合更优指令数据。  
- 基础 LLM 更强（Mistral-7B，Yi-34B）。

### LLaVA-OneVision

12.08 课详细介绍 OneVision。简而言之：用相同投影器，通过课程学习覆盖单图、多图和视频，一个模型共用视觉 token 预算。

### 与 Q-Former 的对比

|                | Q-Former（BLIP-2） | MLP（LLaVA）         |
|----------------|--------------------|----------------------|
| 图像视觉 tokens | 32                 | 576（基础）或 2880（AnyRes） |
| 可训练参数数   | 1.88亿 + LM         | 4000万 + LM          |
| 阶段 1 损失    | ITC+ITM+ITG         | 仅语言模型           |
| LLM 替换       | 需重训              | 仅需少量重训         |
| 多图像支持     | 不便                | 自然（拼接）         |
| 视频支持       | 不便                | 自然（逐帧拼接）     |
| Token 预算     | 小                  | 大                   |

MLP 在简单性和 token 灵活性上胜出。Q-Former 在 token 预算上领先。到 2023 年底，token 预算不再是瓶颈（LLM 上下文扩展到 32k-128k+），简单性成主导。

### 提示格式

```text
一段好奇的人类与人工智能助手的对话。助手提供对人类提问的有帮助、详细且礼貌的回答。  
USER: <image> 请详细描述这张图像。  
ASSISTANT: 这幅图像展示了...
```

`<image>` 是占位 token。Tokenize 前替换成 576 个视觉 token（AnyRes 为 2880）。Tokenizer 会遇到比训练时更长的序列，但阶段 1 教会了模型应对。

### 参数经济性

LLaVA-1.5-7B 参数分布：  
- CLIP ViT-L/14 @ 336：3.03 亿（阶段 1 冻结，阶段 2 通常解冻）。  
- 投影器（2 个线性层）：约 2200 万可训练参数。  
- Llama-7B：70 亿。  
- 总计：73 亿参数。阶段 2 可训练参数：70 亿 LLM + 2200 万投影器。

阶段 2 训练时间：8x A100 约 20 小时。关键数字 — 一天一台节点，可复现。LLaVA 因此传播开来。

## 使用方法

`code/main.py` 实现了：

1. 两层 MLP 投影器（微型示例维度 16 → 32 → 32），纯 Python 实现。  
2. 提示构建管线：系统 prompt + `<image>` 替换为 N 个投影 token + 用户轮次 + 助手生成占位符。  
3. 可视化显示 576-token 视觉块占用 LLM 上下文（2k / 32k / 128k）百分比。

## 交付物

本课产出文件 `outputs/skill-llava-vibes-eval.md`。给定 LLaVA 家族的检查点，运行 10 条 prompt 的 Vibes 评估套件（3 条标题，3 条视觉问答，2 条推理，2 条拒绝），报告易读的评分卡。非基准测试；烟雾测试以确认投影器与 LLM 连接正常。

## 练习

1. 计算两层 MLP 投影器（1024 → 4096 → 4096）可训练参数数量。加上 GELU 与偏置，它占 LLaVA-13B 的百分比是多少？

2. 构造一个 LLaVA prompt，用于“拒绝”情况——图像包含私人信息。写出预期的助手回复。为何 LLaVA 应该在零样本条件下拒绝？需要什么训练数据来加强拒绝？

3. 阅读 LLaVA-NeXT 博客的 AnyRes 部分。计算 1344x672 图像的视觉 token 数量（AnyRes）。与基础的 336x336、576 tokens 比较。

4. LLaVA 阶段 1 投影器用标题的语言模型损失训练。如果跳过阶段 1 直接进入阶段 2（视觉指令微调），会怎样？参考 Prismatic VLMs 消融（arXiv:2402.07865）给出答案。

5. LLaVA-Instruct-150k 用 GPT-4 和 COCO 标题生成指令。对于新领域（医学 X 光、卫星图像），描述四步数据流水线以生成领域指令。每步可能会出什么问题？

## 关键词

| 术语                | 通常说法           | 实际含义                                               |
|---------------------|--------------------|--------------------------------------------------------|
| Projector（投影器） | “MLP 桥梁”         | 两层带 GELU 的 MLP，将 ViT 维度映射到 LLM 维度         |
| Image token（图像 token） | “<image> 占位符” | 推理前被替换为 N 个投影视觉 token 的提示标记           |
| Visual instruction tuning（视觉指令微调） | “LLaVA 阶段 2” | 基于 GPT-4 生成的（图像，指令，响应）三元组训练        |
| Stage 1 alignment（阶段 1 对齐） | “投影器预训练” | 冻结 ViT 和 LLM，投影器用标题语言模型损失训练          |
| AnyRes               | “多裁剪平铺”       | 将高分辨率图像拆分为平铺网格，拼接每个裁剪的视觉 token   |
| LLaVA-Instruct       | “GPT-4 生成”       | 从 COCO 标题和 GPT-4 合成的 158k 指令-响应对            |
| Vision encoder freeze（视觉编码器冻结） | “骨干锁定”      | CLIP 权重在阶段 1 不更新，阶段 2 有时也不更新           |
| ShareGPT4V           | “更好标题”         | 由 GPT-4V 生成 100 万条密集标题，用以更高质量对齐         |
| VQA（视觉问答）       | “视觉问答任务”     | 针对图像回答自由形式问题的任务                            |
| Prismatic VLMs       | “设计空间论文”     | Karamcheti 2024 消融系统地测试投影器和数据选择           |
