# Any-Resolution Vision: Patch-n'-Pack 和 NaFlex

> 真实图像不是 224x224 的正方形。收据是 9:16，图表是 16:9，医学扫描可能是 4096x4096，手机截图是 9:19.5。2024 年之前的视觉语言模型（VLM）解决方案 —— 将所有图像缩放到固定正方形 —— 丢失了支持 OCR、文档理解以及高分辨率场景解析所需的重要信号。NaViT（谷歌，2023）展示了可以通过块对角掩码将可变分辨率的补丁（patches）打包到一个 transformer 批次中。Qwen2-VL 的 M-RoPE（2024）完全摈弃了绝对位置表。LLaVA-NeXT 的 AnyRes 将高分辨率图像切分为基础图+子图。SigLIP 2 的 NaFlex 变体（2025）现在是开放 VLM 的默认编码器，能够使用单个检查点服务所有宽高比。本文课程从头实现 patch-n'-pack。

**类型：** 构建  
**语言：** Python（标准库，补丁打包器 + 块对角掩码）  
**先决条件：** 阶段 12 · 01（ViT 补丁），阶段 12 · 05（LLaVA）  
**时长：** ~120 分钟

## 学习目标

- 将一批可变分辨率图像的补丁打包成一个序列，并构建块对角注意力掩码。  
- 针对任务选择 AnyRes 平铺（LLaVA-NeXT）、NaFlex（SigLIP 2）或 M-RoPE（Qwen2-VL）。  
- 在不缩放的情况下，计算 OCR、图表及摄影的令牌预算。  
- 说明固定大小缩放的三种失败模式：文本变形裁切、内容裁剪和多余填充浪费令牌。

## 问题描述

Transformers 期待输入为一个序列。一个批次是多个长度相同序列的堆叠。如果图像是 224x224，那么每张图获得 196 个补丁令牌，无需填充，任务完成。训练时用 224，推理时用 224，再也不用考虑分辨率。

现实情况并非如此。文档是竖向（8.5x11 英寸，约 2:3），图表截图是横向（16:9），收据细长（1:3），医学成像分辨率通常是 2048x2048 及以上，手机截图 1170x2532（0.46:1）。

2024 年前的三种方案及其失败原因：

1. 缩放至固定正方形（224x224 或 336x336）。缩放导致文字和面部变形，下采样破坏图表标签和 OCR 内容。LLaVA-1.5 之前的标准做法。  
2. 裁剪到固定宽高比。丢弃图像大部分内容，且裁剪位置本身是一个复杂的视觉问题。  
3. 填充至最长边。避免变形，但对于竖图浪费超过 50% 的令牌，全是填充。所有填充令牌带来平方级别的注意力开销。

2024-2025 年的答案是：让 transformer 直接处理图像原始分辨率的补丁，设计如何将异构批次打包成一个序列，避免浪费计算。

## 概念解析

### NaViT 和 patch-n'-pack

NaViT（Dehghani 等，2023）展示了该方法的可扩展性。其核心思想：

1. 对批次中每张图像，按选定补丁大小（例如 14）计算其原始的补丁网格。  
2. 将图像的补丁展平成各自长度可变的序列。  
3. 将全批次的图像补丁按序列连接成一个长序列。  
4. 构建块对角注意力掩码，使图像 A 的补丁只能相互注意。  
5. 保留每个补丁的位置编码（2D RoPE 或分数位置嵌入）。

例如，三张图像分别为 336x336（576 令牌）、224x224（256 令牌）、448x336（768 令牌），则合成序列长度 1600，掩码尺寸 1600x1600，块对角矩阵，无填充，无浪费计算。Transformer 可处理任意宽高比。

NaViT 还引入了训练期间的分数补丁丢弃 —— 随机丢弃 50% 补丁以正则化并加速训练。SigLIP 2 延续了这一做法。

### AnyRes（LLaVA-NeXT）

LLaVA-NeXT 的 AnyRes 是实用替代方案。给定高分辨率图像和固定编码器（CLIP 或固定大小 336 的 SigLIP），图像被切分：

1. 从预定义的网格中选取一个适合图像宽高比的布局——(1x1)、(1x2)、(2x1)、(1x3)、(3x1)、(2x2) 等。  
2. 将整图切分成该网格，每个瓦片变成一个 336x336 的裁剪。  
3. 还生成一个缩略图：将整图缩放到 336x336 作为全局上下文令牌。  
4. 经冻结的 336 编码器编码所有瓦片。连接瓦片令牌和缩略图令牌。

例如 672x672 图像用 2x2 网格加缩略图，即 4 * 576 + 576 = 2880 个视觉令牌。代价大但效果好——LLM 既能看到局部细节，也具备全局上下文。

当编码器冻结且只支持一种分辨率时，AnyRes 是首选方案。高分辨率图像时令牌暴涨（如 1344x1344 图用 4x4 网格是 9216+576 ≈ 9800 令牌，接近 8k LLM 上下文最大值）。

### M-RoPE（Qwen2-VL）

Qwen2-VL 引入了多模态旋转位置编码（Multimodal Rotary Position Embedding）。不同于 NaViT 的分数位置或 AnyRes 的瓦片+缩略图，每个补丁带有三维位置（时间、行、高度、宽度）。Query/Key 的旋转对应可处理任意高 H、宽 W 和时间长度。

M-RoPE 原生支持动态分辨率，无需重训。推理时输入任意 HxW 图像，补丁嵌入器生成 H/14 x W/14 个令牌，每个令牌附带 (t=0, r=行, c=列) 坐标，RoPE 旋转注意力频率，则完成。Qwen2.5-VL 和 Qwen3-VL 继续采用该方法。InternVL3 的 V2PE 也是同一思路，按模态编码变量位置。

不同于 AnyRes，M-RoPE 令牌数量为 O(H×W/P²)，没有瓦片带来的乘法开销。不同于 NaViT，M-RoPE 仍期望单图前向。跨分辨率批处理仍需在其上做 patch-n'-pack。

### NaFlex（SigLIP 2）

NaFlex 是 SigLIP 2 检查点的 native-flex 模式。单一模型在推理时支持多种序列长度（256、729、1024 令牌）。训练时内部使用 NaViT 风格的 patch-n'-pack 和每补丁绝对分数位置编码。优势在于：单个检查点，可根据任务自由选择推理时令牌预算。

语义任务（分类、检索）用 256 令牌。OCR 或图表理解用 1024 令牌，无需重训练。

### 打包掩码

块对角掩码是多数实现易犯错的地方。给定总序列长度 `N_total`，覆盖批次中图像 `i=0..B-1`，每个长度为 `n_i`，掩码矩阵 `M` 形状 `(N_total, N_total)`，当两个索引均属于同一图像区段时值为 1，否则为 0。通过累计长度列表构建：

```text
offsets = [0, n_0, n_0+n_1, ..., N_total]
M[i, j] = 1 当且仅当存在 b 使 offsets[b] <= i < offsets[b+1] 且 offsets[b] <= j < offsets[b+1]
```

PyTorch 一行代码用 `torch.block_diag` 或显式 gather 实现。FlashAttention 的可变长度路径 (`cu_seqlens`) 省去了掩码，直接用累积长度张量在序列内做注意力，速度提升约 10 倍，适合常规批次。

### 令牌预算

按任务选择策略：

- OCR / 文档：1024-4096 令牌。SigLIP 2 NaFlex 用 1024，或 AnyRes 3x3 + 缩略图。  
- 图表及界面：729-1024 令牌，保持 384-448 原始分辨率。Qwen2.5-VL 动态分辨率，设定最大像素数。  
- 自然照片：256-576 令牌足够。下游 LLM 已获取足够信息。选用内容密集区域分配令牌。  
- 视频：每帧空间池化后 64-128 令牌，2-8 fps。课时 12.17 涵盖。

2026 年生产规则：为每个任务选定最大像素限制，按原始宽高比编码至该限制，打包批次，取消填充。Qwen2.5-VL 提供了 `min_pixels` 和 `max_pixels` 参数，方便调节上述限制。

## 使用方法

`code/main.py` 实现了包含整数像素坐标的异构批次优化 patch-n'-pack。功能：

- 接收一组 (H, W) 图像尺寸。  
- 按补丁大小 14，计算各图像补丁序列长度。  
- 打包成总长度为 `sum(n_i)` 的序列。  
- 建立块对角注意力掩码（为清晰使用密集形式）。  
- 对比打包方式与固定平方缩放和 AnyRes 平铺的令牌消耗。  
- 打印混合批次（收据、图表、屏幕截图、照片）的令牌预算表。

运行代码。输出数字正是 2026 年所有开放 VLM 标配 patch-n'-pack 的原因。

## 练习

1. 收据尺寸 600x1500（1:2.5），补丁大小 14 时，在原始分辨率有多少令牌？裁剪到固定大小 336 后有多少？哪个方案在实际 OCR 准确率上损失更大？  

2. 为一批四张图像（长度分别为 256、576、729、1024）构建块对角掩码。验证注意力矩阵大小为 2585x2585，且非零元素数量为 `256^2 + 576^2 + 729^2 + 1024^2`。  

3. 对 1792x896 图像（补丁 14）比较：(a) 固定 336 大小缩放编码；(b) AnyRes 2x1 网格加缩略图；(c) M-RoPE 原始分辨率。哪个方案令牌数最少？哪个方案细节保留最多？  

4. 实现分数补丁丢弃：对打包序列随机丢弃 50% 令牌，更新块对角掩码。测量掩码稀疏度变化。  

5. 阅读 Qwen2-VL 论文第 3.2 节（arXiv:2409.12191）。用两句话描述 `min_pixels` 和 `max_pixels` 控制内容及二者为何都重要。

## 关键词汇

| 术语 | 常见称呼 | 实际含义 |
|------|----------|----------|
| Patch-n'-pack | “NaViT 风格打包” | 将不同图像的可变长度补丁序列连接成一个批次维度 |
| Block-diagonal mask | “打包掩码” | 只允许同一图像内部补丁相互注意的注意力掩码 |
| AnyRes | “LLaVA-NeXT 平铺” | 将高分辨率图分割成固定大小瓦片网格加全局缩略图；用固定编码器编码每个瓦片 |
| NaFlex | “SigLIP 2 native-flex” | 单个 SigLIP 2 检查点支持 256/729/1024 令牌预算推理，无需重训练 |
| M-RoPE | “多模态旋转位置编码” | 适用于任意 H、W、T 的三维旋转位置编码（时间、行、列），无需位置表 |
| cu_seqlens | “FlashAttention 打包” | FlashAttention 可变长度路径用的累计长度张量，替代密集块对角掩码 |
| min_pixels / max_pixels | “分辨率边界” | Qwen2.5-VL 请求参数，用于控制非常小/大输入的令牌上限 |
| Visual token budget | “每图令牌数量” | 估算每个图产生的补丁令牌数，决定 LLM 的提示长度及注意力代价 |
