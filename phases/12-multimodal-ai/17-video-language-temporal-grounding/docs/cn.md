# 视频-语言模型：时间令牌与定位

> 视频不是照片的堆叠。一个5秒的剪辑具有因果顺序、动作动词和事件时序，这是图像模型无法表示的。Video-LLaMA（Zhang 等人，2023年6月）发布了首个带有视听定位的开放视频-大语言模型（video-LLM）。VideoChat 和 Video-LLaVA 扩展了这种模式。到2025年，Qwen2.5-VL的TMRoPE缩小了与前沿专有模型的差距。每个系统对时间令牌的处理方式不同 —— Q-former按剪辑，concat-pool按帧，TMRoPE按令牌。本课将阅读这些模式，构建统一与动态帧采样器，并在时间定位任务上进行评估。

**类型：** 构建  
**语言：** Python（标准库，帧采样器+时间定位评估器）  
**先决条件：** 阶段12 · 08（LLaVA-OneVision）  
**时长：** ~180分钟

## 学习目标

- 解释为什么时间位置编码会独立于视觉编码器影响视频VLM性能。  
- 比较均匀采样、动态FPS和事件驱动的帧采样在令牌速率与定位准确度上的表现。  
- 描述Q-former按剪辑（Video-LLaMA） vs 按帧池化（Video-LLaVA） vs M-RoPE按令牌（Qwen2.5-VL）设计。  
- 命名四个视频基准：VideoMME、TempCompass、EgoSchema、Video-MMMU。

## 问题

一个一分钟的30 FPS视频有1800帧。每帧196个视觉令牌（224分辨率的ViT-B），共352k令牌 —— 超出了任何2024年时代LLM的上下文容量。

存在三种降维策略：

1. 子采样帧（根据内容，1-8 FPS不等）。  
2. 对每帧的补丁令牌进行激进池化（3x3或4x4双线性池化）。  
3. 通过Q-former压缩，输入16帧剪辑，输出64个令牌。

每种折中不同。子采样丢失时间细节。池化丢失空间细节。Q-former两者都稍丢，但节省令牌。

时间位置编码是另一个维度：模型如何知道第5帧在第6帧之前？选项包括简单的一维时间RoPE（Video-LLaMA）、学习的时间嵌入（Video-LLaVA）和TMRoPE（Qwen2.5-VL，完整3D）。

## 概念

### Video-LLaMA：按剪辑Q-former + 音频分支

Video-LLaMA（2023）是首个开源视频-LLM。架构：

- 16帧剪辑，2 FPS采样（共8秒）。  
- 每帧ViT特征 -> Video Q-former对所有16帧进行跨注意力 -> 32个学习查询 -> LLM。  
- 并行音频分支：波形 -> ImageBind音频编码器 -> Audio Q-former -> 32查询 -> LLM。

优势：视听联合推理。劣势：固定剪辑长度，无法任意时间定位。

### VideoChat 和 Video-LLaVA

VideoChat保持了Video-LLaMA思路，但去掉音频且更简化。Video-LLaVA（Lin 等，2023）训练单个视觉编码器同时处理图像和视频帧（“投影前对齐”），实现统一表示。二者都是冻结CLIP编码器+MLP+LLM。

都不支持长视频。均为8-16帧系统。

### Qwen2.5-VL与TMRoPE

Qwen2.5-VL引入了TMRoPE —— 时序-模态旋转位置编码（Temporal-Modality Rotary Position Embedding）。每个补丁令牌携带一个三位（t, h, w）位置，其中t是真实时间戳（非帧索引）。

区别于简单时间嵌入：

- 绝对时间，而非索引。模型可见“在4.2秒时”，而非“第15帧”。  
- 按令牌旋转，而非按剪辑。每个视觉令牌根据其时间戳独立旋转。  
- 兼容动态FPS。2 FPS与4 FPS采样共存，TMRoPE天然支持时间间隔不均匀。

TMRoPE使模型能够回答“猫在第几秒跳跃？” 可输出“4.2秒时”，而Video-LLaMA只能说“剪辑早期”。

### 帧采样策略

均匀采样：在整个时长均匀采样N帧。简单，但损失运动高峰信息。  

动态FPS：根据运动强度自适应采样。使用光流或帧差检测运动密集段落，密集采样。Qwen2.5-VL采用此法。  

事件驱动：运行轻量检测器，在动作发生处多采样。VideoAgent使用此法。  

关键帧+上下文：在镜头切换处采样并采集邻近帧。用于影视内容。

### 按帧池化

1 FPS时每帧576令牌，5分钟剪辑约172,800令牌。Qwen2.5-VL-72B的128k上下文容量可操作，但代价高昂。

3x3双线性池化降至每帧64令牌，5分钟约19,200令牌。适合大多数任务的平衡点。

更激进池化（6x6 -> 每帧16令牌）适用于空间细节不重要的agent工作流。

### 四大视频基准

- VideoMME：全面视频理解，短/中/长。  
- TempCompass：细粒度时间推理，"之前"/"之后"问题。  
- EgoSchema：长周期第一人称视角视频。  
- Video-MMMU：多模态多领域视频问答。

完整视频VLM评估覆盖四者。它们关注不同维度 —— TempCompass重排序，EgoSchema重长时推理，VideoMME跨时长。

### 定位输出格式

时间定位输出格式：

- 自由文本：“猫跳跃大约4秒时。”易读但不精确。  
- 结构化JSON：`{"event": "jump", "start": 4.1, "end": 4.3}`。Qwen2.5-VL训练此格式。  
- 基于令牌：特殊`<time>4.1</time>`令牌与答案交织。Qwen2.5-VL内部格式。

基于令牌最精准，方便下游使用。Qwen2.5-VL的JSON格式可直接解析。

### 2026最佳实践

2026年视频VLM：

- 编码器：SigLIP 2 + M-RoPE或TMRoPE（Qwen2.5-VL）。  
- 帧采样：动态FPS（1-4，依运动强度）并设上限。  
- 按帧池化：3x3双线性。  
- 输出：带时间+事件字段的结构化JSON。  
- 基准：一般用VideoMME+TempCompass；长时用EgoSchema。

## 术语表

| 术语           | 俗称                    | 实际含义                                |
|----------------|-------------------------|----------------------------------------|
| Temporal grounding（时间定位） | “时间定位答案”            | VLM输出事件发生的具体时间戳范围         |
| TMRoPE         | “时间-模态旋转位置编码”  | 绝对时间戳的3D旋转位置编码，Qwen2.5-VL使用  |
| Dynamic FPS（动态FPS）       | “运动感知采样”            | 在高运动段多采样帧，静止段少采样         |
| Frame pooling（帧池化）       | “每帧空间压缩”            | 在输入LLM前用双线性插值减少每帧补丁数     |
| Video Q-former（视频Q-former） | “剪辑压缩器”              | 对N帧做跨注意力瓶颈映射成K个学习查询       |
| VideoMME（视频多模态理解）    | “视频基准”                | 全面短/中/长视频理解基准，2500+样本        |
