# 百万 token 上下文中的长视频理解

> 一小时的 4K 视频以 24 FPS 处理，分块嵌入后产生大约 6000 万个 token。两小时的播客转录文本约 3 万 token。即使经过激进池化压缩的完整版蓝光电影，也有数十万 token。谷歌的 Gemini 1.5（2024 年 3 月）开启了 1000 万 token 上下文时代，实现了对小时级视频中的“针尖找大海”式回忆的高可靠性。LWM（Liu 等，2024 年 2 月）展示了环形注意力的扩展路径。LongVILA 和 Video-XL 进一步扩展了摄取量。VideoAgent 则采用了智能检索替代原始上下文。每种方法都是计算资源、召回性能和工程复杂度的不同权衡。本课将它们并列解读。

**类型：** 构建  
**语言：** Python（标准库，针尖找大海模拟器+智能检索路由）  
**先修：** 第 12 · 17 阶段（视频时间步 token）  
**时长：** ~180 分钟

## 学习目标

- 计算不同 FPS 和池化情况下长视频的视觉 token 总量。  
- 解释三条扩展路径：蛮力上下文（Gemini 1.5）、环形注意力（LWM）、token 压缩（LongVILA / Video-XL）。  
- 比较原始上下文视频 VLM（视觉语言模型）与智能检索视频 VLM（VideoAgent）的准确率和延迟。  
- 设计一个 30 分钟视频的“针尖找大海”测试，并测量特定时间点的召回率。

## 问题背景

Qwen2.5-VL 级别的补丁在 384 原始分辨率下单帧约 729 token。3x3 池化后，每帧 81 token。30 分钟剪辑按 1 FPS 采样即 1800 帧，共 145,800 token。2025 年的开源 VLM 能勉强处理。2 FPS 则为 291,600 token，只有超大上下文模型能应付。

2 小时电影按 1 FPS 则有 58.3 万 token，超出大多数 2026 年开源模型的能力，需要 Gemini 2.5 Pro 或更激进的池化。

业界出现了三条扩展路径。

## 概念解析

### 路径 1：蛮力上下文（Gemini 1.5、Claude Opus）

硬件堆叠解决。将上下文扩展到百万级 token，所有内容一并前向推理。

Gemini 1.5 Pro 启动时 100 万 token，上升到 Gemini 1.5 Ultra 的 1000 万，2026 年的 Gemini 2.5 Pro 可稳定处理数小时视频。论文（arXiv:2403.05530）记录了在约 950 万 token 范围内“针尖找大海”召回率高达 99.7%。

工程实现：定制注意力机制，带内存层次结构（本地 + 全局 + 稀疏）并辅以 MoE 专家路由实现长上下文效率。具体细节未完整公开，非开源。

### 路径 2：环形注意力（LWM、LongVILA）

环形注意力将长序列切分分布在多设备上，每设备保存一部分。通过在环状模式中传递 chunk，实现跨全序列的注意力计算。

LWM（Liu 等，2024）用此训练了 100 万 token 上下文模型。训练计算资源与上下文线性相关，而非二次方——因为注意力的二阶复杂度分摊到环上各节点。

LongVILA（arXiv:2408.10188）将该模式移植到视觉语言模型。1400 帧、每帧 192 token，共 26.8 万 token，上下文在 8 路并行下用环形注意力训练。

### 路径 3：token 压缩（Video-XL、LongVA）

比蛮力上下文更节省计算：在送入 LLM 前先做激进压缩。

Video-XL（arXiv:2409.14485）使用视觉摘要 token：每 N 帧生成一个“摘要” token，并通过注意力关注这 N 帧。推理时 LLM 只看到每片段一个摘要 token，大幅缩减上下文。

LongVA 将 LLM 上下文从 20 万扩展到 200 万，采用“长上下文迁移”技术。先训练长文本模型，再通过共享表征迁移到长视频。

token 压缩以牺牲某些具体时间点的召回率换取规模。模型知道总体发生了什么，但有时错失精确帧。

### 路径 4：智能检索（VideoAgent）

不将整个视频全部输入 LLM，而是把视频当成数据库，由 LLM 发起检索查询。

VideoAgent（arXiv:2403.10517）流程：

1. LLM 读入问题。  
2. LLM 请求检索工具返回相关视频片段（“给我带猫的片段”）。  
3. 检索工具返回对应片段时间戳。  
4. LLM 通过 VLM 读取这些片段。  
5. LLM 生成答案或进一步发起查询。

这是典型的“LLM 作为智能代理”在长视频的应用。推理成本低（只编码相关片段），工程难度高（检索质量瓶颈）。

### “针尖找大海”基准测试

标准长上下文测试：在随机时间点插入唯一视觉或文本标记，后续查询要求模型能回忆起它。

指标：Recall@k，覆盖视频长度和标记位置。

Gemini 2.5 Pro 在长达 90 分钟视频中召回率超过 99%。开源 72B 模型（Qwen2.5-VL-72B、InternVL3-78B）30 分钟召回约 85-90%，60 分钟后表现下降。

VideoAgent 在 2 小时以上视频中可匹配甚至超越原始上下文模型，条件是检索工具准确定位“针尖”。

### 如何选择路径

15 分钟剪辑且要求前沿准确：开源 72B + 原生上下文通常够用，推荐 Qwen2.5-VL-72B。

30 分钟至 1 小时内容：开源首选 LongVILA 或 Video-XL，闭源则选 Gemini 2.5 Pro。质量需求高则倾向闭源方案。

2 小时以上内容：VideoAgent 或相似智能检索方案。可选方案还包括先摘要成较小块，再输入分层摘要。

### 2026 年生产模式

实际生产长视频管道采用混合方案：

1. 全视频动态 FPS 采样 + 激进池化（获得约 10 万 token 的全局表征）。  
2. 交由 72B VLM 生成全局摘要。  
3. 用户提问细节时，基于摘要索引启动智能检索。

结合了蛮力上下文的全局理解和智能检索的局部细节。

## 关键词

| 术语         | 流行说法         | 实际含义                            |
|--------------|------------------|-----------------------------------|
| 蛮力上下文   | “就是更多 token” | 将 LLM 上下文扩展到百万 token，统一一次前向计算 |
| 环形注意力   | “LWM 风格并行”   | 分布式注意力，每个设备持有一片，循环传递           |
| token 压缩   | “摘要 token”     | 通过学习压缩器减少每段的 token 数，传入 LLM         |
| 针尖找大海   | “NIH 测试”       | 在随机点插入唯一标记，测试时检索模型能否回忆       |
| 智能检索     | “LLM 作为查询规划”| LLM 请求检索工具查找相关片段，读取后生成答案       |
| VideoAgent  | “视频检索模式”   | 标准智能检索设计：问题->检索工具->片段->答案       |
