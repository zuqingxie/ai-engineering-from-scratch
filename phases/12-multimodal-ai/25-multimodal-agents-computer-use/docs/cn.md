# 多模态智能体与计算机操作（毕业设计）

> 2026 年的前沿产品是一个多模态智能体，能够读取截图、点击按钮、浏览网页 UI、填写表单，并完成端到端的工作流程。SeeClick 和 CogAgent（2024）验证了 GUI grounding（GUI 定位）原语。Ferret-UI 添加了移动端支持。ChartAgent 引入了图表的视觉工具使用。VisualWebArena 和 AgentVista（2026）是前沿努力追逐的基准——甚至 Gemini 3 Pro 和 Claude Opus 4.7 在 AgentVista 的难题上得分约为 30%。本毕业设计汇集了第 12 阶段的所有线索：感知（高分辨率 VLM（视觉语言模型））、推理（带工具调用的 LLM（大语言模型））、定位（坐标输出）、长远记忆与评估。

**类别：** 毕业设计  
**语言：** Python（标准库、动作 schema（模式）+ 智能体循环骨架）  
**先修条件：** 第 12 阶段·05（LLaVA）、第 12 阶段·09（Qwen-VL JSON）、第 14 阶段（智能体工程）  
**时间：** 约 240 分钟

## 学习目标

- 设计多模态智能体循环：感知 → 推理 → 行动 → 观察 → 重复。  
- 构建 GUI grounding 输出 schema（点击坐标、输入文本、滚动、拖拽），VLM 能以 JSON 格式输出。  
- 比较仅截图智能体、辅助功能树智能体和混合智能体性能。  
- 设立多模态智能体基准评测，在小规模 VisualWebArena 片段上测试。

## 问题描述

一个预订网站的工作流程：“帮我找到 4 月 15 日飞东京的航班，走道座位，价格不超过 800 美元，帮我预订。”

多模态智能体需要：

1. 截取浏览器截图。  
2. 将截图 + URL + 目标解析成计划。  
3. 发出结构化动作：点击（在 x,y）、输入“Tokyo”（在元素 E）、下滚、选择（单选按钮）。  
4. 将动作应用至浏览器。  
5. 观察新的状态（下一张截图）。  
6. 重复，直到任务完成。

每一步都是一次多模态 VLM 调用。VLM 输出必须是可解析的 JSON。错误会跨步累计，所以恢复机制很重要。

## 概念解析

### GUI grounding —— 基本原语

GUI grounding 是：给定截图和自然语言指令，输出点击的（x, y）坐标（或其他动作）。

SeeClick（arXiv:2401.10935）是第一个大规模的公开结果：微调 VLM 用合成及真实 GUI 数据，输出坐标为纯文本标记。有效。

CogAgent（arXiv:2312.08914）加入了 1120×1120 高分辨率编码以适应密集的 UI。性能约为网页导航命中率 84%。

Ferret-UI（arXiv:2404.05719）专注于移动 UI，整合 iOS 辅助功能数据。

输出格式通常是 JSON：

```json
{"action": "click", "x": 384, "y": 220, "element_desc": "搜索按钮"}
```

`element_desc` 有助于恢复：当截图之间坐标出现漂移时，语义提示让系统重新定位。

### 动作 schema（模式）

典型动作 schema 拥有 6-10 种动作类型：

- `click`： (x, y)  
- `type`： (text, x?, y?)  
- `scroll`： (方向, 数量)  
- `drag`： (x0, y0, x1, y1)  
- `select`： (option_index)  
- `hover`： (x, y)  
- `navigate`： (url)  
- `wait`： (ms)  
- `done`： (success, explanation)

智能体每步发出一个动作。浏览器封装执行后返回新状态。

### 仅截图 vs 辅助功能树

两种输入模式：

- 仅截图：完整图像，无结构信息。最通用；适用任何应用。  
- 辅助功能树：结构化 DOM / iOS 辅助功能信息。对定位更可靠；适用树信息可用时。  
- 混合：两者兼用，将辅助树作为原子动作的可靠依据，截图提供语义上下文。

生产环境智能体优先使用混合方式。浏览器自动化（Selenium + 辅助功能）始终拥有树结构；桌面应用有时也支持。

### 长远记忆

20 步工作流产生 20 张截图。VLM 上下文容量迅速填满。三种压缩策略：

- Summary-chain（摘要链）：每 5 步汇总已发生内容，丢弃旧截图。  
- Skip-frame（跳帧）：保留首末及每第 3 张截图。  
- 工具记录日志：执行动作，保留文字日志；不反复查看旧截图。

Claude 的计算机使用 API 采用日志模式。更简单且更可靠。

### 视觉工具使用

ChartAgent（arXiv:2510.04514）引入图表视觉工具使用：裁剪、放大、OCR（光学字符识别）、调用外部检测。智能体可输出“裁剪到区域 (100, 200, 300, 400)，随后调用 OCR”的工具调用。工具返回文本，VLM 继续推理。

此范式能泛化：标记集合提示、区域注释与外部检测工具均符合“输出工具调用，接收结构化响应”的 schema。

### 2026 年基准

- ScreenSpot-Pro。约 1000 张网页截图的 GUI grounding。开源 SOTA Qwen2.5-VL-72B 约 85%，前沿目标约 90%。  
- VisualWebArena。端到端网页任务（购物、论坛、分类信息）。开源 SOTA 约 20%，Gemini 3 Pro 约 27%。  
- AgentVista（arXiv:2602.23166）。最困难的 2026 年基准。12 个领域的真实工作流。前沿模型得分 27%-40%，开源模型 10%-20%。  
- WebArena / WebShop。较旧基准，已被前沿技术饱和。

### 为什么依然困难

智能体性能瓶颈：

1. 细粒度视觉定位。“点击小 X”经常在移动分辨率失效。  
2. 长远规划。十步后，智能体目标漂移。  
3. 错误恢复。点击失败（错误按钮）时，检测与恢复数据很少。  
4. 跨页面上下文。标签页切换或长表单导致状态丢失。

研究方向：记忆架构、显式重规划、多模态验证（截图匹配检查动作成功）。

### 毕业设计构建任务

毕业设计任务：构建一个计算机操作智能体，能够：

1. 读取预订网站模拟页面的 HTML + 截图。  
2. 规划多步序列：搜索 → 选择 → 填表 → 提交。  
3. 发出符合动作 schema 的 JSON 动作。  
4. 在固定 10 任务片段上进行评估。

课程提供易扩展成真实浏览器的骨架代码。

## 使用方法

`code/main.py` 是毕业设计骨架代码：

- 动作 schema（10 种动作）的 JSON 定义。  
- 作为 dict（字典）的模拟浏览器状态。  
- 智能体循环骨架：接收状态，发出动作，应用，并循环。  
- 10 任务小基准（合成页面），测量端到端成功率。  
- 动作失败时的错误恢复钩子。

## 关键词表

| 术语 | 常见说法 | 实际含义 |
|------|----------|----------|
| GUI grounding | “点击坐标” | 模型针对截图和指令输出 (x,y) 位置 |
| Action schema | “工具定义” | 有效动作（点击、输入、滚动、拖拽等）的 JSON 描述 |
| Accessibility tree | “结构化 DOM” | 浏览器/iOS API 提供的机器可读 UI 层级 |
| Hybrid agent | “截图 + 树” | 结合图像和结构信息，比单一方式更可靠 |
| Visual tool use | “缩放/裁剪/检测” | 智能体中途调用外部视觉工具（OCR、检测） |
| Summary-chain | “记忆压缩” | 定期文本摘要替代长截图历史 |
| VisualWebArena | “端到端网页基准” | 2024 年度端到端网页任务基准 |
| AgentVista | “2026 困难基准” | 12 个领域的真实工作流；Gemini 3 Pro 得分约 30% |
