# 行动预算（Action Budgets）、迭代上限（Iteration Caps）与成本管控器（Cost Governors）

> 一个中型电商智能体的月LLM成本在其团队启用“订单跟踪”技能后，从1200美元暴涨至4800美元。这不是定价错乱，而是智能体发现了一个新的循环并持续在里面花费。微软的Agent Governance Toolkit（2026年4月2日）规范了针对这一类问题的防御措施：每次请求的 `max_tokens`，每任务的令牌及美元预算，每日/月度上限，迭代上限，分层模型路由，提示缓存，上下文窗口化，昂贵操作的人工介入检查点（HITL checkpoints），预算超限的终止开关。Anthropic的Claude Code Agent SDK 用不同名字实现了同类原语。金融速度限制——例如“10分钟内超过50美元就切断访问”——比月度上限更快捕捉循环。

**类型：** 学习  
**语言：** Python（stdlib，分层成本管控器模拟器）  
**先决条件：** 阶段15·10（权限模式）、阶段15·12（持久执行）  
**时长：** 约60分钟

## 问题描述

自主智能体每一步都会花费真实的钱。聊天机器人的糟糕输出只是一条糟糕回复；智能体的循环失控则是一张账单。业界公认的术语是“钱包拒付（Denial of Wallet）”——智能体持续推理、持续调用工具、持续计费，没有任何机制能够阻止它，因为设计时没有考虑到。

解决方案不是单一数字，而是不同时间尺度和粒度的限制栈：每请求、每任务、每小时、每日、每月。一个设计良好的限制栈能在几分钟内捕捉失控循环，在数小时内捕捉缓慢泄漏，在一天内捕捉错误发布。这个限制栈还能保证预算，即使智能体操作时间长且自主。

这是一个工程教训：数学本身简单，失败在于团队不够纪律化。下面的限制类型均在微软Agent Governance Toolkit或Anthropic Claude Code Agent SDK文档中有命名。

## 概念解析

### 成本管控器栈

1. **每次请求的 `max_tokens`。** 简单，防止单次调用产出无界完成结果。  
2. **每任务令牌预算。** 整个运行中不超出N个令牌，达到上限强制停止。  
3. **每任务美元预算。** 同令牌，但以货币计。Claude Code中为 `max_budget_usd`。  
4. **每工具调用上限。** 不超过N次 `WebFetch` 调用，N次 `shell_exec` 调用等。  
5. **迭代上限（`max_turns`）。** 总智能体循环次数，防止无限推理。  
6. **每分钟/每小时/每日/每月上限。** 滚动窗口，针对不同时间尺度捕捉泄漏。  
7. **金融速度限制。** 如“10分钟内花费超过50美元则切断访问”，比月度上限更快捕获循环烧钱。  
8. **分层模型路由。** 默认用小模型；只有分类器判定任务需要时才升级到大模型。  
9. **提示缓存。** 系统提示及稳定上下文存储在提供者缓存中，重发的令牌成本几乎为零。  
10. **上下文窗口化。** 压缩/摘要以保持活跃上下文在阈值以下，直接降低令牌成本。  
11. **耗费高昂操作的人工介入检查点（HITL checkpoints）。** 在明确昂贵操作（长时间工具调用、大量下载、成本巨大的模型升级）前要求人工确认。  
12. **预算超限终止开关。** 任何限制触发即终止会话，限制记录在案，需另外路径重新启用。  

### 为什么要用限制栈，而不是单一限制

单一的月度上限只能在钱包耗尽后才能捕获失控智能体。单一请求级别的限制则根本无法在会话级捕捉问题。不同的失败模式需要不同时间尺度的限制：

- **失控循环**（智能体卡在5秒重试里）由速度限制捕获。  
- **缓慢泄漏**（智能体完成每任务工作约2倍预期）由每日上限捕获。  
- **错误发布**（新版本使用5倍令牌）由周/月上限捕获。  
- **合法激增**（真实需求非BUG）由时/日上限捕获并产生清晰日志。

### Claude Code 的预算界面

Claude Code Agent SDK公开文档中支持：

- `max_turns` — 迭代上限。  
- `max_budget_usd` — 美元上限；超限时终止会话。  
- `allowed_tools` / `disallowed_tools` — 允许和禁止工具清单。  
- 工具调用前的钩子点用于自定义成本核算。

结合权限模式阶梯（第10课）。一个无 `max_budget_usd` 的 `autoMode` 会话是不受管控的自主。Anthropic 明确认为自动模式需要预算控制；分类器与成本无关。

### 欧盟AI法案、OWASP Agentic Top 10

微软的Agent Governance Toolkit涵盖了OWASP Agentic Top 10 和欧盟AI法案第14条（人工监督）要求。在欧盟境内生产环境中，日志记录和限制执行是强制性的。

### 观察到的1200美元→4800美元案例

微软文档中的真实案例如下：一个电商智能体在新增一个工具后月成本翻了三倍。该工具允许智能体在每次会话轮询订单状态。没有循环检测，没有每工具调用上限，没有周度增长告警。修复方案是为每工具加入调用上限和日增长告警。这是典型模板：每个新工具都可能引入潜在循环；每个新工具都需要它自己的调用上限和告警。

## 练习题

1. 运行 `code/main.py`。确认在轮询循环轨迹中速度限制先于迭代上限触发。然后禁用速度限制，测量迭代上限触发前智能体消耗了多少。  

2. 设计为浏览器智能体（第11课）设置的每工具调用上限。哪个工具需要最紧密的限制？哪个工具可无限制运行而无风险？

3. 阅读微软Agent Governance Toolkit文档。列出文档定义的全部上限类型。将每种对应到一个失败模式（失控循环、缓慢泄漏、错误发布、激增）。

4. 为现实任务（例如“排查仓库中50个问题”）估价一次通宵无人值守运行。将 `max_budget_usd` 设置为你的估价的2倍。说明为什么乘以2。

5. Claude Code的 `max_budget_usd` 针对会话总成本触发。设计一个你会在外部强制执行的补充速度限制。触发切断的条件是什么，重新启用如何操作？

## 关键词

| 术语 | 俗称 | 实际含义 |
|---|---|---|
| Denial of Wallet | “失控账单” | 智能体循环产生消费，无限制停止 |
| max_tokens | “每请求上限” | 单次完成输出令牌数上限 |
| max_turns | “迭代上限” | 单次会话智能体循环次数上限 |
| max_budget_usd | “美元终止开关” | 会话成本上限，超限终止 |
| Velocity limit | “速率上限” | 短时间窗口内消费限制（如50美元/10分钟） |
| Tiered routing | “先小模型” | 默认使用成本低模型，必要时才升级 |
| Prompt caching | “提示缓存” | 提供者侧缓存，重发令牌成本接近零 |
| HITL checkpoint | “人工审批关卡” | 昂贵操作前需人工确认 |
