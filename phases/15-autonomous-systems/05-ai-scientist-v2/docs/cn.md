# AI Scientist v2 — 工作坊级别的自治研究

> Sakana 的 AI Scientist v2（Yamada 等人，arXiv:2504.08066）运行完整的研究循环：假设、代码、实验、图表、撰写、提交。它是首个由生成论文通过 ICLR 2025 工作坊同行评审的系统。独立评估（Beel 等人）发现 42% 的实验因编码错误失败，文献回顾经常错误标记已知概念为新颖。Sakana 自身文档警告该代码库执行 LLM 编写的代码，建议使用 Docker 隔离。这个局面两面都是重点。

**类型：** 学习  
**语言：** Python（标准库，研究循环状态机玩具）  
**先决条件：** 第 15 阶段·03（AlphaEvolve）、第 15 阶段·04（DGM）  
**时间：** 约 60 分钟

## 问题

研究是一个开放式任务。不同于 AlphaEvolve 的算法搜索或 DGM 设有限标杆的自我改进，研究结果没有机器可检验的正确性标准。一篇论文由审稿人评判，而非单元测试。这使得循环闭合更难——若闭合则更有价值，因为研究是积累进步的所在。

AI Scientist v1（Sakana，2024）通过从人类编写的模板开始闭合循环。LLM 在固定框架内填写实验。AI Scientist v2（Yamada 等，2025）通过使用带视觉-语言模型批评循环的智能树搜索去除模板需求。系统生成想法，实现实验，制作图表，写论文，并根据审稿意见迭代。

同行评审结果：一篇 v2 生成的论文被 ICLR 2025 工作坊接受（并进行了披露）。独立评估结果：系统远不可靠。这两者都属实。

## 概念

### 架构

1. **想法生成。** LLM 根据主题和已有文献提出研究想法。v1 使用模板；v2 使用围绕假设空间的智能搜索。
2. **新颖性检查。** 文献检索步骤检查想法是否已发表。Beel 等评估发现这一环节常将已知方法误标为新颖。
3. **实验计划。** 智能体起草实验方案并编写代码。
4. **执行。** 代码在沙箱中运行。失败反馈回重试循环。Beel 等测量中，42% 的实验在此阶段因编码错误失败。
5. **图表生成。** 视觉-语言模型读取生成的图表并对其进行重写以提高清晰度。是 v2 的关键技术创新。
6. **撰写。** LLM 起草论文，并与内部审稿人反复迭代。
7. **可选：提交。** 论文提交至会场。

### 工作坊接受结果意味着什么

一篇 v2 生成的论文通过了 ICLR 2025 工作坊的同行评审。作者向程序委员会披露了论文的来源。该接受是一条数据点，并非“系统做出研究”的许可。

重要背景：工作坊论文门槛低于主会场论文。同行评审有噪声，当天部分提交被接受。一例成功是概念验证，不是可靠性声明。2026 年 Nature 论文记录了完整循环，且由人类研究者共同署名；不是“系统写的 Nature 论文”。

### 独立评估发现

Beel 等（arXiv:2502.14297）做了外部评估。摘要：

- **实验失败。** 42% 的实验因编码错误（错误导入、形状不匹配、未定义变量）失败。重试循环捕获了一部分，但未全部捕获。
- **新颖性误标。** 文献检索步骤经常将已知概念误标为新颖，这相当于研究领域的“幻觉”。
- **表现质感差距。** 视觉-语言图表批评产生出版级视觉效果，掩盖了实验弱点。

最后一点对于本阶段最重要。一个生成令人信服输出但进行不够令人信服研究的系统，比明显失败的系统更危险。评估必须触及核心主张，而非停留在图表层面。

### 沙箱逃逸的担忧

Sakana 自身仓库 README 警告：

> 由于本软件运行 LLM 生成代码，无法保证安全。存在危险包、不受控网络访问和意外进程生成风险。使用时自行承担风险，建议使用 Docker 隔离。

这是未经验证领域自治的实际形态。LLM 写代码；代码运行；代码能做进程允许做的任何操作。若无严格限制文件系统、网络与进程行为的沙箱，任何自主研究智能体都能窃取数据、耗尽计算资源或自我重写。

AlphaEvolve 的沙箱较简单，因为其评估者受控。AI Scientist v2 循环运行开放式代码，目标开放。故需更强隔离（至少 Docker；首选 seccomp / gVisor）和每次提交离开系统前人工审核。

### v2 在前沿栈中的位置

| 系统 | 目标 | 输出类型 | 评估器 | 已知失败 |
|---|---|---|---|---|
| AlphaEvolve | 算法 | 代码 | 单元测试+基准测试 | 受评估者严谨度限制 |
| DGM | 智能体脚手架 | 代码 | SWE-bench | 奖励操控 |
| AI Scientist v2 | 研究论文 | 文字 + 代码 + 图表 | 同行评审（弱） | 实验失败，误标，修饰掩盖弱点 |

v2 具有三者中最弱的自动评估器，最广的输出面，和最短的公开产物路径。操作控制（沙箱、审核、披露）主导安全工作。

## 使用方法

`code/main.py` 模拟 v2 循环为状态机：想法 → 新颖性检查 → 实验 → 图表 → 撰写 → 审核 → 接受或迭代。每一状态有配置的失败概率，基于 Beel 等发现。运行模拟器 N 次，统计：

- 多少想法达到提交阶段。
- 多少提交的论文图表掩盖了关键实验缺陷。
- 重试预算如何权衡质量与产出。

## 交付

`outputs/skill-ai-scientist-sandbox-review.md` 是一个两层审核清单，用于任何研究循环智能体产物离开沙箱前的审核。

## 练习

1. 使用默认参数运行 `code/main.py`。循环运行中“干净”论文比例是多少？有实验失败缺陷但被图表修饰掩盖的论文比例是多少？

2. 默认已用 Beel 等的 42% / 25%。用 `--experiment-failure 0.20 --novelty-mislabel 0.10` 再跑一遍，再用 `--experiment-failure 0.60 --novelty-mislabel 0.40` 跑一遍。两次运行中修饰掩盖缺陷的比例如何变化？

3. 阅读 Sakana AI Scientist v2 仓库 README 中的沙箱要求。提出针对多天自治运行，除 Docker 外，你会施加的两条额外限制。

4. 阅读 Beel 等第 4 节关于表现质感差距的内容。设计一个评估器，用于捕捉外表完善但实验有缺陷的论文。

5. 提出一套比“博士论文都要读”更可扩展的研究智能体产物人工审核协议。指出瓶颈并设计解决方案。

## 关键词

| 术语 | 常用说法 | 实际含义 |
|---|---|---|
| AI Scientist v1 | “Sakana 的模板化研究智能体” | 在固定框架内填写实验 |
| AI Scientist v2 | “无模板研究智能体” | 带视觉-语言模型图表批评的智能树搜索 |
| 智能树搜索（Agentic tree search） | “分支研究智能体” | 并行扩展多个实验计划；由内部批评者修剪 |
| 视觉-语言批评（Vision-language critique） | “图表的 VLM 修饰” | 多模态模型读取图表并重新为清晰度重写 |
| 文献检索（Literature retrieval） | “新颖性检查” | 搜索先前工作确认想法新颖性——已证实存在误标 |
| 修饰掩盖（Polish masking） | “漂亮但有缺陷的论文” | 表现质量超过实验质量，隐藏实验缺陷 |
| 沙箱逃逸（Sandbox escape） | “LLM 代码逃逸” | 智能体执行的代码做了设计者未预期的事情 |
