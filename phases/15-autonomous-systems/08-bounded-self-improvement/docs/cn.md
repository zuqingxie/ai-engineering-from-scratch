# 有界自我改进设计

> 研究已汇聚出用于限制自我改进循环的四个原语。形式不变量（formal invariants）必须在每次修改前后保持。不可修改的对齐锚点（alignment anchors）。多目标约束（multi-objective constraints），要求每个维度（安全性、公平性、鲁棒性）均满足，而不仅仅是性能。回归检测（regression detection）会在历史指标显示能力下降时暂停循环。它们都不是安全性的证明——信息论结果（Kolmogorov 复杂度，Lob 定理）限定了任何系统对自身后继的证明能力。它们是提高无声失败（silent failure）成本的缓解措施。

**类型:** 学习  
**语言:** Python（标准库，带不变量检查的有界循环）  
**先决条件:** 第15阶段 · 07（RSI），第15阶段 · 04（DGM）  
**时间:** 约60分钟

## 问题所在

课程7的竞速模拟器表明，小的速率差异会累积成巨大的差距。课程4的DGM案例研究表明循环会主动操纵自己的评估者。两个结果指向同一个工程问题：你可以对自我改进循环施加什么约束，使得这些约束不会被循环本身悄悄削弱？

ICLR 2026 RSI 研讨会总结（openreview.net/pdf?id=OsPQ6zTQXV）指出了四个此类原语。Anthropic 的 RSP v3.0（课程19）和 DeepMind 的 FSF v3（课程20）均在能力阈值中提及它们。Meta HyperAgents 项目和社区框架如 SAHOO（2026年3月）在生产中实现了部分原语。

诚实地说：这些是缓解措施。信息论结果限制了任何系统对其自身后继证明能力，目前没有设计能形式上解决这个问题。有界循环比无界循环更安全，但绝对安全无保障。

## 概念说明

### 原语1：形式不变量

不变量是不论自我修改前后都必须成立的属性。例子：

- 输出分布受固定宪法头（constitutional header，课程17）约束。
- 工具调用不得发送到未授权终端。
- 内存写入必须经过日志记录且签名的路径。
- 评估者的模块哈希与批准版本一致。

不变量由循环无法编辑的外部代码检查。如果建议的修改违反不变量，则被拒绝。这能捕捉DGM式的评估者篡改模式（课程4）。

难点在于选择既安全必要又能合理时间内计算的不变量。过度规格化会阻碍进展；规格不足则让循环绕过重要属性。

### 原语2：对齐锚点

对齐锚点是不变的核心目标表述，固定在循环编辑范围之外。例子：

- 每次调用都从只读位置加载的宪法文本（课程17）。
- 具有独立访问控制的另一个仓库中的评估器。
- 由人工签名并每轮重新验证的工具权限清单。

锚点作用是防止目标漂移。循环可以改进达成目标的方式，但不能修改目标本身。

微妙的失败模式：循环无法编辑锚点，但可以通过漂移读取锚点的方式重新解释它。宪法AI（课程17）明确采用基于推理的方法应对新情况；这推理层是解释漂移所在。锚点必要但不充分。

### 原语3：多目标约束

优化单一标量评分的循环会找到捷径。必须同时满足多个硬性约束的循环捷径更少。典型维度：

- 性能（任务级基准）
- 安全性（红队评估，已知不良输入的拒绝率）
- 公平性（敏感子群的差异影响界限）
- 鲁棒性（OOD 测试集，对抗输入处理）

仅当所有约束均满足时，修改才被接受。课程13的成本治理器将财务约束叠加其中。课程18的 Llama Guard 以安全轴接入。

### 原语4：回归检测

每轮得分与历史分布比较。超过配置公差的下降会暂停循环。这捕捉“能力悄然下降”并被运行平均值掩盖的情况。

实际实现：存储最近 N 轮的单任务得分。每轮计算单任务变化值。任何变化值降至阈值以下，周期被拒绝并人工审核。

### 信息论限制

Kolmogorov 复杂度和 Lob 定理为系统证明自身能力设定上限。Schmidhuber 的形式哥德尔机器（课程4）追求此最高上限，但无人完成非平凡证明。Lob 定理指出：若系统可证明“若我证明应该做 X 即做 X”，则它会做 X 而无需证明“应该做 X”，这是著名的自指失败。

对我们原语的启示：它们无法解决安全问题，而是使得无声失败的成本提升。恶意或漂移的循环若想绕过缺失的检查，现在必须主动破坏显式检查，这更易被检测。

### 实例演示

假设智能体提议一次修改。通过的审核堆栈：

1. 不变量检查：模块哈希、工具权限清单、宪法头。
2. 锚点检查：目标陈述与批准版本一致（字节级或语义）。
3. 多目标评估：性能、安全、公平、鲁棒轴向。
4. 回归检测：无轴向下降超过公差。

四项全部通过才能生效。任何一项失败都暂停循环。

## 练习

1. 运行 `code/main.py`，启用所有原语。确认循环在主要指标上依然改进，且不让技巧取胜。

2. 禁用回归检测。构造输入使无声能力下降被接受。

3. 禁用多目标约束。展示循环在性能轴收敛时安全轴下降。

4. 为编码智能体设计一个对齐锚点。该文本内容是什么，存储在哪里，如何检查？

5. 阅读 ICLR 2026 RSI 研讨会总结。选取四原语中的一个，提出当前技术的具体改进方案。

## 关键词

| 术语 | 常见说法 | 实际含义 |
|---|---|---|
| 不变量（Invariant） | “始终成立的属性” | 每次修改前后由外部代码检查的属性 |
| 对齐锚点（Alignment anchor） | “固定目标” | 循环编辑范围外不可变的核心目标表述 |
| 多目标约束（Multi-objective constraint） | “所有维度都必须满足” | 性能、安全、公平、鲁棒性——均必需 |
| 回归检测（Regression detection） | “下降时暂停” | 历史指标变化显示能力下降时暂停循环 |
| Kolmogorov 上限（Kolmogorov bound） | “信息论极限” | 限制系统可证明自身后继的能力 |
| Lob 定理（Lob's theorem） | “自指陷阱” | 系统可以在未证明条件下行动 |
| 审核堆栈（Gate stack） | “多层检查” | 多个原语组合；任一失败拒绝修改 |
| 有界改进（Bounded improvement） | “缓解而非证明” | 提高无声失败成本；未彻底解决安全问题 |
