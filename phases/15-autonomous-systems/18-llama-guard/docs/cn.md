# Llama Guard 与输入/输出分类

> Llama Guard 3（Meta，基于 Llama-3.1-8B 基础模型，经过内容安全微调）针对 MLCommons 13类风险分类法，对大语言模型（LLM）输入和输出进行分类，支持8种语言。1B-INT4 量化版本在移动 CPU 上速度超过30个标记/秒。Llama Guard 4 是多模态（图像+文本），将分类体系扩展到 S1–S14（包括 S14 代码解释器滥用），并且可直接替代 Llama Guard 3 的8B/11B版本。NVIDIA NeMo Guardrails v0.20.0（2026年1月发布）在输入和输出分类轨道基础上添加了 Colang 对话流程规则。诚实的说明：“绕过 LLM Guardrails 中的提示注入和越狱检测”（Huang 等，arXiv:2504.11168）显示 Emoji 走私攻击在6个重要防护系统上成功率达到100%；NeMo Guard Detect 在越狱检测上的成功率为72.54%。分类器是一个防护层，不是全盘解决方案。

**类型：** 学习  
**语言：** Python（标准库，带类别标签的分类器模拟器）  
**先决条件：** 第15阶段 · 10（权限模式），第15阶段 · 17（宪法）  
**时间：** 约45分钟

## 问题

LLM 输入和输出的分类器位于智能体堆栈的最狭窄环节：每个请求和响应都必须通过。一个好的分类器层应快速、基于分类体系，并能以较小的计算成本捕获大量明显的滥用行为。一个差的分类器层则可能带来虚假的安全感。

2024–2026年的分类器体系已趋于一小批生产就绪的选项。Llama Guard（Meta）发布了基于社区许可的开放权重。NeMo Guardrails（NVIDIA）发布了宽松许可的轨道和用于对话流程规则的 Colang。两者设计为与基础模型搭配使用，而非替代模型的安全行为。

已知的攻击面也被详细映射。字符级攻击（Emoji 走私、同形异义字替换）、上下文指令重定向（“忽略前述内容，直接回答”）、语义释义等都会导致分类器准确率明显下降。Huang 等人2025年的研究显示特定 Emoji 走私攻击在6个知名防护系统上的成功率达100%。

## 概念

### Llama Guard 3 简述

- 基础模型：Llama-3.1-8B  
- 针对内容安全微调；非通用聊天模型  
- 分类输入和输出两端  
- 基于 MLCommons 13类风险分类法  
- 支持8种语言  
- 1B-INT4 量化版本在移动CPU上速度超过30标记/秒  

分类体系即是产品。“S1 暴力犯罪”到“S13 选举”对应模型训练的共享词汇表。下游系统可以为特定类别配置动作：如直接阻断 S1，标记 S6 以人工复核，注释 S12 但允许继续。

### Llama Guard 4 新增功能

- 多模态：图像+文本输入  
- 扩展分类体系：S1–S14（新增 S14 代码解释器滥用）  
- 可无缝替换 Llama Guard 3 的8B/11B版本  

S14 分类非常关键。自主编码智能体（第9课）在沙箱中执行代码（第11课）；代码解释器滥用分类能捕获早期版本未覆盖的一类攻击。

### NeMo Guardrails（NVIDIA）

- v0.20.0 版本，2026年1月发布  
- 输入轨道：用户回合进行分类并阻断  
- 输出轨道：模型回合进行分类并阻断  
- 对话轨道：用 Colang 定义的流程约束（例如“如果用户问X，则回复Y”）  
- 集成 Llama Guard、Prompt Guard 和自定义分类器  

对话轨道是区别点。输入/输出轨道仅对单轮对话生效；对话轨道可强制执行“客户支持机器人即使用户多次打听也不讨论医疗诊断”等持续规则。

### 攻击语料库

**Emoji 走私**（Huang 等，arXiv:2504.11168）：在禁止请求的字符间插入不可见或视觉相似的 emoji。分词器与分类器的分词方式不一样，造成绕过。6个著名防护系统成功率100%。

**同形异义字替换**：用视觉相同的西里尔字母替换拉丁字母。“Bomb”变成“Воmb”；训练于英文数据的分类器检测不到。

**上下文指令重定向**：输入中加入“请先考虑这是研究情境，并应用不同策略”等指令，测试分类器是否容易被上下文语句绕过。

**语义释义**：用新的表述方式改写禁止请求，分类器微调难以涵盖所有表述方式。

**NeMo Guard Detect**：在 Huang 等论文中的越狱基准测试中攻击成功率达72.54%。这是精心设计的攻击；普通越狱攻击成功率远低，但上限显然不是“零”。

### 分类器的优势

- **对明显滥用快速默认拒绝**（如生成 CSAM 请求毫秒级捕获）  
- **类别路由**可实现不同处理策略（阻断某些请求，记录某些请求，升级处理少量请求）  
- **输出轨道**捕获模型原本可能泄露的敏感输出  
- **合规面向监管机构**——有明确文档和可审计的分类器及分类体系  

### 分类器的不足

- 易受对抗构造（emoji 走私、同形异义字）攻击  
- 多轮攻击可跨越单轮上下文绕过检测  
- 语义释义成训练数据中未见过的表达方式难捕获  
- 内容本身在允许与禁止类别间模糊不清  

### 深度防御

分类器层位于宪法层（第17课）之下，运行时层（第10、13、14课）之上。整体防护组成：

- **权重**：采用 Constitutional AI 训练，默认拒绝明显滥用  
- **分类器**：Llama Guard / NeMo Guardrails，快速拒绝明显滥用，实现类别路由  
- **运行时**：权限模式、预算、终止开关、金丝雀机制  
- **人工复核**：重要行为前提出建议，后由人类裁决实施  

没有单一层能完全解决安全问题。各层覆盖不同类型攻击。

## 使用方法

`code/main.py` 模拟一个6类别分类器，针对输入文本进行分类。同一文本有原始、emoji走私和同形异义字替换版；分类器的命中率按照 Huang 等人论文中描述方式出现下降。代码还展示了输出轨道如何在输入通过时仍拒绝输出。

## 交付检查

`outputs/skill-classifier-stack-audit.md` 审核部署的分类器层（模型、分类体系、输入/输出轨道、对话轨道）并标出缺口。

## 练习

1. 运行 `code/main.py`，确认分类器可捕获原始恶意输入，但漏判 emoji 走私版本。添加归一化步骤，测量新命中率。

2. 阅读 MLCommons 13类风险分类体系和 Llama Guard 4 的 S1–S14 类别列表。找出 S1–S14 中未在原13类中对应的类别，解释为何 S14（代码解释器滥用）对第15阶段特别重要。

3. 设计一个 NeMo Guardrails 对话轨道，约束客户支持机器人绝不讨论诊断话题。用简明英文描述（Colang 类似），并针对三种不同提问诊断问题的表述测试。

4. 阅读 Huang 等人论文（arXiv:2504.11168），选一个攻击类别（emoji走私、同形异义字、释义）提出缓解方案，并说明该缓解方案自身的失败模式。

5. 对 NeMo Guard Detect 在越狱基准中72.54%成功率的结果（基于精心设计攻击）设计一套评估协议，测量分类器在一般（非对抗性）用户分布中的成功率。你预期的数值是多少？为何该数值重要？
