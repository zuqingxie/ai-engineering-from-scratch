# 为什么选择 Transformers——RNN 的问题所在

> RNN（循环神经网络）（RNNs）一次处理一个 token（标记）。Transformers（Transformer 架构）一次处理所有 token。这个单一的架构赌注自 2017 年以来改变了深度学习的所有扩展曲线。

**类型:** 学习  
**语言:** Python  
**先决条件:** 第三阶段（深度学习核心）、第五阶段 · 09（序列到序列）、第五阶段 · 10（注意力机制）  
**时间:** 约 45 分钟

## 问题

在 2017 年之前，全球所有最先进的序列模型——语言、翻译、语音——几乎都是循环神经网络。LSTM（长短期记忆网络）和 GRU（门控循环单元）在类 ImageNet 的翻译基准赛中称霸了半个十年。它们是唯一的选择。

它们有三个致命弱点。顺序计算意味着你不能在时间轴上并行：token `t+1` 需要 token `t` 的隐藏状态。一个 1,024 个 token 的序列意味着在一个可以每周期执行 1,000,000 次浮点运算的 GPU 上需要运行 1,024 个串行步骤。训练的实际时间随着序列长度线性增长，而硬件是为并行设计的。

梯度消失意味着 50 个 token 之前的信息已经通过 50 个非线性函数被压缩。门控循环单元（LSTM, GRU）缓解了这种压缩，但并没有消除它。长距离依赖——“去年夏天在去京都的飞机上读的那本书……”——经常失败。

固定宽度的隐藏状态意味着编码器必须将整个源序列压缩成一个单向量再传给解码器。无论源序列是 5 个 token 还是 500 个，瓶颈形状都相同。

2017 发表的论文《Attention Is All You Need》提出了一个激进的想法：完全舍弃循环。让每个位置并行关注所有其它位置。一次巨大矩阵乘法，替代 1,024 次顺序矩阵乘法。

到 2026 年，结果在每个模态中都称霸。语言（GPT-5, Claude 4, Llama 4）、视觉（ViT, DINOv2, SAM 3）、音频（Whisper）、生物学（AlphaFold 3）、机器人学（RT-2）。同一个模块，不同输入。

## 概念

![RNN 顺序计算 vs Transformer 并行注意力](../assets/rnn-vs-transformer.svg)

**循环是瓶颈。** 一个 RNN 计算 `h_t = f(h_{t-1}, x_t)`。每一步都依赖于上一步。你无法在计算 `h_4` 前计算 `h_5`。在拥有超过 10,000 个并行核心的现代 GPU 上，长序列计算浪费了 99% 的硅片资源。

**注意力是广播。** 自注意力计算 `output_i = sum_j(a_ij * v_j)`，针对每对 `(i, j)` 同时计算。N×N 的注意力矩阵一次批量完成矩阵乘法。各步骤互不依赖，GPU 非常擅长。

**加速不是常数。** 它是 `O(N)` 串行深度和 `O(1)` 串行深度之差。实际上，在 N=512 时，Transformer 训练每轮速度比 RNN 快 5 到 10 倍，并且随着序列加长差距越显著，直到 hit 注意力的 `O(N²)` 内存墙（Flash Attention 在第 12 课中讲解过）。

**Transformer 的代价。** 注意力内存扩展是 `O(N²)`。对于 2K 上下文还行。面对 128K 上下文，则需要滑动窗口、RoPE 外推、Flash Attention 瓦片技术或线性注意力变种。循环的时间和内存都是 `O(N)`；Transformer 用内存换时间，并通过并行再次赢回时间。

**归纳偏置转变。** RNN 假设局部性和时序性。Transformers 则无偏假设——每对位置都是关注候选。这就是为什么 Transformer 需要更多数据才能训练好，但数据足够时能扩展得更远。Chinchilla（2022）形式化了这一点：给定足够的 token，Transformer 总是胜过同参数量的 RNN。

## 构建它

这里不构建神经网络——我们用数值模拟核心瓶颈，让你在笔记本上感受差距。

### 第一步：测量串行深度

参见 `code/main.py`。我们构建了两个函数。一个像 RNN 那样将序列作为加法链（串行）编码。另一个像注意力那样并行归约（广播）。数学相同，依赖关系图不同。

```python
def rnn_style(xs):
    h = 0.0
    for x in xs:
        h = 0.9 * h + x   # 无法并行：h 依赖上一个 h
    return h

def attention_style(xs):
    return sum(xs) / len(xs)  # 每个 x 独立
```

我们在最多 100,000 元素的序列上计时。RNN 版本是 `O(N)`，串行 CPU 流水线。即使纯 Python 实现，在序列长度 ≥ 1000 时，注意力样式的归约因 `sum()` 在 C 中实现、无解释器开销，依然快。

### 第二步：计算理论运算量

两个算法都做 N 次加法。区别在于*依赖深度*：下一步能开始前须连续执行多少运算。RNN 深度 = N，注意力深度 = 以树形归约是 log(N)，或并行扫描时为 1。深度，而非运算量，决定 GPU 时间。

### 第三步：长序列上的实际扩展

打印时间表，使 `O(N)` 差距清晰。在 2026 年的 Mac 笔记本上，长度小于 1000 的序列太快无法准确测量。10 万序列展现了明显的线性扫描。扩展到 16,384 token 的 Transformer 与 12 层 LSTM 等效，可见 2016 年训练时间为何成瓶颈。

## 使用它

2026 年何时仍选 RNN：

| 情况 | 推荐选型 |
|-------|----------|
| 流式推理，一次处理一个 token，内存常数 | RNN 或状态空间模型（Mamba, RWKV） |
| 超长序列（>1M token），注意力内存暴涨 | 线性注意力，Mamba 2，Hyena |
| 无矩阵乘法加速器的边缘设备 | 深度可分 RNN 在 FLOPs/瓦特上胜出 |
| 其他（训练、批量推理、上下文最大128K） | Transformer |

状态空间模型（SSM）（如 Mamba）实质是带结构化参数的 RNN，兼具最佳属性：`O(N)` 扫描内存、通过选择性扫描实现并行训练。它们在长上下文扩展上达到了 90% 的 Transformer 质量。2026 年大多数前沿实验室训练混合 SSM+Transformer 模型（如 Jamba, Samba）——循环并未消亡，只是个组成部分。

## 练习

1. **简单。** 从 `code/main.py` 中取 `rnn_style` 并将标量隐藏状态替换为长度 64 的隐藏状态向量。重新测量。串行开销随隐藏状态维度增长多少？
2. **中等。** 用纯 Python 实现并行前缀和（Hillis-Steele scan）。验证在长度 1024 上，与串行扫描输出数值相同。计算深度。
3. **难。** 将注意力样式归约移植到 GPU 上的 PyTorch。随序列长度从 64 到 65,536 测时。绘图并解释曲线形状。

## 关键词

| 术语 | 俗称 | 实际含义 |
|-------|-------|-----------|
| 循环 | “RNN 是顺序的” | 步骤 `t` 计算依赖于步骤 `t-1`，强制时间轴上串行执行。 |
| 串行深度 | “依赖图有多深” | 依赖操作最长链；即使硬件无限也限制总时间。 |
| 注意力 | “让 token 互相看” | 权重求和 `sum_j a_ij v_j`，其中 `a_ij` 来自位置 i 与位置 j 的相似度分数。 |
| 上下文窗口 | “模型能看到多少” | 注意力层可输入的位置数；平方内存开销与此成正比。 |
| 归纳偏置 | “架构中预设假设” | 对数据分布的先验；CNN 假设平移不变性，RNN 假设时间相关性。 |
| 状态空间模型 | “带代数的循环” | 通过结构化状态空间矩阵参数化的循环，可实现并行训练。 |
| 二次瓶颈 | “上下文为何代价高” | 注意力内存是 `O(N²)`；Flash Attention 降低常数，但不改变规模。 |
