# 分块策略比较

> 分块决定了您的检索器最终能呈现什么内容。如果边界划分错误，再强的 embedding model（嵌入模型）、reranker（重排器）、LLM（大语言模型）也无法修复下游的损失。

**类型:** 构建  
**语言:** Python  
**先决条件:** 第11阶段第04课（嵌入）、06课（RAG）、07课（高级RAG）；第19阶段B轨基础（第20-29课）  
**用时:** 约90分钟

## 学习目标
- 从零实现五种分块策略：fixed-window（固定窗口）、sentence（句子分块）、recursive-split（递归分割）、semantic clustering（语义聚类）、structural markdown headers（结构化 Markdown 头部分块）。
- 在带有金标答案跨度的基准语料库上衡量 recall@k，并解释为何一套策略在散文文本中表现最佳，而另一套策略适合技术文档。
- 阅读分块长度分布，识别每种策略带来的失败模式：孤立句子、中断符号、仅头部分块、语义漂移。
- 通过检查文档类型、平均段落长度、以及格式是否携带显式结构等三项属性，不运行基准测试即选出新语料库的默认分块策略。

## 问题描述

每个 RAG（检索增强生成）流程都从将源文档拆分为足够小，使嵌入模型能处理，同时又足够大保证每个片段内含有完整独立思想的块开始。划分边界决策不是超参数，而是检索器能返回内容的上限。

例如，提问“预算中断阈值是什么样”只有当包含该阈值的块被检索到时才可能成功。如果 fixed-window（固定窗口）拆分时将阈值与上下文切断，生成的嵌入就会进入不同簇，BM25分数下降，重排器看见噪声，LLM给出的答案就会错误。2024年的论文《LongRAG: Enhancing Retrieval-Augmented Generation with Long-context LLMs》测量到单纯由于分块选择引起的检索召回率最高有35个百分点的绝对差异。2025年后续关于上下文分块头的工作缩小了差距，但未完全消除。

本课将并行构建五种策略，对带有金标答案跨度的基准语料库进行测试，让你亲自观察召回率数据。

### 固定窗口（Fixed-window）

暴力基线。每 N 个字符切分。可选重叠，确保句子在靠近边界处仍完整落在某区块内。快速、确定性强，但边界效果极差。作为对照使用，而非默认选择。

### 句子分块（Sentence）

通过正则或有限状态机分割句子边界。将一个或多个句子打包成一个块，目标字符数以内。不会断词但会断段落和章节。许多早期 RAG 流程默认用此策略，对于无结构的散文是合理选择。

### 递归分割（Recursive split）

2023年流行的层级策略。先尝试在最强分隔符处切分（双换行，段落），fallback下一层（单换行），再到句子，最后到字符。递归直到块大小满足预算。对结构不规则文档表现强，因为它会根据文档区域自适应。

### 语义聚类（Semantic clustering）

对每句嵌入，聚类连续句子话题中心相近的句子。当相似度低于阈值时切分。边界反映语义，而非字符位置。构建较慢，依赖嵌入模型，但对于段落内部主题转变的文档更稳健。

### 结构化 Markdown 头部（Structural markdown headers）

针对带有显式结构的文档（Markdown、reStructuredText、RFC样式编号章节），在各级标题边界切分。每块包含标题及以下直至同级或更高级标题前的全部内容。每话题块最小，但仅当语料格式良好时适用。

### recall@k 如何衡量边界选择

带金标的查询包含答案字符跨度。分块后，查看检索前k块中是否与答案跨度有重叠。有则该查询的 recall@k 是1，无则为0。对所有查询求平均。对每种策略重复评估，结果显示哪个边界策略更适合现有语料库。

## 实现细节

`code/main.py` 实现：

- `fixed_window(text, size, overlap)` - 基线实现。
- `sentence_chunks(text, target)` - 简单句子打包。
- `recursive_split(text, separators, target)` - 层级递归分割。
- `semantic_chunks(text, similarity_threshold)` - 基于确定性模拟嵌入的中心聚类。
- `structural_markdown(text)` - 头部感知切分器。
- `mock_embed(text, dim)` - 基于哈希的伪嵌入，方便离线循环。
- `DenseIndex` - 与第19阶段B轨混合检索课中相同结构。
- `eval_recall(strategy, corpus, queries, k)` - 评测循环。
- `main()` - 对各策略在基准语料上运行并打印 recall@k 表格。

运行：

```bash
python3 code/main.py
```

输出为策略每行、各k值的召回率小表。句子策略在结构化语料中表现差。结构化 Markdown 适合 Markdown 语料。递归策略适应混合语料。语义聚类在无结构散文内效果最佳。

## 表格不会隐瞒的失败模式

**孤立句子。** 句子分块时可能遗漏主题句，导致嵌入指向错误簇。

**中断符号。** 固定窗口会将代码或 YAML 标识符拆断，分成两半，嵌入成噪声。

**仅头部分块。** 结构化 Markdown 可能生成只含 `## 标题` 的空块。过滤掉或与下一块首段合并。

**语义漂移。** 当语料主题单一时，语义聚类分块过小。5000字符大块内包含多个答案，嵌入过于分散。可结合硬字符上限。

**陈旧嵌入。** 语义聚类依赖嵌入模型。换模型就需换分块。将分块模型和检索模型分开固定，或一同重建索引。

## 不跑基准测试时如何选默认

新语料默认分块器由三项属性确定。

| 属性 | 值 | 默认策略 |
|------|-------|---------|
| 文档类型 | 无结构散文 | 递归分割，目标800字符 |
| 文档类型 | Markdown / RFC / API文档 | 结构化 Markdown |
| 文档类型 | 代码 | AST感知（超出范围，见第19阶段第02课） |
| 段落长度 | 长且单一主题 | 句子，目标500字符 |
| 段落长度 | 短且多主题 | 语义聚类，阈值0.6 |

不确定时，选递归分割。它是最强单策略基线。

## 使用方法

生产环境实践：

- 新管线发布前须先跑评测，不要盲目信赖库默认策略。
- 嵌入模型或语料变化后必须重新评测，最佳策略依赖语料。
- 将策略名保存在每个分块元数据，方便迟后追溯回归。

## 练习

1. 添加第六种策略：基于 `tiktoken` 的 token-window（令牌窗口），代替字符计数。并与 fixed-window 在相同基准下比较。
2. 在散文基准语料中注入 30% 代码块。重新跑表格。解释为何除了结构化 Markdown 外，所有策略召回率下降。
3. 用项目真实提供商的嵌入替换确定性伪嵌入。测量语义聚类召回率变化。报告策略间差异是扩大还是缩小。
4. 给每块添加一个 `summary` 字段：一句话的中心描述。在块正文后添加摘要再跑评测，测量召回提升。

## 关键词

| 术语 | 人们说 | 实际含义 |
|------|--------|----------|
| Recall@k | “查到正确块了吗？” | 查询中任一前k块与金标答案跨度重叠的比例 |
| Chunk overlap | “滑动窗口” | 在下个块中重复包括前块末尾的 N 字符 |
| Structural splitter | “头部感知分块” | 在 H1/H2/H3 等标题边界切分，标题文本包含在块内 |
| Semantic chunker | “话题感知分块” | 句子嵌入，基于中心相似度聚类，遇漂移切分 |
| Centroid drift | “话题转变” | 运行均值与下一句的余弦相似度低于阈值 |
