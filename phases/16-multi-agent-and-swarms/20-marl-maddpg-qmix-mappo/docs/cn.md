# MARL — MADDPG、QMIX、MAPPO

> 多智能体协调的强化学习（reinforcement-learning）传承，到2026年仍然影响着LLM-agent系统。**MADDPG**（Lowe 等人，NeurIPS 2017，arXiv:1706.02275）引入了集中训练、去中心化执行（Centralized Training, Decentralized Execution，CTDE）模式：训练时每个critic看到所有智能体的状态和动作；测试时则只运行本地actor。适用于合作、竞争和混合设置。**QMIX**（Rashid 等人，ICML 2018，arXiv:1803.11485）是带单调混合网络的值分解（value-decomposition）；每个智能体的Q值合成联合Q值，使得 `argmax` 操作可以干净地分布式计算——在星际争霸多智能体挑战（StarCraft Multi-Agent Challenge，SMAC）中表现卓越。**MAPPO**（Yu 等人，NeurIPS 2022，arXiv:2103.01955）是带集中值函数的PPO；在粒子世界、SMAC、谷歌研究足球、Hanabi上效果“出人意料的好”，且调参极少。这些方法支撑了必须去中心化行动的智能体团队策略训练。MAPPO是**2026年合作MARL的默认基线**。本课从一个小型网格世界玩具开始，建立三者，帮助形成肌肉记忆后再触及LLM-agent训练。

**类型：** 学习  
**语言：** Python（标准库，小型无NumPy实现）  
**先决条件：** 阶段09（强化学习），阶段16·09（并行群集网络）

## 问题

LLM-agent系统越来越多地训练跨智能体协调的策略：何时让出、何时行动、调用哪个伙伴。指导你训练此类策略的文献是多智能体强化学习（Multi-Agent Reinforcement Learning，MARL），它早于LLM浪潮且有一小批占优的算法。

没有模式词汇看MARL论文很痛苦。集中训练、去中心化执行（CTDE）、值分解和集中critic并非流行词，而是针对具体问题的具体答案：

- 独立强化学习（Independent RL，每个智能体独自学习）从各智能体视角看是非平稳的。很糟糕。
- 集中式强化学习（Centralized RL，一个智能体控制所有）不具备扩展性且违反执行约束。
- CTDE兼得两者：训练用全局信息，部署用局部策略。

## 概念

### 论文中使用的三种环境

- **Particle World（多智能体粒子环境）。** 简单的二维物理环境，含合作/竞争任务。MADDPG的原始测试平台。  
- **StarCraft Multi-Agent Challenge（SMAC）。** 合作微观管理，部分观察。QMIX的测试平台。动作离散，状态连续。  
- **谷歌研究足球、Hanabi、MPE。** MAPPO的基线环境。

不同环境的动作/观察类型不同。算法据此做出选择。

### MADDPG（2017）——CTDE模式

每个智能体 `i` 有actor `mu_i(o_i)`，将自身观测映射到动作。训练时每个智能体还有critic `Q_i(x, a_1, ..., a_n)`，可见所有观察和动作。actor通过策略梯度对critic的评估进行更新。

```text
actor更新：    grad_theta_i J = E[grad_theta mu_i(o_i) * grad_a_i Q_i(x, a_1..n) 在 a_i=mu_i(o_i) 处求导]
critic更新：   给定下一个状态的联合估计，对 Q_i(x, a_1..n) 进行时序差分（TD）
```

为什么使用CTDE：训练时，我们知道所有人的动作；用来减少各critic的方差。部署时，每个智能体仅看 `o_i` 并调用 `mu_i(o_i)`。

失败模式：critic的输入包含所有动作，随着智能体数量N增长而指数增长。超过约10个智能体后难以扩展，除非做近似。

### QMIX（2018）——值分解

仅适合合作环境。全局奖励为单调函数对每个智能体Q值之和：

```text
Q_tot(tau, a) = f(Q_1(tau_1, a_1), ..., Q_n(tau_n, a_n)),   df/dQ_i >= 0
```

单调性保证了 `argmax_a Q_tot` 可以由每个智能体独立选择 `argmax_{a_i} Q_i` 来计算。这完全符合你需要的**去中心化执行属性**。训练时，一个混合网络从每个智能体Q产生 `Q_tot`。

QMIX在SMAC上获胜的原因：合作的星际争霸微观管理是同质智能体、本地观察、全局奖励——非常适合值分解。

失败模式：单调性约束限制了表示能力；一些任务有非单调分解的奖励结构（例如某个智能体为团队牺牲）。拓展方法（QTRAN, QPLEX）对此有所放松。

### MAPPO（2022）——被忽视的默认选项

多智能体PPO（Multi-Agent PPO）：带集中值函数的PPO。每个智能体有自己的策略；所有智能体共享（或各自持有）可见全状态的值函数。Yu 等于2022年在五个基准上将MAPPO与MADDPG、QMIX及其拓展进行比较，发现：

- MAPPO在粒子世界、SMAC、谷歌研究足球、Hanabi、MPE上匹配或超过离策略（off-policy）MARL方法。
- 调参极少。
- 训练稳定；不同随机种子下表现可复现。

社区之前未充分重视在线策略（on-policy）的MARL直到这篇论文。2026年，MAPPO是合作MARL的默认基线；新方法必须超过它。

### 为什么LLM-agent工程师应关注

三种直接用途：

1. **路由器训练。** 元智能体选择哪个子智能体处理任务。这是一个包含N个去中心化子智能体和一个集中路由器的MARL问题。MAPPO适用。  
2. **角色涌现。** 生成型智能体模拟中，训练智能体随时间扮演互补角色实为变相的MARL问题。QMIX样式值分解从结构上强制互补性。  
3. **多智能体工具使用。** 智能体共享工具且竞争预算，通过CTDE训练生成符合资源约束的可部署本地策略。

实操提醒：2026年，大部分生产LLM-agent系统是通过prompt而非训练得到策略。MARL场景是具备（a）大量交互数据，（b）清晰奖励信号，（c）愿投入训练基础设施时的选择。

### CTDE作为RL之外的设计模式

即使不培训，CTDE也是有用的架构模式：

- 在*设计阶段*，假设团队全局可见。  
- 在*运行时*，严格执行去中心化：每个智能体仅见 `o_i`。

此模式迫使你明确维护每个智能体的状态，提前考虑部分可观测问题。许多生产多智能体系统默认了共享状态；CTDE的规范避免了这种隐式假设。

### 非平稳问题（Non-stationarity）

多智能体同时学习时，每个智能体的环境（含其他智能体的策略）是非平稳的。单智能体RL的理论失效。本课所涵盖的MARL算法都针对这一点提出了解决：

- MADDPG：集中critic查看所有动作，其值估计保持平稳。  
- QMIX：值分解使学习转向联合Q空间，最优性明确定义。  
- MAPPO：集中值函数减缓了来自其他智能体策略变化的方差。

在LLM-agent系统中，非平稳表现为“我方智能体上月运行正常，因上游智能体变更导致我方行为异常”。使用CTDE训练MARL是原则性解决方案；prompt层修补快但不持久。

### 本课不涵盖内容

训练真实神经网络是阶段09主题。本课构建了有脚本策略版本，演示CTDE、值分解和集中值函数模式，无梯度更新。目标是让你熟悉这些模式，然后再使用完整MARL库（PyMARL、MARLlib、RLlib多智能体）。

## 搭建示例

`code/main.py` 实现了三种模式演示，均在一个极小的2智能体合作网格世界中：

- 环境：2个智能体在4x4网格上，一个奖励球。任一智能体触达奖励球即得1分，任务结束。  
- `IndependentAgents` —— 每个智能体将其他当作环境。基线。  
- `MADDPGStyle` —— 集中critic计算联合值；actor策略根据其更新。脚本策略改进。  
- `QMIXStyle` —— 单调混合器的值分解。  
- `MAPPOStyle` —— 集中值函数；策略根据共享基线更新。

四者均运行相同回合，报告平均到达目标所需步数。CTDE变体比独立基线收敛到更短路径。

运行：

```text
python3 code/main.py
```

预期输出：独立智能体平均约6步；CTDE变体趋近于约3.5步（4x4网格最优为3步）。尽管使用脚本策略，模式差异仍明显。

## 交付要点

生产中使用MARL罕见。若使用：

- **从MAPPO开始。** 2022论文确定了该基线，先复现节省大量盲目追逐更复杂方法的时间。  
- **记录每个智能体的观测和动作流程。** 没有独立追踪难以调试MARL。  
- **训练代码与执行代码分离。** CTDE是一种规范，执行路径只触及 `o_i`。  
- **奖励塑形需警惕。** MARL对奖励设计极度敏感，一次协调错误可能导致智能体学会利用漏洞。进行对抗性测试。  
- **对于LLM-agent，优先考虑prompt策略。** 仅当具备交互数据、奖励信号和训练基础设施时才投资MARL训练。

## 关键词

| 术语         | 常用说法               | 实际含义                             |
|--------------|------------------------|------------------------------------|
| MARL         | “多智能体强化学习”     | 多智能体系统的强化学习。           |
| CTDE         | “集中训练，去中心化执行” | 训练时用全局信息，部署时用局部策略。 |
| MADDPG       | “多智能体DDPG”         | CTDE模式，集中critic可见所有观察和动作。 |
| QMIX         | “值分解”               | 每智能体Q值经单调混合，适合合作。  |
| MAPPO        | “多智能体PPO”           | 带集中值函数的PPO。2026默认基线。 |
| 值分解       | “单个Q值之和”           | 联合Q被表示为每智能体Q的单调函数。 |
| 非平稳       | “移动的目标”           | 各智能体的环境因他者学习而变化。   |
| 在线/离线策略 | “用当前/重放数据学习”  | PPO是在线（MAPPO）；DDPG和Q-learning为离线。 |
| SMAC         | “星际争霸多智能体挑战” | 合作微观管理基准，QMIX的发源地。   |
