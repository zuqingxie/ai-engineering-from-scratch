# Agents 的共识与拜占庭容错（Byzantine Fault Tolerance）

> 经典分布式系统的 BFT 遇上随机性 LLM。2025-2026 年涌现三条研究方向：**CP-WBFT**（arXiv:2511.10400）通过置信探测（confidence probe）加权每个投票；**DecentLLMs**（arXiv:2507.14928）无领导者架构，worker 并行提议，几何中位数汇聚；**WBFT**（arXiv:2505.05103）结合加权投票与层次结构聚类，拆分 Core 节点与 Edge 节点。《AI Agents 能共识吗？》（arXiv:2603.01213）实证表明即使是标量共识也极易破裂——单个欺骗代理就能损害多代理混合体。BFT 是必要条件，却非充分条件。本课将构建最简 BFT 协议，注入三种特定代理攻击（拜占庭谎言、拍马屁式从众、相关误差单一文化），并测量各共识变体的对抗能力。

**类型：** 学习 + 实作  
**语言：** Python（标准库）  
**预备知识：** Phase 16 · 07（社会心智与辩论），Phase 16 · 13（共享内存）  
**时长：** ~75 分钟

## 问题

你有 N 个 LLM 代理各自输出答案。它们无法达成一致。多数投票选出错的答案因为两个代理高度相关（同基模型、同训练数据、同失败模式）。第三个代理错误地以全新方式出错——导致多数派是虚假多数。

再加一个欺骗代理：故意撒谎；或者拍马屁代理：总是赞同最后发言者。在经典 BFT 中，拜占庭节点假设占比为 `f < n/3`，并可任意行为。2026 年的现实是 LLM 节点即使诚实也具随机性，模型间相关，并受彼此输出影响，不能视为独立的伯努利投票者。

经典 BFT（PBFT，1999）不是错，而是不完整。它能处理随机位翻转，却不能处理“3 个诚实代理因共享训练数据而共幻觉”的情况。本课从 PBFT 基础出发，叠加三种 2025-2026 年的新适配。

## 概念

### 经典 BFT 带给你的

Practical Byzantine Fault Tolerance（Castro & Liskov，OSDI 1999）容忍 `f < n/3` 拜占庭节点。协议包含三个阶段（pre-prepare、prepare、commit）和两大原语（签名消息、法定证书）。保证在 `n >= 3f + 1` 个诚实与恶意节点间达成单值共识。

保证强大，但假设：

1. **故障独立。** 拜占庭节点不协同。
2. **诚实节点完全诚实。** 诚实节点输出正确。协议只解决分歧对齐。
3. **问题有客观真值。** 错误的共识依然是共识。

LLM 代理违反全部三条：  
同基模型的两个代理共享故障；  
“诚实” LLM 仍会幻觉；  
模糊问答中，“真相”是代理共识，外部无神谕。

### 三种 LLM 特定攻击

**拜占庭谎言。** 一个代理故意输出错误答案。PBFT 能处理 `f < n/3` 的此类。

**拍马屁从众。** 一代理先看其他答案，投票与最后发言者一致。非恶意，但和最响声音关联。经典 BFT 不阻止此类因代理签名合法。

**相关误差单一文化。** 三代理共享基模型。它们产出同样错误的幻觉。多数派错误。经典 BFT 无助，因为三代理“诚实”一致。

### 2025-2026 年的应对

**CP-WBFT**（arXiv:2511.10400）— 置信探测加权 BFT。每个投票者附带置信度探测（自报概率或校准模型预测），用置信度加权投票。报告在完全图上提升 85.71% BFT 效果。缓解：拍马屁从众（顺从代理通常置信度低）。

**DecentLLMs**（arXiv:2507.14928）— 无领导者。worker 并行提案，evaluator 评评分，最终答案是计分位置的几何中位数。容忍 `f < n/2`。缓解：拜占庭谎言与相关误差（几何中位数对离群点稳健，靠近稠密簇而非模型偏均值）。

**WBFT**（arXiv:2505.05103）— 层次结构聚类加权 BFT。按回应质量及历史学到的信任分配投票权重。聚类划分 Core 和 Edge，优先达成 Core 共识，再由 Edge 跟进。缓解：可扩展性（小型 Core 快速达成）及部分缓解单一文化（Core 可选多样性）。

### 实证：《AI Agents 能达成共识吗？》（arXiv:2603.01213）

论文测量了多前沿模型中的标量共识（对单一数值的共识）。发现令人不安：

- 即使无对手，LLM 代理对标量问题分歧率在多基准超过 30%。
- 一个欺骗角色能使多代理共识从诚实基线偏移超过 40 个百分点。
- 分歧率与模型多样性相关——异质集群分歧多于同质集群（好处是误差不相关），但也更慢达成一致（坏处是达共识所需时间更长）。

总结：BFT 给你输出对齐机制，但不保证对齐输出正确。需结合验证（Phase 16 · 08 角色专精）、多样性（Phase 16 · 15 辩论变体）与评估代理（Phase 16 · 24 基准）。

### 核心协议（简化）

LLM 代理的最简 BFT 轮次：

```text
1. 任务到达；每个代理 i 产出答案 a_i
2. 每个代理附加置信探测 c_i ∈ [0, 1]
3. 汇总器收集所有 n 个代理的 (a_i, c_i)
4. 汇总器按语义聚类（等价答案）
5. 汇总器计算每聚类 C 权重：
     w(C) = sum_{i in C} c_i
6. 若最大权重大于 threshold * sum(c_i)，返回最大权重聚类，否则重试或升级
7. 记录少数派聚类及其来源，供事后审计
```

语义聚类是针对 LLM 的创新步骤。比如“两种答案‘研究报告了4.2%’和‘4.2%提升’”同簇。简单字符串匹配无法识别。生产环境下用廉价嵌入模型或显式规范化。

### 阈值调节

`threshold` 参数决定接收还是重试。阈值太低接受弱多数；太高则永不接受。实测范围：`n=5-7` 时设 0.5-0.67，较小 n 时更高。阈值以下则升级给人工或不同代理集群。

### 共识无益处的场景

- **模糊问题。** 无客观真值时，共识只是观点。
- **复合问题。** 比如“写代码并解释”，两个答案，分别投票。
- **对抗多轮。** 若代理可观测以前轮并模仿（见 Du 2023 辩论），便会无视真相互相应和。限制轮次（通常 2-3 轮）。

## 实作

`code/main.py` 实现：

- `AgentVoter` — 脚本策略（答案+置信度）
- `MajorityVote` — 经典绝对多数投票
- `CPWBFT` — 置信度加权投票与语义聚类
- `DecentLLMs` — 计分提案的几何中位数汇聚
- `Scenario` — 对三种攻击模式下各聚合器运行

攻击模式：

1. `byzantine`：一个代理带高置信度撒谎
2. `sycophancy`：一个代理复制第一个答案，置信度匹配
3. `monoculture`：三个代理共享错误答案（相关错误），置信度中等

运行：

```text
python3 code/main.py
```

期望输出：一张（攻击, 聚合器）->最终答案的表格，正确答案高亮。多数投票失败于单一文化。CPWBFT 置信权重减缓了拍马屁攻击。DecentLLMs 几何中位数在单一文化少于半数时向诚实簇靠拢。

## 交付要求

发送任何共识机制前：

- **用至少上述三种攻击模式进行攻击测试。** 协议应可预测失败，不可默默崩溃。
- **记录每个少数派聚类及来源。** 少数派聚类是关联错误的预警。
- **限制轮次。** 不得“持续辩论直至一致”，避免奖励拍马屁。
- **区分一致性与正确性。** 共识输出送独立验证器，验证器与集群独立。
- **监测一致率。** 快速上升意味着从众偏差；快速下降意味着模型漂移。

## 练习

1. 运行 `code/main.py`。确认多数投票在单一文化攻击失败，CPWBFT 当单一文化置信度低于 0.7 时部分缓解。
2. 增加第四种攻击：**沉默弃权**——一个代理拒绝回答（“我不知道”）。各聚合器应如何对待弃权？实现你的策略。
3. 将语义聚类从字符串规范化改为嵌入相似度（可用任一开源嵌入模型）。拍马屁攻击效果如何变化？
4. 阅读 CP-WBFT（arXiv:2511.10400）。实现置信探测校准步骤（用独立校准模型检测每代理自报置信度）。测量单一文化场景下准确率提升。
5. 阅读《AI Agents 能达成共识吗？》（arXiv:2603.01213）。复现简化的标量一致性实验：三代理，一个标量问题，带欺骗角色提示。CPWBFT 或 DecentLLMs 能否检测出欺骗？

## 关键词

| 术语 | 一般说法 | 实际含义 |
|------|----------|-----------|
| BFT | “拜占庭容错” | Castro-Liskov 1999 协议，容忍 `f < n/3` 的任意故障。 |
| Byzantine | “任意恶劣行为” | 可说谎、丢消息、静默失败，非安全宕机节点。 |
| Confidence probe | “你有多确定？” | 投票附带的自报或校准预测概率。 |
| Semantic clustering | “同义答案不同词” | 投票前将等价答案聚合。 |
| Geometric median | “稳健中心” | 极小化与样本距离和的点，稳健不受异常值影响。 |
| Monoculture | “同模型同缺陷” | 代理共享训练数据或基模型导致的相关错误。 |
| Sycophantic conformity | “随响亮声音附和” | 投票倾向于第一个或最响亮说话者。 |
| Core/Edge | “层次式 BFT” | WBFT 拆分核心与边缘节点，先达成 Core 一致，再由 Edge 跟进。限制延迟。 |
