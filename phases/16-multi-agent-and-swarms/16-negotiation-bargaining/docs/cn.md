# 谈判与讨价还价

> 智能体协商资源、价格、任务分配和条款。2026年基准集很清楚：NegotiationArena（arXiv:2402.05863）显示，LLMs 通过角色操控（“绝望”）可以将收益提升约20%；“Measuring Bargaining Abilities”（arXiv:2402.15813）显示买方比卖方更难，规模不起作用——他们的 **OG-Narrator**（确定性报价生成器 + LLM 旁白）将成交率从26.67%提升到88.88%；大型自动化谈判竞赛（arXiv:2503.06416）进行了约18万次谈判，发现 **chain-of-thought-concealing**（思路隐藏）智能体通过隐藏推理来获胜；Bhattacharya 等人2025年基于哈佛谈判项目指标评定 Llama-3 最有效，Claude-3 最激进，GPT-4 最公平。本课实现了合同网协议（FIPA 前身，课程02），连接了 LLM 风格买卖双方，运行了 OG-Narrator 风格的分解，并测量结构选择对成交率的影响。

**类型：** 学习 + 构建  
**语言：** Python（标准库）  
**先决条件：** 阶段16 · 02（FIPA-ACL 传承）、阶段16 · 09（并行群体网络）  
**时长：** ~75分钟

## 问题

两个智能体需要就价格达成一致。单凭纯语言提示，2024-2026年的 LLMs 在紧参数化讨价还价中成交率出乎意料地低（arXiv:2402.15813 中约27%）。规模并不能解决问题：GPT-4 在谈判结构上并不优于 GPT-3.5；它只是在谈判*语言*方面更擅长。

根本问题是 LLMs 混淆了两个岗位——决定报价和叙述报价。OG-Narrator 将其分离：确定性报价生成器计算数值动作；LLM 只负责叙述。成交率跃升至约89%。

这反映了一个经典的多智能体发现：将机制与通信层分离是成功关键。合同网协议（FIPA，1996；Smith，1980）是参考的任务市场机制。把 LLM 插入旁白位置，就成了现代的 LLM 驱动型任务市场。

## 概念

### 合同网协议，一段话总结

Smith 1980年合同网协议：一个**管理者**广播**征求提案（call for proposals，cfp）**；**竞标者**以包含报价的**提议（propose）**消息回应；管理者选出赢家并向赢家发送**接受提案（accept-proposal）**，向输家发送**拒绝提案（reject-proposal）**。赢家完成工作。可选消息：**拒绝（refuse）**（竞标者拒绝提案）。FIPA 将此规范化为 `fipa-contract-net` 交互协议。

### OG-Narrator 为什么赢

《测量语言模型的讨价还价能力》（arXiv:2402.15813）观察到：

- LLMs 常破坏讨价还价规则（以无意义的价格报价，忽视对方的 ZOPA）。
- 锚定不好（接受糟糕的首次报价；反报价非战略性而是符号化）。
- 规模无法修正这些。大模型语言更合理但战略错误类似。

OG-Narrator 分解：

```text
           ┌──────────────────┐        ┌──────────────────┐
  state  → │ 报价生成器       │ price → │  LLM 旁白        │ → message
           │  （确定性）     │        │  （撰写人类风格  │
           │                  │        │   说明）         │
           └──────────────────┘        └──────────────────┘
```

报价生成器是经典谈判策略：Rubinstein 讨价还价模型、Zeuthen 策略，或基于价格的简单以牙还牙。LLM 负责叙述。消息包含确定性价格和自然语言框架。

成交率提升原因：
- 价格保持在讨价还价区间。
- 锚点是战略性的，而非情绪化。
- LLM 擅长写作。

### NegotiationArena 发现

arXiv:2402.05863 提供标准基准。主要发现：

- 通过采用角色（“我急于在周五之前卖出”）LLMs 能提升约20%的收益——角色操控是一种真实战术。
- 公平/合作型代理被对抗型代理利用；防御需要明确的对抗姿态。
- 对称配对在约40%的基准场景中收敛至不公平结果。

这不是说“LLMs 是糟糕谈判者”，而是“LLMs 过于像人类谈判者，包括其易被利用的部分”。

### 思路隐藏（Chain-of-thought concealment）

大型自动化谈判竞赛（arXiv:2503.06416）进行了约18万次谈判，涵盖多种 LLM 策略。赢家隐藏了他们的推理：

- 如果智能体在公开可见的 scratchpad 中打印“我最多只能出价75美元；我的保留价是70美元”，对手就会看到。
- 赢家私下计算策略；输出通道只包含报价和最小必要的旁白。

这呼应了经典博弈论（Aumann 1976关于理性与信息）：泄露私人估值会降低收益。LLMs 不具备此直觉，快乐地将保留价等推理痕迹打印给对方。

工程教训：私有 scratchpad 上下文必须与公开消息上下文分离。这不是可选的。

### Bhattacharya 等人 2025 年模型排名

基于哈佛谈判项目指标（原则性谈判、BATNA 尊重、利益互惠）：

- **Llama-3** 是成交率与收益最高效的谈判者。
- **Claude-3** 是最激进的谈判者（高锚点，后期让步少）。
- **GPT-4** 是最公平的（不同配对间收益方差最小）。

2025年的快照。重点不是2026年4月谁赢，而是不同基模型拥有持续的谈判风格。异构合奏（课程15）就是这种多样性来源之一。

### 通过合同网协议 + LLM 实现任务分配

合同网在现代 LLM 多智能体中的复用：

1. 管理者智能体将任务拆分成子单元。
2. 广播带任务描述的 `cfp` 给工作者智能体。
3. 每个工作者返回报价：(价格，预计完成时间ETA，自信度)，价格可以是代币、计算资源或美元。
4. 管理者选出赢家（单个或多个，视任务而定）并授予任务。
5. 被拒绝的工作者可以竞标其他任务。

该机制可扩展至100+工作者，因为协调是广播响应式，而非同步聊天。已应用于生产：微软智能体框架的编排模式、部分 LangGraph 实现。

### LLM-利益相关者交互谈判

NeurIPS 2024（https://proceedings.neurips.cc/paper_files/paper/2024/file/984dd3db213db2d1454a163b65b84d08-Paper-Datasets_and_Benchmarks_Track.pdf）引入多方可评分游戏，带**秘密分数**与**最低接受阈值**。每个利益相关者有私有效用，LLM 必须从消息中推断。这是两方讨价还价推广到N方联盟形成的泛化模型，对具备异构能力的生产任务市场极具意义。

### 叙述与机制规则

在所有2024-2026年谈判基准中，一条一致的工程规则是：

> 让 LLM 叙述。不要让 LLM 计算报价。

如果报价需要数字（价格、ETA、数量），应从谈判状态确定性生成，让 LLM 进行语言框架构造。如果报价需结构化方案（任务拆分，角色分配），让 LLM 起草，但发送前须模式与约束检验。

## 构建它

`code/main.py` 实现：

- `ContractNetManager`、`ContractNetTask`、`Bid` — 管理者 + 竞标者，广播 cfp，收集提案，授予任务。
- `og_narrator_bargain(state, rng)` — OG-Narrator 买家：向中点的确定性 Zeuthen 式让步策略。
- `seller_response(state, rng)` — 确定性卖家反报价策略（两个风格的结构性基准）。
- `naive_llm_bargain(state, rng)` — 模拟全 LLM 讨价还价者：高方差选择价格，常落在 ZOPA 外。
- 测量：1000次试验成交率，每次随机采样新的保留价。

运行：

```text
python3 code/main.py
```

预期输出：naive-LLM 成交率约65-75%；OG-Narrator 成交率约85-95%；15-25点差距即分离报价生成与叙述的结构优势。并附带一个含三个竞标者和一个任务的合同网任务市场示例。

## 使用它

`outputs/skill-bargainer-designer.md` 设计了讨价还价协议：谁生成报价（确定性或 LLM），谁叙述，如何私有 scratchpad 与公开消息分离，如何监控成交率。

## 交付它

生产谈判清单：

- **分离 scratchpad。** 私有状态绝不进入对方上下文，非议价项。
- **确定性报价生成。** 价格、数量、ETA：计算，不要提示。
- **校验所有输入报价** 对照模式。ZOPA 外的提案在协议边界拒绝。
- **限制轮数。** 最大3-5轮；僵局时升级到调解者。
- **持续测量成交率与收益方差。** 成交率下降是症状——通常是提示漂移或对方攻击。
- **记录所有被拒绝提案** 及确定性的拒绝理由。合同网管理者需让落标者知因。

## 练习

1. 运行 `code/main.py`。确认 OG-Narrator 成交率优于 naive-LLM。差多少？
2. 实现**基于角色的收益提升**（arXiv:2402.05863）——买方在旁白中采用“本周急需购买”角色，报价生成器不变。成交率或收益有变吗？
3. 实现思路**隐藏**：维持一个未传递给对方的私有 scratchpad 字符串。若不小心泄露（模拟交换通道）会怎样？
4. 将合同网扩展为带保留价的 N竞标者拍卖。所有出价均超过保留价时，管理者如何在价格最低和质量最高间选择？你会挑哪个授奖规则，为什么？
5. 阅读 Bhattacharya 等人2025年哈佛谈判项目指标。实现两个谈判者（激进和公平风格）。在对称与非对称配对下测量收益方差。

## 关键词

| 术语          | 常见说法           | 实际含义                                      |
|--------------|--------------------|---------------------------------------------|
| Contract Net | “任务市场”          | Smith 1980，FIPA 1996。cfp + propose + accept/reject。经典任务市场。       |
| ZOPA         | “可能协议区间”       | 买方最大值与卖方最小值的重叠区。区外报价无法成交。                   |
| BATNA        | “谈判备选方案”       | 若本协议失败你的备选方案。设定你的保留价格。                       |
| OG-Narrator  | “报价生成器 + 旁白”  | 分解：确定性报价，LLM 旁白。                                      |
| Zeuthen strategy | “风险最小化让步”   | 经典报价生成器，根据风险限度进行让步。                               |
| Rubinstein bargaining | “交替报价均衡”  | 含折扣的无限期讨价还价博弈模型。                                    |
| CoT concealment | “隐藏你的推理”       | arXiv:2503.06416 的赢家保留私有 scratchpad；公开通道仅展示报价。     |
| Persona manipulation | “角色操控”         | arXiv:2402.05863：通过表现绝望/紧迫感提升约20%收益。                 |
