# 评估与协调基准

> 五个2025-2026年的基准覆盖多智能体评估领域。**MultiAgentBench / MARBLE**（ACL 2025, arXiv:2503.01935）评估星形/链式/树形/图形拓扑结构的里程碑关键绩效指标（KPI）；**图结构在研究中表现最佳**，认知规划在各拓扑下提升约3%的里程碑达成率。**COMMA**评估多模态非对称信息协调；包括GPT-4o在内的最先进模型难以打败随机基线。**MedAgentBoard**（arXiv:2505.12371）覆盖四类医疗任务，常发现多智能体不优于单一LLM。**AgentArch**（arXiv:2509.10769）基准测试企业代理架构，结合工具使用＋记忆＋编排。**SWE-bench Pro**（[arXiv:2509.16941](https://arxiv.org/abs/2509.16941)）包含41个仓库共1865个问题，涵盖商业应用、B2B服务、开发者工具；前沿模型在Pro上得分约23%，而在Verified上超过70%——现实的污染检查。Claude Opus 4.7（2026年4月）以显式智能体团队协调报道**64.3%**的Pro成绩（无Anthropic一手资料，预览性质）；Verdent（智能体框架）在Verified上有**76.1% pass@1**（[Verdent技术报告](https://www.verdent.ai/blog/swe-bench-verified-technical-report)）。**AAAI 2026 Bridge Program WMAC**（https://multiagents.org/2026/）是2026年的社区焦点。本课程基于MARBLE的指标，展开拓扑与指标的扫查，并确立“仅通过SWE-bench Verified不能证明泛化能力”的规则。

**类型：** 学习  
**语言：** Python（stdlib）  
**先决条件：** 第16阶段 · 15（投票与辩论拓扑），第16阶段 · 23（失效模式）  
**时长：** ~75分钟

## 问题

当论文宣称“我们的多智能体系统更优”时，问题是：比什么更好，在什么指标上，用什么方式衡量？2023-2024年多智能体评估混乱无序——各自选择指标、基线和任务集。2025-2026年基准引入了结构化。

没有共享基准，无法有意义比较两个多智能体系统。更糟的是，没有保留基准，前沿模型可能被污染。到2025年中期，SWE-bench Verified在训练语料中部分污染；分数被抬高；Pro设计为无污染的现实检查。

本课列举五大2026年度权威基准，说明各自测量内容，教你用怀疑态度解读基准声明。

## 概念

### MultiAgentBench （MARBLE）— ACL 2025

arXiv:2503.01935。评估四种协调拓扑（星形、链式、树形、图形）在研究、编码和规划任务上的表现。以里程碑为基础的KPI追踪部分进展，而非仅看终极成功。

测量结果：

- **图形**拓扑在研究场景下最佳，支持任意对任意的批判。
- **链式**在逐步细化编码中表现最佳。
- **星形**适合快速事实归纳。
- 超过约4个智能体后，图形拓扑出现**协调负担**。
- **认知规划**提升各拓扑约3%的里程碑达成率。

适用场景：需要苹果对苹果比较协调拓扑时。MARBLE仓库（https://github.com/ulab-uiuc/MARBLE）提供评估器。

### COMMA — 多模态非对称信息

覆盖智能体具有不同观察模态，且必须在不完全信息共享下协调的任务。结果令人不安：包括GPT-4o在内的先进模型都难以打败COMMA中代理协作的**随机基线**。信号是多智能体多模态协调训练不足，评估缺失——LLM单一模态合作表现尚可；多模态协调崩溃。

适用场景：系统涉及多模态或非对称信息协调。COMMA的无效结果是 “声称前先测量”的警告。

### MedAgentBoard — 领域压力测试

arXiv:2505.12371。四类医疗任务：诊断、治疗规划、报告生成、患者沟通。比较多智能体、单一LLM和传统规则系统。

发现：多智能体在大多数类别未必优于单一LLM。多智能体优势有限——任务分解对明确可分子任务（诊断＋治疗）有效；但协调成本超过专业化收益时（报告生成）反而不利。

适用场景：领域存在明确的单一LLM基线。若MedAgentBoard的结论能推广，许多多智能体方案被认为过度设计。

### AgentArch — 企业架构

arXiv:2509.10769。企业环境下工具使用、记忆、编排分层叠加。基准分拆每层贡献：添加工具有多少帮助？添加记忆呢？多智能体编排呢？

适用场景：设计企业级智能体栈，需要证明每层价值。AgentArch帮助避免买入无法量化的功能。

### SWE-bench Pro — 现实检验

arXiv:2509.16941。41个代码仓库内1865个问题，涵盖商业应用、B2B服务、开发者工具。设计成**无污染**，有后续训练截断。前沿模型在Pro上得分约23%，而在Verified上超过70%。差距即污染信号。

2026年4月成绩：  
- Claude Opus 4.7 Pro得分：**64.3%**（报道显式智能体团队协调；无Anthropic第一手资料，视为试验数据）  
- Verdent（智能体框架）Verified得分：**76.1% pass@1**（[技术报告](https://www.verdent.ai/blog/swe-bench-verified-technical-report)）  
- 无智能体框架的前沿模型Pro原始分：23%-35%（[SWE-bench Pro论文](https://arxiv.org/abs/2509.16941)）

结论是：“我们超过SWE-bench Verified”不再代表能力。Pro是当前的准入门槛。智能体团队框架在Pro上带来约30-40点增益，这是2026年多智能体协调最强有力的实证论据。

### AAAI 2026 WMAC

AAAI 2026桥接项目——多智能体协调研讨会（https://multiagents.org/2026/）。2026年多智能体AI研究的社区核心。被接受的论文与会议论文集是评估新方法的权威场所；生产决策应优先参考WMAC接受的结论，而非arXiv预印本。

### 对基准声明保持怀疑态度 — 2026年核查清单

当有人宣称多智能体结果时：

1. **哪个基准，哪个数据划分？** SWE-bench Verified 与 Pro的区别极大。错误划分下的数字毫无价值。  
2. **污染检测。** 基准发布时间是否晚于模型训练截断？否则需谨慎。  
3. **基线比较。** 对单一LLM基线，对随机基线，对先前多智能体工作，而非“未调优的相同系统版本”。  
4. **统计显著性。** 实验次数、p值、置信区间。前沿模型方差高，一次运行易误导。  
5. **任务多样性。** 一项任务还是多项？泛化性关乎生产。  
6. **成本披露。** 每任务token数，真实时间。90%性能但成本20倍，是业务决定，不是能力宣称。

### 基准未能评估好的方面

- **长时程协调。** 多天真实交互。现有基准都很短。  
- **对抗性韧性。** 若某智能体恶意或被攻破，后果如何？  
- **部署期间的漂移。** 基准静态，生产数据分布在变。  
- **成本归一化性能。** 多数基准仅报准确率，未报每成本准确度。

自己搭建针对关心维度的内部基准，往往是正确的选择。

## 构建实践

`code/main.py`是非交互式演练：

- 模拟3个多智能体系统的玩具任务。  
- 计算MARBLE风格的里程碑指标。  
- 通过保留任务队列模拟污染检测。  
- 明确对比随机基线。  
- 打印基准声明评分表。

运行：

```bash
python3 code/main.py
```

预期输出：系统评分表，包括原始准确率、里程碑达成率、每任务成本、相对随机基线差值及污染检查注释。

## 使用方法

`outputs/skill-benchmark-reader.md`读取任意多智能体基准声明，并应用核查清单。输出：等级与注意事项。

## 产出规范

生产评估纪律：

- **构建反映实际生产分布的内部基准。** 公共基准可参考，但不可替代。  
- **每次比较包含随机基线。** 若协调任务上无法大幅超越随机，任务本身可能设计不合理。  
- **准确度旁披露成本。** token成本与真实时间均需报告。运维团队需要双重指标。  
- **季度重建基准。** 生产分布在变，过时基准会误导。  
- **避免过拟合公开基准。** 若团队针对SWE-bench Pro特意调优，必然在生产环境退步。

## 练习

1. 运行`code/main.py`。识别三个模拟系统中哪个里程碑成本最低。它是否与最高原始准确率系统对应？  
2. 阅读MultiAgentBench（arXiv:2503.01935）。结合自己的任务领域，决定MARBLE推荐的四种拓扑中哪种。并据论文结果论证。  
3. 阅读SWE-bench Pro论文。其具体如何实现抗污染？该技术可否应用于你关注的其他基准？  
4. 阅读COMMA有关多模态协调的发现。设计一个简单的多模态协调任务，加入你的内部基准。什么信号可作为有用指标？  
5. 用基准声明核查清单评价一篇近期多智能体论文的主要结果。你会给出什么等级？
