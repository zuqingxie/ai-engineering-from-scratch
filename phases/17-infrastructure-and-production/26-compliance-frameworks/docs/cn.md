# 合规 — SOC 2、HIPAA、GDPR、PCI-DSS、欧盟AI法案、ISO 42001

> 多框架覆盖是2026年企业交易的基本要求。**欧盟AI法案**：自2024年8月1日起生效。大多数高风险要求自2026年8月2日起执行。高风险系统义务违反，罚款最高达1500万欧元或全球年营业额的3%（第99条第4款）；禁止的AI行为罚款最高达3500万欧元或7%（第99条第3款）。若服务欧盟用户，全球适用。**科罗拉多AI法案**：自2026年6月30日生效（经SB25B-004从2026年2月推迟）—要求高风险系统进行影响评估，有权对AI决策提出申诉。弗吉尼亚州类似，针对信贷/就业/住房/教育。**SOC 2 Type II**：事实上的B2B AI要求（金融科技领域需Type II而非Type I）。**GDPR**：最大已记录的AI专项罚款为对Clearview AI的3050万欧元（荷兰数据保护局，2024年9月）；意大利数据保护机构于2024年12月对OpenAI处以1500万欧元罚款（2026年3月上诉推翻）。推理时的实时个人身份信息（PII）去识别是可辩护的标准，事后清理不足以合规。**HIPAA**：医疗保健相关 — 未经商业关联协议（BAA）禁止将受保护健康信息（PHI）发送到外部AI服务。**PCI-DSS**：对涉及支付的AI交互层需配置加合同协议，而非自动合规。**ISO 42001**：新兴的AI治理标准，是与ISO 27001并行的采购要求。参照配置：OpenAI维护SOC 2 Type 2、ISO/IEC 27001:2022、ISO/IEC 27701:2019、GDPR/CCPA/HIPAA（BAA）/FERPA、ChatGPT支付组件的PCI-DSS。跨框架映射减少审计疲劳：访问控制在ISO 27001 A.5.15-5.18、GDPR 第32条、HIPAA §164.312(a)均有映射。

## 学习目标

- 列举与大语言模型（LLM）产品相关的七个2026年框架，并将其匹配到对应客户细分。
- 说明欧盟AI法案的执行时间表（2024年8月生效；高风险于2026年8月执行）以及两级罚款上限（高风险义务1500万欧元/3%，禁止行为3500万欧元/7%）。
- 解释为何事后处理PII清理不足以满足GDPR，指出实时推理层去识别为可辩护标准。
- 描述跨框架控制映射（例如，访问控制对应ISO 27001 A.5.15-5.18 + GDPR 第32条 + HIPAA §164.312(a)）。

## 问题

企业客户采购要求SOC 2 Type II、GDPR、HIPAA BAA、ISO 27001及“欧盟AI法案合规声明”。团队仅有SOC 2 Type I，距离Type II还有六个月，GDPR第30条记录尚未开始。

多框架覆盖不是LLM特有问题，是企业SaaS问题，带有LLM特有叠加。2026年采购团队希望得到以框架为行、控制项为列的矩阵，而非PDF文件。

## 概念

### 七个框架

| 框架 | 适用范围 | LLM特有要求 |
|-----------|-------|--------------------------|
| SOC 2 Type II | B2B SaaS 基线 | 6-12个月的过程控制审计 |
| HIPAA | 美国医疗保健 | 需BAA；未经协议不得将PHI传出基础设施 |
| GDPR | 欧盟用户 | 实时PII去识别；数据主体权利；第30条记录 |
| PCI-DSS | 支付数据 | 配置+合同要求涉及支付的AI |
| 欧盟AI法案 | 服务欧盟用户 | 风险分级；高风险系统需符合性评估、文档、日志 |
| 科罗拉多AI法案 | 服务科罗拉多居民 | 影响评估；申诉权 |
| ISO 42001 | AI治理 | 新兴，与ISO 27001配套 |

### 欧盟AI法案时间线

- 2024年8月1日：生效。
- 2025年2月2日：禁止AI行为强制执行。
- 2026年8月2日：高风险系统强制执行（符合性评估、文档、日志）。
- 2027年8月：根据统一立法覆盖产品的高风险系统。

风险等级：不可接受（禁用）、高风险（符合性+日志）、有限风险（透明度）、最小风险（无约束）。大多数B2B LLM SaaS为有限风险；高风险应用于就业、信贷、教育、执法、移民、关键服务领域。

罚款（第99条）：违反高风险系统义务最高处罚1500万欧元或全球年营业额3%（第99条第4款）；禁止AI行为罚款最高3500万欧元或7%（第99条第3款），取较高者。

### GDPR — 实时去识别为标准

事后清理（LLM接收后再去识别PII）不可辩护——模型已见数据。2026年标准是实时推理层去识别：

- 在LLM调用前进行实体识别。
- 采用一致分词（Mesh方法）保持语义。
- 仅存储去识别后的提示及用户同意的原始数据。

近期执法案例：Clearview AI被罚3050万欧元（荷兰数据保护局，2024年9月），为迄今最大AI专属GDPR罚款；OpenAI遭意大利数据保护机构罚款1500万欧元（2024年12月），为最大LLM专属罚款，2026年3月上诉推翻，判决仍在复审中。事后处理主张在审计中均未通过。

### HIPAA — BAA非可选项

未经签署商业关联协议，严禁将PHI发送至外部AI服务。三大超大规模云服务LLM平台（Bedrock、Azure OpenAI、Vertex）均提供BAA。OpenAI直连API提供BAA。Anthropic直连API提供BAA。发送PHI前务必确认BAA。

### SOC 2 Type II

Type I：控制设计并文档化。  
Type II：控制在6-12个月期间有效运行。

2026年B2B采购默认Type II。Type I为起步阶段，Type II为门槛。

常见审计驱动：访问日志（谁看了什么）、变更管理（如何部署）、风险评估（季度）、事件响应（是否测试）。第17阶段 · 25的审计日志可直接复用。

### 跨框架映射

单一访问控制策略满足多框架要求：

| 控制 | 框架 |
|---------|-----------|
| 访问日志 | ISO 27001 A.5.15-5.18、GDPR 第32条、HIPAA §164.312(a) |
| 变更管理 | ISO 27001 A.8.32，PCI DSS 要求6，HIPAA 违规通知范围 |
| 传输加密 | ISO 27001 A.8.24，GDPR 第32条，HIPAA §164.312(e) |
| 密钥管理 | ISO 27001 A.8.19，PCI DSS 要求8，SOC 2 CC6.1 |

合规工具（如Drata、Vanta、Secureframe）可自动化映射，大规模运营极具性价比。

### ISO 42001 — 新兴标准

2023年末发布。与ISO 27001配套的采购要求。AI治理框架，涵盖风险管理、数据质量、透明度、人类监督。

### OpenAI参考配置

OpenAI维持SOC 2 Type 2、ISO/IEC 27001:2022、ISO/IEC 27701:2019、GDPR/CCPA/HIPAA（BAA）/FERPA、ChatGPT支付组件的PCI-DSS，代表2026年企业合规基线。

### 你应记住的数据

- 欧盟AI法案罚款上限：1500万欧元/3%（高风险义务，第99条第4款）；3500万欧元/7%（禁止行为，第99条第3款）。
- 欧盟AI法案高风险执法时间：2026年8月2日。
- 最大记录AI专属GDPR罚款：Clearview AI 3050万欧元（荷兰DPA，2024年9月）。
- 最大LLM专属GDPR罚款：OpenAI 1500万欧元（意大利Garante，2024年12月；2026年3月上诉推翻）。
- SOC 2 Type II覆盖时间：6-12个月有效运行的控制。
- 科罗拉多AI法案生效时间：2026年6月30日（SB25B-004延迟自2026年2月）。

## 关键术语

| 术语 | 通常理解 | 实际含义 |
|------|----------------|------------------------|
| SOC 2 Type II | “受审控件” | 控件有效运行6-12个月，独立验证 |
| HIPAA BAA | “医疗合同” | 商业关联协议；PHI必需 |
| GDPR | “欧盟隐私法” | 实时PII去识别是2026年可辩护标准 |
| 欧盟AI法案 | “欧盟AI规则” | 高风险于2026年8月强制；罚款1500万欧元/3%（高风险义务）、3500万欧元/7%（禁止行为） |
| 科罗拉多AI法案 | “美国AI州法” | 2026年6月30日生效（SB25B-004延期）；影响评估要求 |
| ISO 42001 | “AI治理” | 新兴的AI风险与透明框架 |
| ISO 27001 | “安全信息管理体系（ISMS）” | 信息安全管理基线 |
| 符合性评估 | “欧盟AI文档包” | 高风险要求：文档、测试、日志 |
| 跨框架映射 | “一控多框” | 单一策略满足多框架控制 |
