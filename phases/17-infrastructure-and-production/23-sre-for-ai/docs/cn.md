# AI SRE — 多智能体故障响应、运行手册、预测检测

> AI SRE 使用以基础设施数据（日志、运行手册、服务拓扑）为基础的 LLM（大语言模型）通过 RAG（检索增强生成）自动化调查、文档编写和协调阶段。2026 年的架构模式是多智能体编排 — 专业化智能体（日志、指标、运行手册）由监督者协调；AI 提出假设和查询，人类审批判断。Datadog Bits AI 和 Azure SRE Agent 作为托管产品发布。运行手册在演进：NeuBird Hawkeye 使用对抗评估（两模型分析同一事件；一致=置信，不一致=不确定）；运维记忆在团队更替间持续。自动修复保持谨慎：AI 建议，人类审批。完全自动化操作范围窄（重启 pod，回滚特定部署），设有严格保护措施 — 任何宣传“设置后无需管控”的说法都是过度宣传。新兴前沿：事前预测。MIT 研究报告训练基于历史日志 + GPU 温度 + API 错误模式的 LLM 能提前 10-15 分钟预测 89% 故障。预测：2026 年底，95% 企业级 LLM 实现自动故障切换。

**类型：** 学习

**先决条件：** 第 17 阶段 · 13（可观测性）、第 17 阶段 · 24（混沌工程）

## 学习目标

- 绘制多智能体 AI SRE 架构图：监督者 + 专业智能体（日志、指标、运行手册） + 人类审批环节。
- 解释为何自动修复范围狭窄（重启 pod、回滚部署）而非广泛（重新设计服务）。
- 命名对抗评估模式（NeuBird Hawkeye）：两模型一致=置信，分歧=升级处理。
- 引用 MIT 的 89% 早期检测结果及运维约束：无执行的预测仅是仪表板。

## 问题描述

一名值班工程师凌晨 3 点接到告警：“结账模块高错误率。”他们查看 Datadog、Loki、三份运行手册和部署日志。30 分钟后发现根因是 vLLM 发生了 KV 缓存峰值导致的 OOM（内存溢出）。重启 pod 后，错误消除。

2026 年，这样调查的前 20 分钟可实现自动化。通过服务划分日志、与最近部署关联、匹配运行手册——均为 RAG + 工具使用。监督智能体可做首次分诊并提出假设，先于人类打开 Datadog。

完全自动修复是另一个问题。重启 pod，安全。扩展 GPU 池，政策允许则安全。重新设计服务，绝对不行。关键是划定狭窄界限。

## 概念解析

### 多智能体架构

```text
          事故
             │
             ▼
        监督者
        /    |    \
       ▼     ▼     ▼
  日志智能体  指标智能体  运行手册智能体
       │     │     │
       └─────┴─────┘
             │
             ▼
        假设 + 证据
             │
             ▼
        人类审批
             │
             ▼
        操作（狭义）
```

监督者将事故拆分为子查询。专业智能体可访问工具（日志搜索、PromQL、文档检索）。监督者整合后，将假设和证据呈现给人类。人类审批或重新指派。

### 自动修复范围

**安全（狭义）**：重启 pod、回滚特定部署、在预先批准范围内扩展池、启用预先批准的功能开关。

**不安全（广义）**：更改服务拓扑、修改资源限制、部署新代码、更改 IAM（身份和访问管理）、修改数据库。

任何宣传“设置后无需管控”都是过度宣传。随着 AI SRE 的成熟，安全集扩大，但界限确实存在。

### 对抗评估（NeuBird Hawkeye）

两个模型独立分析相同事件。若根因一致，置信度高；若不一致，呈报人类并展示两个假设。简单模式，有效过滤幻觉根因。

### 运维记忆

团队变动是传统 SRE 的隐形杀手 — 口传知识流失。AI SRE 将运行手册和事故复盘存入向量数据库；智能体每次新事故时检索。新工程师加入时，AI 拥有完整历史。

### 事前预测

MIT 2025 年研究：基于历史日志、GPU 温度和 API 错误模式训练的 LLM 可提前 10-15 分钟预测 89% 故障。

现实检验：无执行的预测仅是仪表板。实际问题是“预测后我们做什么？”是预排空？报警？自动扩缩？答案依政策而定。

### 2026 年产品

- **Datadog Bits AI** — Datadog 内托管的 SRE 助手。
- **Azure SRE Agent** — Azure 原生。
- **NeuBird Hawkeye** — 对抗评估 + 运维记忆。
- **PagerDuty AIOps** — 分诊 + 去重。
- **Incident.io Autopilot** — 事故指挥 + 协调。

### 运行手册即代码

运行手册由 Confluence 页面进化为带结构化章节（症状、假设、验证、操作）的版本化 Markdown。结构化运行手册驱动更优的 RAG 检索。任何 AI-SRE 试点均从将非结构化手册转为结构化开始。

### 你需要记住的数据

- MIT 早期检测：89% 故障，提前 10-15 分钟
- 多智能体分诊：监督者 +（日志、指标、运行手册）+ 人类
- 安全自动修复集：重启 pod、回滚部署、范围内扩展
- 对抗评估：两模型独立；一致=置信
