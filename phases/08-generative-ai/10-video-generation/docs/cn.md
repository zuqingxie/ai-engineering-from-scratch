# 视频生成

> 一张图像是二维张量。视频则是三维张量。理论相同，但计算量大10至100倍。OpenAI 的 Sora（2024年2月）证明了这是可能的。到了2026年，Veo 2、Kling 1.5、Runway Gen-3、Pika 2.0 和 WAN 2.2 都能够从文本生成1080p生产级视频 —— 开源权重的模型栈（CogVideoX、HunyuanVideo、Mochi-1、WAN 2.2）落后12个月。

**类型：** 构建  
**语言：** Python  
**先决条件：** 第8阶段 · 07（Latent Diffusion 潜在扩散）、第7阶段 · 09（ViT）、第8阶段 · 06（DDPM）  
**时间：** 约45分钟

## 问题描述

一个10秒钟的1080p视频，帧率24fps，是240帧，分辨率为1920×1080×3像素。每个剪辑的原始数据大约为1.5 GB。基于像素空间的扩散不可行。你需要：

1. **时空压缩。** 一个VAE（变分自编码器），对视频进行编码，而不是单帧，将其压缩为一系列时空块（patch）。
2. **时间连续性。** 帧之间需要共享内容、光照和对象身份，持续数秒。网络必须能够建模运动。
3. **计算预算。** 视频训练的计算成本比图像高10-100倍，且模型规模相同。
4. **条件输入。** 支持文本、图像（首帧）、音频或其他视频作为条件。大多数生产模型都支持这四种。

解决方案架构是应用于时空块的**Diffusion Transformer（DiT，扩散变换器）**，训练于超大规模的（提示、标题、视频）数据集上。其使用与第06课相同的扩散损失函数。

## 概念解析

![视频扩散：分块，DiT，解码](../assets/video-generation.svg)

### 分块 (Patchify)

用3D VAE编码视频（学习时空压缩）。潜变量形状为 `[T_latent, H_latent, W_latent, C_latent]`，切分为大小为 `[t_p, h_p, w_p]` 的块。对于Sora风格的模型，`t_p = 1`（每帧分块）或 `t_p = 2`（每两帧一块）。10秒1080p视频压缩后约得到20,000至100,000个块。

### 时空DiT

一个变换器处理平铺的块序列。每个块包含3D位置嵌入（时间 + y + x）。注意力一般因式分解为：

- **空间注意力，** 仅对单帧内的块做；
- **时间注意力，** 对同一空间位置跨帧块做；
- **完整3D注意力** 代价是16-100倍，仅在低分辨率或研究中使用。

### 文本条件输入

通过大型文本编码器T5-XXL实现跨注意力（Sora、CogVideoX-5B均采用）。长提示很重要——Sora的训练集包含了GPT生成的平均每个剪辑200tokens的密集重标注。

### 训练

在时空潜变量上进行标准扩散损失（ε或v预测）。数据来源：网络视频 + 约1亿条精选剪辑 + 合成文本标题。计算成本：小规模研究至少1万GPU小时；Sora级别则需10万+ GPU小时。

## 构建方法

`code/main.py` 模拟了核心时空DiT思想：将小型合成视频分块添加位置嵌入，并用变换器风格注意力对整序列进行去噪。纯Python实现，无numpy。显示即使在一维情况下，当邻近帧块共享去噪器和位置嵌入时，也出现时间连续性。

### 第1步：分块合成一维“视频”

```python
def make_video(T_frames=8, rng=None):
    # “视频”是一系列沿平滑轨迹变化的一维数值
    base = rng.gauss(0, 1)
    return [base + 0.3 * t + rng.gauss(0, 0.1) for t in range(T_frames)]
```

### 第2步：每帧位置嵌入

```python
def pos_embed(t, dim):
    return sinusoidal(t, dim)
```

### 第3步：去噪器处理整个序列

不是独立去噪每帧，而是将所有帧的值与其位置嵌入连接起来，联合预测所有帧的噪声。

### 第4步：时间连续性测试

训练后采样视频。测量帧间差异。若模型学到时间结构，差异将小于独立采样。

## 易犯错误

- **独立逐帧采样 = 闪烁。** 独立图像扩散对每帧采样导致噪声无关，因此输出闪烁。视频扩散通过注意力或共享噪声耦合修复。
- **天真的3D注意力 = 内存溢出。** 10秒1080p潜变量全3D注意力需数千亿次运算。需拆分为空间+时间注意力。
- **数据标题比模型规模更重要。** Sora主要升级点是训练时使用了约10倍精细的标题（GPT-4重标注剪辑）。OpenAI技术报告明确说明。
- **首帧条件。** 大多数生产模型支持以图像作为第一帧输入。这是“图像到视频”模式，训练时包含这一变种。
- **物理漂移。** 长剪辑（>10秒）容易累积细微不一致。滑动窗口生成和关键帧锚定能够缓解。

## 练习

1. **简单。** 在 `code/main.py` 中，比较（a）独立逐帧采样和（b）联合序列采样的帧间差异，报告均值和方差。
2. **中等。** 添加首帧条件：固定第0帧为给定值，采样剩余帧。测量固定值的传播效果。
3. **困难。** 使用HuggingFace diffusers，在本地GPU运行CogVideoX-2B。对720p、6秒剪辑进行20步推理计时。分析时空注意力并定位瓶颈。

## 关键术语

| 术语 | 常见说法 | 实际含义 |
|------|-----------------|-----------------------|
| 视频VAE | “3D VAE” | 编码器将 `(T, H, W, C)` 压缩为时空潜变量。 |
| 块（Patches） | “tokens” | 潜变量的固定大小3D块，DiT输入。 |
| 分解注意力 | “空间+时间” | 先对空间做注意力，再对时间做；跳过完整3D注意力。 |
| 图像到视频 (I2V) | “给图片做动画” | 模型输入图像+文本，输出从该图像开始的视频。 |
| 关键帧条件 | “锚定帧” | 固定某些帧以控制视频轨迹。 |
| 运动画笔 | “方向提示” | 用户界面输入，在图像上绘制运动矢量。 |
| 重标注标题 | “密集标题” | 使用大型语言模型重新标注训练剪辑详细提示。 |
| 闪烁 | “时间伪影” | 帧间不连续；通过耦合去噪修正。 |

## 生产注释：视频潜变量是内存带宽瓶颈

10秒1080p 24fps视频为240帧 × 1920 × 1080 × 3 ≈ 1.5GB原始像素。经过4倍视频VAE压缩（2×空间 × 2×时间）后，每个请求的数据量约为100MB。用时空DiT进行30步、batch=1时，每步必须传输约3GB数据到HBM —— 内存带宽而非浮点计算是瓶颈。

三个生产调节参数，均来自推理文献：

- **DiT张量并行（TP）。** 文本到视频模型常 ≥100亿参数。4个H100 GPU上的TP=4是常规；大型模型还会混合流水线并行（PP）和TP。每步延迟近似与TP成线性反比，直到all-reduce瓶颈。
- **帧批量处理 = 连续批处理。** 生成时，视频是由注意力关联的帧批组成。可“连贯批处理”(in-flight scheduling) —— 如果模型架构支持滑动窗口生成，可在第`t-1`帧返回时启动第`t+1`帧渲染。
- **剪辑级预计算缓存。** 图像到视频模式下，首帧条件相当于LLM的提示预填充：计算一次，整个时间解码过程复用。即视频中的KV缓存。
