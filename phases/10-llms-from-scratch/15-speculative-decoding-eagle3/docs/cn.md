## 问题描述

对 70B 模型的自回归解码在 H100 上大约 35 tokens/秒，GPU 并未饱和。瓶颈是内存带宽：每个 token 需要从 HBM 载入 70B 权重，做一步算术，产生一个浮点数，计算单元大部分时间空闲。

推测解码将其转化为一个实际能解决的吞吐量问题。一个廉价草稿生成 `N` 个 token，分别做 `N` 次小规模前向。验证器一次前向计算整个前缀加上 `N` 个草稿 token，如果在第 `i` 个位置验证分布 `q_i` 和草稿分布 `p_i` 一致（统计意义上），则接受；否则拒绝并从残差分布采样纠正。一次大模型前向最多产生 `N+1` 个接受 token。

关键定理是 Leviathan、Kalman、Matias（ICML 2023）：输出分布与直接从验证器采样分布完全相同。不是近似，是完全一致。这也是推测解码能放心上生产环境的根本——纯粹的延迟优化，无质量折中。

第7阶段 · 第16课给你了数学证明，本课给你训练栈视角。好的草稿比简易草稿带来约 2 倍加速。EAGLE、EAGLE-2、EAGLE-3（Li 等，2024–2025）将“草稿=较小同款模型”变成精密工程技术。2026 生产推理服默认启用 EAGLE-3。

## 概念

### 不变量：Leviathan 拒绝采样

设 `p(t)` 是草稿在给定前缀下的下一个 token 分布，`q(t)` 是验证器分布。先从 `p` 中采样草稿 token `d ~ p`。以概率 `min(1, q(d)/p(d))` 接受，否则从残差分布 `(q-p)_+ / ||(q-p)_+||_1` 采样。所得样本服从分布 `q`。这无关 `p` 有多差——`p` 越差，拒绝次数越多，但输出始终精确。

对 `N` 个位置堆叠此采样过程，单次验证器前向计算 `prefix + d_1 + ... + d_N` 的分布 `q_1, q_2, ..., q_{N+1}`。从左到右，当第 `j` 个位置首次拒绝时，从残差中采样纠正并停止。全部接受时，从 `q_{N+1}` 采样额外 token。

### 决定加速的因素

令 `α` 是草稿每个 token 的期望接受率，`c = cost(draft) / cost(verifier)` 是成本比。期望每次验证器前向接受 token 数为：

```text
E[accepted] = (1 - α^(N+1)) / (1 - α)
```

每接受 token 的期望总耗时为 `(N * c + 1) / E[accepted]`。对 `N` 最小化此值即最佳。举例：对于 `α = 0.8, c = 0.05`，最佳 `N` 约 5–7，加速约 3.2×。对于 `α = 0.95, c = 0.02`，最佳 `N` 约 8–10，加速推至 5×。

最大杠杆是 `α`。令 `N=5` 固定，`α` 从 0.6（基础草稿）提升到 0.9（EAGLE-3），每次验证器前向接受 token 数由 2.2 增至 4.1，几乎加倍吞吐。

### 两年进展历程

**基础推测（Leviathan，2023）：** 草稿是家族中另一个独立训练的小模型。实现简单，`α ≈ 0.6`，加速顶多约 2×。

**EAGLE-1（Li 等，2024）：** 草稿为轻量 transformer，通常 1-2 层，直接输入验证器最后一层隐藏状态，预测下 token。由于草稿可使用验证器特征，分布更接近验证器，`α` 提升至 0.7–0.8。

**EAGLE-2（Li 等，2024）：** 增加动态草稿树：不再生成单一长度为 `N` 的序列，生成候选的小树结构，单次验证器前向得分（树形注意力），选最高概率路径，草稿长度自适应步长。接受路径 token 的 `α` 超过 0.85。

**EAGLE-3（Li 等，2025，NeurIPS）：** 两项改进。首先，完全摒弃特征预测损失 —— EAGLE-1/2 用来训练草稿匹配 verifier 隐状态，限制了数据带来的提升。EAGLE-3 直接基于 token 预测训练。其次，训练时测试（TTT）：训练时将草稿自身先前预测多步反馈作为输入，使训练和推理分布一致，防止误差积累。测得聊天加速达 6.5×，H100 上 SGLang 批量 64 吞吐提升 38%。

### KV 缓存回滚

验证器前向一次扩展 KV 缓存 `N` 条目。若第 `j` 位置拒绝，则 `j-1` 后的缓存无效。一种实现方案是写入缓存区，接受时提交（vLLM、TensorRT-LLM）；另一方案是实际缓存加逻辑长度，拒绝时截断。回滚成本是每层每头的字节数，相较前向成本可忽略不计。

EAGLE-2 的树搜索中，验证器用非因果掩码支持树形拓扑注意力。工程复杂，但本质仍是带自定义掩码的 flash-attention 调用。

## 构建步骤

详见 `code/main.py`。这是完整 Leviathan 推测循环实现，包括：长度为 N 的草稿、验证器并行前向、逐位置拒绝、残差采样、额外 token 输出、KV 回滚，以及经验验证输出分布匹配 `q` 直接采样。

### 步骤1：拒绝规则

```python
def accept(q_prob, p_prob, u):
    if p_prob <= 0:
        return True
    return u < min(1.0, q_prob / p_prob)
```

### 步骤2：残差分布

```python
def residual(q, p):
    raw = [max(0.0, qi - pi) for qi, pi in zip(q, p)]
    s = sum(raw)
    if s == 0:
        return list(q)
    return [r / s for r in raw]
```

### 步骤3：完整推测步骤

`spec_step` 函数先从 `p` 草稿生成 `N` 个 token，然后一次计算验证器的 `q` 分布。对每个草稿 token 应用拒绝规则，首次拒绝时从残差分布采样纠正。若全部接受，从 `q_{N+1}` 输出额外 token。

### 步骤4：KV 回滚管理

模拟器跟踪每个工作线程的逻辑 `kv_length`。接受 `k` 个草稿时，`kv_length += k`。第 `j` 位置拒绝时，缓存已写过该位置之后，逻辑长度设置为 `prefix_length + j + 1`（即纠正 token 后一个位置）。后续读取会被截断到此逻辑长度。

### 步骤5：Leviathan 检查

运行 50,000 次推测步骤。统计接受 token 的经验分布。和 50,000 次直接 `q` 采样的分布对比。卡方统计应远低于临界值。理论得以实际验证。

### 步骤6：α 对加速的影响

通过在不同幅度下扰动 `p` 使其偏离 `q`，测量 `α`。绘制 `α` 和 `N` 对每次验证器调用预期 token 数的关系。代码打印表格展示 EAGLE-3 级别的草稿质量（`α ≈ 0.9`）如何带来约 4-5 个 token 每验证器调用。

## 使用方法

生产级 `vllm serve` 结合 EAGLE-3：

```bash
vllm serve meta-llama/Llama-3.3-70B-Instruct \
  --speculative-config '{
    "model": "yuhuili/EAGLE3-LLaMA3.3-Instruct-70B",
    "num_speculative_tokens": 5,
    "method": "eagle3"
  }'
```

SGLang 在 H100 批量大小 64 时用 EAGLE-3，加速约为基础批处理 64 的 1.38 倍，符合 EAGLE-3 论文。

使用推测解码的时机：

- 任何交互聊天场景，p50 延迟比峰值吞吐重要。
- 代码生成及结构化输出（JSON、SQL），因目标分布高度可预测，`α > 0.9`。
- 长文本生成（数千 token），摊销加速效果显著。

不适用情况：

- 极小模型（< 3B），草稿成本无明显优势。
- 极小批量单例 CPU 部署，草稿模型内存开销不划算。
- 非常高温度创意采样，导致 `α` 崩塌。

## 关键词

| 术语 | 人们的说法 | 实际含义 |
|-------|--------------|------------|
| Leviathan 规则 | "min(1, q over p)" | 以概率 `min(1, q(d)/p(d))` 进行的伯努利接受/拒绝，拒绝时从残差分布采样，精确保留 verifier 分布 |
| 残差分布 | "(q minus p) plus, normalized" | `(q - p)_+` 截断为零并重新归一化——拒绝时应从中采样的正确分布 |
| 接受率 α | "draft 正确的频率" | 拒绝规则下，每个令牌伯努利成功概率的期望；控制所有加速数学 |
| EAGLE-1 | "隐藏状态 draft" | 小型 transformer draft，以 verifier 最后一层隐藏状态为条件（Li 等，2024） |
| EAGLE-2 | "动态 draft 树" | EAGLE-1 加上通过树注意力对候选续写形成的树结构，单次 verifier 评估 |
| EAGLE-3 | "训练时测试" | 去除特征预测损失，训练时令 draft 使用自身输出进行直接令牌预测 |
| 训练时测试（TTT） | "暴露偏差修复" | 训练时自回归运行 draft，使训练与测试的输入分布匹配——计划采样的直接对应 |
| KV 回滚 | "撤销被拒绝的 draft" | 维护记录，拒绝时将 verifier 的 KV 缓存复位到接受前缀长度 |
| 奖励令牌 | "免费的那个" | 当所有 `N` 个 draft 均接受时，从 `q_{N+1}` 再采样一个，且不增加 verifier 代价 |
| 树注意力 | "同时验证多个候选" | 带有非因果掩码的注意力，尊重 draft 树的拓扑结构；在一次前向传递中计算所有树节点的 `q_i` |
