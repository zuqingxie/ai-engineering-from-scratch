# 技能库与终身学习（Voyager）

> Voyager（Wang 等，TMLR 2024）将可执行代码视为一种技能。技能具有命名、可检索、可组合，并通过环境反馈迭代优化。这是 Claude Agent SDK 技能、skillkit 以及 2026 技能库模式的参考架构。

**类型：** 构建  
**语言：** Python（stdlib）  
**前置条件：** 第14阶段 · 07（MemGPT），第14阶段 · 08（Letta Blocks）  
**时间：** ~75 分钟

## 学习目标

- 说出 Voyager 的三个组成部分——自动课程、技能库、迭代提示——及其各自作用。  
- 解释为何 Voyager 将动作空间定义为代码，而非原始命令。  
- 实现一个带有注册、检索、组合和基于失败的迭代优化的 stdlib 技能库。  
- 将 Voyager 模式映射到 2026 Claude Agent SDK 技能和 skillkit 生态系统。

## 问题

在每个会话中都重新构建所有功能的智能体存在三个问题：

1. **浪费令牌。** 每项任务都重复进行相同的推理。  
2. **进度丢失。** 会话A中学到的纠正不会传递到会话B。  
3. **长远组合失败。** 复杂任务需要层级能力；一次性提示无法表达。

Voyager 的解决方案是：将每个可复用能力视为命名的代码块，存储于库中，支持相似度检索，可与其他技能组合，并通过执行反馈迭代优化。

## 概念

### 三个组成部分

Voyager（arXiv:2305.16291）构建代理核心包括：

1. **自动课程。** 基于智能体当前技能和环境状态，由好奇心驱动的任务生成器挑选下一个任务。探索方式为自下而上。  
2. **技能库。** 每个技能都是可执行代码。成功完成任务后新增技能。通过任务描述的相似度进行检索。  
3. **迭代提示机制。** 失败时，智能体获取执行错误、环境反馈及自我验证输出，然后对技能进行迭代优化。

Minecraft 评估（Wang 等，2024）：相比基线，产生了 3.3 倍独特物品，石制工具速度快 8.5 倍，铁制工具速度快 6.4 倍，地图探索时间长 2.3 倍。数字虽针对 Minecraft，但模式可推广。

### 动作空间 = 代码

大多数智能体发出原始命令。Voyager 发出 JavaScript 函数。一个技能示例：

```javascript
async function craftIronPickaxe(bot) {
  await mineIron(bot, 3);
  await mineStick(bot, 2);
  await placeCraftingTable(bot);
  await craft(bot, 'iron_pickaxe');
}
```

由子技能组合而成。以描述和嵌入为键存储。检索时以程序形式获取，而非提示文本。

这就是 2026 Claude Agent SDK 技能：命名的、可检索的代码块与说明，智能体按需加载。

### 技能检索

新任务“制作钻石镐”。智能体流程：

1. 对任务描述进行嵌入。  
2. 在技能库中检索前 k 个最相似技能。  
3. 获取 `craftIronPickaxe`、`mineDiamond`、`placeCraftingTable` 等技能。  
4. 以检索到的子技能及新逻辑组合新技能。

此为 MCP 资源（第13阶段）和 Agent SDK 技能实现的模式：在知识/代码表面上针对当前任务进行检索。

### 迭代优化

Voyager 的反馈循环：

1. 智能体编写技能。  
2. 运行技能并与环境交互。  
3. 返回三种信号之一：`success`，`error`（含堆栈信息），`self-verification failure`。  
4. 智能体以上述信号为上下文重写技能。  
5. 循环直至成功或达到最大重试次数。

这是 Self-Refine（第05课）应用于代码生成的环境验真机制。CRITIC（第05课）则是同样模式，但用外部工具作为验证器。

### 课程与探索

Voyager 的课程模块根据智能体已有技能和未完成任务，提出诸如“在湖边建造避难所”之类的任务。任务生成器基于环境状态和技能库存，选出刚超出当前能力的任务，即探索的黄金区间。

对生产环境智能体而言，可转化为“缺失什么”操作符：根据当前技能库和领域，找出尚未覆盖的技能。团队通常通过课程评审手动实现。

### 该模式的不足

- **技能库腐蚀。** 同一技能由略微不同的描述重复添加十次。应在写入时去重；检索时只返回一个。  
- **组合技能漂移。** 父技能依赖被优化过的子技能。技能应版本管理；父技能固定在 v1 时不会自动切换到 v3。  
- **检索质量下降。** 技能描述的向量检索库超过数百条时效果下降。可辅以标签过滤和硬约束（如“仅支持 `category=tooling`”技能）。

## 构建它

`code/main.py` 实现了 stdlib 技能库：

- `Skill` — 名称、描述、代码字符串、版本、标签、依赖。  
- `SkillLibrary` — 注册，搜索（基于 token 重叠），组合（依赖的拓扑排序），和迭代优化（更新时版本递增）。  
- 一个脚本化代理，注册三个原始技能，组合成第四个技能，遇到失败后进行优化。

运行：

```text
python3 code/main.py
```

输出显示库写入、检索、组合、执行失败，及 v2 优化——Voyager 的完整循环。

## 使用它

- **Claude Agent SDK 技能**（Anthropic） — 2026 年参考标准：每个技能含描述、代码和说明，代理会话中按需加载。  
- **skillkit**（npm: skillkit） — 支持 32+ AI 编程代理的跨代理技能管理。  
- **定制技能库** — 领域专用（数据代理的 SQL 技能，基础设施代理的 Terraform 技能）。Voyager 模式可向下扩展。  
- **OpenAI Agents SDK `tools`** — 轻量级技能的基础形态。

## 发布它

`outputs/skill-skill-library.md` 生成符合 Voyager 结构的技能库，集成注册、检索、版本管理和优化，支持任意目标运行时。

## 练习

1. 为 `compose()` 添加依赖环检测。若技能 A 依赖 B，而 B 又依赖 A，会发生何种情况？报错还是警告？  
2. 实现每个技能的版本固定。若父技能组合了子技能 `crafting@1`，而 `crafting` 升级到 `@2`，父技能不应自动升级。  
3. 将基于 token 重叠的检索替换为 sentence-transformers 嵌入（或 BM25 stdlib 实现），评估 50 条技能的小型库的检索@5 召回率。  
4. 添加“课程”智能体：根据当前库和领域描述，提出 5 个缺失技能。每周运行一次。  
5. 阅读 Anthropic 的 Claude Agent SDK 技能文档。将示例库移植到 SDK 的技能架构下。技能发现性有什么变化？

## 关键术语

| 术语 | 人们说 | 实际含义 |
|------|--------|----------|
| Skill（技能） | “可复用能力” | 命名的代码块+描述，基于相似度可检索 |
| Skill library（技能库） | “智能体的操作记忆” | 持久存储技能，可搜索并可组合 |
| Curriculum（课程） | “任务生成器” | 自下而上的目标生成，基于当前能力差距 |
| Composition（组合） | “技能有向无环图” | 技能调用技能；执行时通过拓扑排序 |
| Iterative refinement（迭代优化） | “自我校正循环” | 环境反馈+错误+自我验证折叠入下一版本 |
| Action-space-as-code（动作空间作为代码） | “程序化动作” | 输出函数而非原始命令，实现时序延展行为 |
| Dedup on write（写时去重） | “技能折叠” | 近似重复描述折叠为一个规范技能 |
