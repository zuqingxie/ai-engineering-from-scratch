# 使用 HTN 和进化搜索进行规划

> 符号规划（symbolic planning）处理可证明正确的计划情况。进化代码搜索（evolutionary code search）处理适合机器评估的适应度函数。ChatHTN （2025）和 AlphaEvolve （2025）展示了各自与大型语言模型（LLM）配合时的能力解锁。

**类型：** 构建  
**语言：** Python（标准库）  
**先决条件：** 第14阶段 · 02课（ReWOO 和 Plan-and-Execute）  
**耗时：** ~75分钟

## 学习目标

- 解释层次任务网络（Hierarchical Task Networks）中的任务、方法、操作符、前置条件和效应。
- 描述 ChatHTN 的混合循环 —— 符号搜索结合 LLM 的备用分解。
- 解释 AlphaEvolve 的进化循环及其为何仅适用于程序化评估器。
- 在 Python 标准库中实现一个玩具 HTN 规划器和一个玩具进化搜索。

## 问题描述

ReWOO（第02课）、Plan-and-Execute 和 ReAct 覆盖了大多数智能体规划场景，但有两种情况处理不足：

1. **具有可证明正确性的计划。** 如调度、飞行航线、合规工作流 —— 计划必须从构造上确保正确。偶尔出现幻觉步骤的流畅 LLM 计划不可接受。
2. **具有机器可校验适应度函数的优化。** 如矩阵乘法、调度启发式、编译器传递 —— 目标不是“正确的计划”，而是“最优计划”。

层次任务网络（HTN）规划和 AlphaEvolve 分别解决这两类不同问题。两者都将 LLM 视作放大器，而非替代品。

## 概念介绍

### 层次任务网络（HTN）

HTN 包含：

- **任务** — 复合任务（需分解）和原始任务（可直接执行）。
- **方法** — 将复合任务分解成子任务的方式，带有前置条件。
- **操作符** — 具有前置条件和效应的原始动作。
- **状态** — 一组事实集。

规划问题：给定目标任务和初始状态，寻找一系列满足前置条件的原始操作符序列。

HTN 早于 LLM，是可证明正确计划的经典方案。

### ChatHTN（Gopalakrishnan 等，2025年）

ChatHTN（arXiv:2505.11814）交错执行符号 HTN 和 LLM 查询：

1. 尝试用已有方法分解当前复合任务。
2. 若无方法适用，询问 LLM：“在状态 `s` 下你如何分解 `task`？”
3. 将 LLM 响应翻译为候选子任务。
4. 根据操作符规范验证，拒绝无效分解。
5. 递归执行。

论文核心论断：所有生成计划均可证明正确，因为 LLM 仅作为候选分解来源，决不直接编辑计划。符号层负责正确性，LLM 负责扩充方法库。

在线方法学习（OpenReview `gwYEDY9j2x`，2025年后续）添加了能够通过回归泛化 LLM 产生分解的学习器，最多减少 75% 的 LLM 查询。

### AlphaEvolve（Novikov 等，2025年）

AlphaEvolve（arXiv:2506.13131，DeepMind，2025年6月）是另一种体系：由 Gemini 2.0 Flash/Pro 组合体操控的进化代码搜索。

循环流程：

1. 以种子程序加程序化评估器（返回适应度分数）开始。
2. LLM 组合体提出变异。
3. 通过评估器运行变异。
4. 保留最优解，继续变异。

已发布成果：

- 56年来首次改进 Strassen 算法完成 4x4 复数矩阵乘法（48次标量乘法）。
- Borg 调度启发式恢复谷歌计算资源 0.7%。
- 对前沿工作负载实现 32% FlashAttention 加速。

硬性要求：适应度函数必须机器可检验。对自然语言答案的进化搜索无法收敛。

### 何时选择哪种方法

| 问题类别                 | 使用方案      | 理由                      |
|------------------------|------------|-------------------------|
| 带硬约束的调度           | HTN + ChatHTN | 可证明的正确性               |
| 编译器优化               | AlphaEvolve | 机器可校验的适应度函数          |
| 多步任务执行             | ReAct / ReWOO | 结合 LLM，缺乏形式保证         |
| 以测试为标准的代码改进    | AlphaEvolve | 测试用例即评估器              |
| 策略约束的自动化         | HTN         | 通过前置条件编码策略             |

### 该模式的局限

- **无操作符的 HTN。** 缺少前置条件/效应规范，正确性声明不成立。ChatHTN 中“LLM 建议分解”需要依靠规范拒绝无效操作。
- **AlphaEvolve 无真实评估器。** “问 LLM 代码是否更优”不是适应度函数。评估器必须确定且高效。
- **过度设计。** 多数智能体任务不需要这两者，应优先尝试 ReAct 或 ReWOO。

## 实践构建

`code/main.py` 实现了两个玩具：

- 一个 Python 标准库 HTN 规划器，包含操作符、方法、前置条件、效应及一个 `LLMFallback`，当无方法匹配复合任务时启动备用 LLM。这里的“LLM”是脚本化分解器，支持离线运行。
- 一个标准库进化搜索，用于算术表达式：生成最小化 `|f(x)-target|` 的表达式，评估器确定性。

运行命令：

```bash
python3 code/main.py
```

输出轨迹展示 HTN 规划器分解复合任务（途中切换到 LLM 备用）以及进化循环收敛到目标表达式。

## 使用建议

- **HTN 规划器** — 使用 `pyhop`、`SHOP3` ，或自行构建以强化领域特定策略。
- **ChatHTN** — 研究代码；此模式（符号＋LLM 备用）可以无缝移植到任何 HTN 规划器。
- **AlphaEvolve** — DeepMind 论文；此模式（组合体＋评估器）可复现。OpenEvolve 及类似开源版本正在涌现。
- **智能体框架** — 尚无自带 HTN 或 AlphaEvolve 的主流框架。可将其构建成子智能体或后台工作线程。

## 部署

`outputs/skill-hybrid-planner.md` 生成混合规划器脚手架（HTN 或进化型），并明确 LLM 角色边界。

## 练习题

1. 为 HTN 规划器添加回溯：当操作符的后置条件运行时失败，回滚重试下一方法。
2. 为 ChatHTN 增加 LLM 方法缓存：当 LLM 分解任务 `T` 于状态模式 `P`，存储结果。下一次调用先检查方法库。
3. 将进化搜索评估器换成真实测试集。使其进化出满足20个测试用例的排序函数；报告收敛所需代数。
4. 阅读 AlphaEvolve 的评估器设计笔记。设计适合你关心领域的评估器（SQL 查询优化、测试集最小化、部署 YAML）。
5. 结合使用：用 HTN 分解复杂任务成子任务，再用进化搜索优化每个子任务的原始操作符。评估优点与过度设计的边界。

## 关键词汇

| 术语            | 常见说法          | 实际含义                           |
|----------------|----------------|----------------------------------|
| HTN            | “层次规划器”      | 带操作符、前置条件和效应的任务分解         |
| 方法           | “分解规则”        | 将复合任务分解为子任务的方案                |
| 操作符          | “原始动作”        | 具体带前置条件及效应的步骤                   |
| ChatHTN        | “LLM + HTN”      | 无方法匹配时符号规划询问 LLM               |
| AlphaEvolve    | “进化代码搜索”     | LLM 组合体变异代码，确定评估器筛选             |
| 适应度函数       | “评估器”          | 确定性、机器可检验的输出得分                 |
| 在线方法学习     | “缓存 LLM 分解”    | 存储并泛化 LLM 计划，减少查询成本             |
