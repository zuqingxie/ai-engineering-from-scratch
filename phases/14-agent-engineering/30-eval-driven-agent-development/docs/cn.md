# 基于评估驱动的代理开发

> Anthropic 的指导原则：“从简单的提示开始，利用全面评估进行优化，仅在必要时添加多步骤的代理系统。”评估不是最后一步，而是驱动第14阶段中所有其他选择的外循环。

**类型：** 学习 + 实践  
**语言：** Python（标准库）  
**先决条件：** 完成第14阶段全部内容。  
**时长：** 约60分钟

## 学习目标

- 说出三层评估——静态基准测试、自定义离线评估、在线生产评估——及其用途。  
- 解释评估器-优化器紧耦合循环。  
- 描述2026年最佳实践：评估与代码共存，在CI中运行，作为PR门槛。  
- 关联第14阶段每节课与其生成的评估用例。

## 问题所在

代理能通过演示测试，但在生产环境中失败，这些失败方式是演示无法预测的。基准测试回答的是“该模型是否具备广泛能力？”，而不是“该代理是否为我的产品提供了正确的补丁？”答案是：三个层面的评估，持续运行，每项防护措施和学习规则都映射到一个评估用例。

## 概念说明

### 三层评估

1. **静态基准测试（Static benchmarks）** — SWE-bench Verified (Lesson 19) 用于代码，WebArena/OSWorld (Lesson 20) 用于浏览/桌面环境，GAIA (Lesson 19) 用于通用任务，BFCL V4 (Lesson 06) 用于工具使用。用于跨模型比较和回归门控。污染问题存在：SWE-bench+ 发现32.67%的解决方案泄露。始终报告 Verified / +-审核过的分数。

2. **自定义离线评估（Custom offline evals）** — 根据产品形态设计：  
   - 以LLM为裁判（Langfuse、Phoenix、Opik — Lesson 24）。  
   - 基于执行（运行补丁，检查测试）。  
   - 基于轨迹（比较动作序列与黄金标准；OSWorld-Human显示顶级代理比黄金标准多1.4-2.7倍效率）。

3. **在线评估（Online evals）** — 生产环境：  
   - 会话重播（Langfuse）。  
   - 防护警报触发（Lesson 16，21）。  
   - 每步成本/延迟跟踪（Lesson 23 OTel 调用片段）。

### 评估器-优化器循环（Anthropic）

紧耦合的流程：

1. 提议者生成输出。  
2. 评估者判定。  
3. 反复调整直至评估者通过。

这是 Self-Refine（Lesson 05）的推广版。任何关注的代理流程都可以用评估器-优化器包装，提升可靠性。

### 2026年最佳实践

- 评估与代码共存。  
- 每次PR都在CI中运行。  
- 以评估分数为合并门槛（例如“与主分支相比无超过5%的回归”）。  
- 每个防护措施对应一个评估用例。  
- 每个学习规则（Reflexion、专业工作流学习规则）对应一个失败用例。

### 评估驱动开发常见失败点

- **缺少基线。** 没有最后已知良好状态，评估数据无法解读。务必存储基线。  
- **无实证的LLM裁判。** 裁判也会幻觉。CRITIC模式（Lesson 05）——裁判通过外部工具落地。  
- **对评估的过拟合。** 优化评估导致产品实际效用偏离。轮换评估用例。  
- **评估不稳定。** 非确定性用例引发误报。固定随机种子，快照状态。

## 实践步骤

`code/main.py` 是标准库的评估框架：

- 用例注册，含分类（基准、自定义、在线）。  
- 一个受测代理。  
- 评估器-优化器循环：提议、判定、反复直到通过或最大轮数。  
- CI 门控：通过率汇总+与基线比较的回归检测。

运行：

```text
python3 code/main.py
```

输出：每个用例的通过/失败，回归标志，CI门控判决。

## 使用方法

- 在与代理代码相同的仓库内编写评估用例。  
- 在每次PR通过CI运行。  
- 回归时构建失败。  
- 跟踪通过率随时间变化。  
- 将每次生产失败映射到新用例。

## 交付成果

`outputs/skill-eval-suite.md` 构建了具备CI门控和回归跟踪的三层评估套件，用于代理产品。

## 练习

1. 选取一个生产失败，写一个能复现它的评估用例。你的代理现在能通过吗？  
2. 为你的领域构建一个三维度的LLM裁判评分表（事实性、语气、范围），对50个会话评分。  
3. 将评估套件接入CI，回归≥5%时构建失败。  
4. 添加轨迹效率指标：代理实际执行步数与黄金轨迹步数之比。  
5. 将第14阶段所有课程映射到你的评估套件用例中，缺失的地方补全。

## 关键术语

| 术语 | 常用说法 | 实际含义 |
|------|----------|----------|
| 静态基准测试 | “现成评估” | SWE-bench、GAIA、AgentBench、WebArena、OSWorld |
| 自定义离线评估 | “领域评估” | 基于LLM裁判／执行／轨迹，针对你的产品形态 |
| 在线评估 | “生产评估” | 会话重播、防护警报、成本/延迟跟踪 |
| 评估器-优化器 | “提议-判定-反复” | 反复进行直到评审通过 |
| CI门控 | “合并阻断” | 如果评估出现回归则失败构建 |
| 基线 | “最后已知良好状态” | 参考分数，用于检测回归 |
| 轨迹效率 | “步骤对黄金轨迹比例” | 代理执行步数除以人类专家最短步数 |
