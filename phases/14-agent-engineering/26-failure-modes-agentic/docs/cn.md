# 失败模式：为什么代理会崩溃

> MASFT（伯克利，2025）将14种多代理失败模式归为3类。微软的分类法记录了现有AI失败在代理环境下如何放大。行业实地数据汇聚成五种常见模式：幻觉行为、范围蔓延、级联错误、上下文丢失、工具误用。

**类型：** 学习 + 构建  
**语言：** Python（标准库）  
**前置知识：** 阶段14·05（自我优化和CRITIC）、阶段14·24（可观测性）  
**时长：** 约60分钟

## 学习目标

- 说出MASFT的三大失败类别及每类中至少四个具体模式。  
- 解释为何代理失败会放大现有AI失败模式（偏差、幻觉）。  
- 描述五种工业中反复出现的失败模式及其缓解措施。  
- 实现一个标准库检测器，为代理执行轨迹标注失败模式标签。

## 问题

团队发布的代理在90%的轨迹上表现正常。那10%的失败不是随机噪声——它们归属于少数反复出现的类别。一旦能准确命名这些类别，就能监控它们并加以修复。

## 概念

### MASFT（伯克利，arXiv:2503.13657）

Multi-Agent System Failure Taxonomy（多代理系统失败分类法）。14种失败模式分成3类。评审员一致性（Cohen's Kappa）为0.88——类别区分度高且可靠。

核心观点：失败是多代理系统的根本设计缺陷，而非限于基础大语言模型（LLM）需要优化的限制。

### 微软代理化AI系统失败模式分类法

- 现有AI失败（偏差、幻觉、数据泄露）在代理环境下被放大。  
- 新失败因自主性产生：大规模的意外操作、工具误用、任务漂移。  
- 白皮书是代理产品的风险登记簿。

### 代理化AI中的故障特性（arXiv:2603.06847）

- 失败源自编排、内部状态演变及环境交互。  
- 不仅仅是“坏代码”或“坏模型输出”。

### LLM代理幻觉调查（arXiv:2509.18970）

两种主要表现：

1. **指令遵循偏差**——代理未遵循系统提示。  
2. **长距离上下文误用**——代理遗忘或错误应用早期回合的上下文。

子意图错误：省略（遗漏步骤）、冗余（重复步骤）、次序错乱（步骤出错顺序）。

### 五种行业反复出现的模式

Arize、Galileo、NimbleBrain 2024-2026年的实地分析发现：

1. **幻觉行为。** 代理调用不存在的工具或伪造参数。  
2. **范围蔓延。** 代理扩展任务范围，超出用户要求（创建额外PR、发送额外邮件）。  
3. **级联错误。** 一次错误调用触发后续连锁反应。一个虚假SKU幻觉导致四次API调用——多系统故障。  
4. **上下文丢失。** 长周期任务遗忘早前回合的限制条件。  
5. **工具误用。** 用错误参数调用正确工具，或调用错误工具。

级联错误最要命。代理无法区分“我失败了”和“任务不可能完成”，经常在400错误上幻觉成功消息以结束流程。

### 缓解方案：每步设门控

在推理链每一步设置自动验证门控，检查事实基础是否与环境状态一致。具体包括：

- 每步安全分类器（课程21）。  
- 工具调用参数验证（课程06）。  
- 检查检索内容与已知事实是否一致（课程05、CRITIC）。  
- 通过重新查询状态检测成功幻觉（文件实际创建了吗？）。

### 失败监控常见误区

- **仅标记崩溃。** 大多数代理失败产出看似有效的结果，需内容级检查。  
- **无基线。** 漂移检测需要最后的良好状态；没有基线无法判断“情况恶化”。  
- **过度报警。** 每次失败都报警。应聚类和限流。

## 构建它

`code/main.py` 实现了标准库失败模式标注器：

- 一个覆盖五种模式的合成轨迹数据集。  
- 每种模式的检测函数（工具调用、输出、重复动作的签名模式）。  
- 一个为每条轨迹打标签并报告模式分布的标注器。

运行：

```text
python3 code/main.py
```

输出：每条轨迹标签 + 汇总分布，是Phoenix轨迹聚类的简易复现。

## 练习

1. 添加“成功幻觉”检测器：代理返回成功但目标状态未变。  
2. 标注你自己产品中的100条真实轨迹。哪个模式占主导？修复成本如何？  
3. 实现“级联半径”指标：给定第N步失败，后续影响了多少步？  
4. 阅读MASFT的14种失败模式，挑选3个适用于你的产品，编写检测器。  
5. 将一个检测器接入CI作业：如果≥5%的轨迹标注该模式则构建失败。

## 关键词

| 术语                    | 常见说法          | 实际含义                             |
|-----------------------|----------------|----------------------------------|
| MASFT                 | “多代理失败分类法”     | 伯克利14种模式分类                      |
| Cascading error       | “连锁故障”         | 一处早期错误传播至后续N步                  |
| Context loss          | “遗忘约束”         | 长周期任务丢失早期回合事实                   |
| Tool misuse           | “错误工具或参数”      | 有效调用但错误使用                      |
| Success hallucination | “伪造完成”         | 代理在400响应上声称成功；状态无变化             |
| Scope creep           | “任务超范围”        | 代理做了超出要求的额外操作                    |
| Instruction-following deviation | “不服从”          | 忽视系统提示或用户约束                    |
| Sub-intention errors  | “计划缺陷”         | 计划执行中的省略、冗余和混乱                 |
