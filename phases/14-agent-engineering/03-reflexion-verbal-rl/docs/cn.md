# Reflexion：口头强化学习（Verbal Reinforcement Learning）

> 基于梯度的强化学习（RL）需要数千次尝试和 GPU 集群来修复失败模式。Reflexion（Shinn 等人，NeurIPS 2023）用自然语言做到这一点：每次失败后，智能体写下反思，存入情节记忆（episodic memory），并基于该记忆调整下一次尝试。这是 Letta 的睡眠时计算、Claude Code 的 CLAUDE.md 学习内容和 pro-workflow 的 learn-rule 背后的模式。

**类型：** 构建  
**语言：** Python（标准库）  
**前置条件：** 第 14 阶段 · 01（Agent Loop）、第 14 阶段 · 02（ReWOO）  
**时间：** 约 60 分钟

## 学习目标

- 说出 Reflexion 的三个组成部分（Actor（执行器）、Evaluator（评估器）、Self-Reflector（自我反思器））及情节记忆的作用。
- 实现一个带有二元评估器、反思缓存和新尝试的标准库 Reflexion 循环。
- 针对特定任务选择标量、启发式和自我评估反馈源。
- 解释为什么口头强化能够捕捉那些基于梯度的强化学习需要数千次尝试才能修复的错误。

## 问题描述

一个智能体在任务中失败。传统强化学习你会运行数千次尝试，计算梯度，更新权重。代价高，速度慢，大多数生产环境的智能体没有资源为每次失败支付训练成本。

Reflexion（Shinn 等人，arXiv:2303.11366）提出不同的问题：如果智能体只是思考自己为什么失败，然后带着这个想法再尝试一次怎么办？不更新权重，不计算梯度。只是在尝试之间存储自然语言。

效果是：在 ALFWorld 上，它击败了 ReAct 和其他非微调基线。在 HotpotQA 上比 ReAct 有进步。在代码生成（HumanEval/MBPP）上，当时创下最先进成果。全程不做一次梯度优化。

## 概念

### 三个组成部分

```text
Actor         : 生成轨迹（ReAct 风格循环）
Evaluator     : 对轨迹评分——二元、启发式或自评
Self-Reflector: 用自然语言写出失败反思
```

加一个数据结构：

```text
情节记忆（Episodic memory）: 先前反思的列表，作为下次尝试提示词的前缀
```

一次尝试运行 Actor。Evaluator 给分。如果分数低，Self-Reflector 生成反思（“我选错了工具，因为我误读了问题，本以为问的是 X，实际上是问 Y”）。反思存入情节记忆。下一次尝试全新开始，但能看到反思。

### 三种评估器类型

1. **标量（Scalar）**——外部二元信号。ALFWorld 成功或失败。HumanEval 测试通过或失败。最简单、信号最高。
2. **启发式（Heuristic）**——预定义失败模式。“如果智能体连续两步做同样动作，则标记为卡住。”“如果轨迹超过 50 步，则标记为效率低。”
3. **自我评估（Self-evaluated）**——LLM 给自己的轨迹打分。当没有地面真相时需要。信号较弱；推荐与工具验证配合使用（第 05 课——CRITIC）。

2026 年默认是混合：有标量用标量，没有用自评，再加启发式作为安全栏。

### 为什么它通用

Reflexion 不是新算法，更像一个命名模式。几乎所有生产中的“自愈”智能体都有某种变体：

- Letta 的睡眠时计算（第 08 课）：一个独立智能体反思过去对话并写入内存块。
- Claude Code 的 `CLAUDE.md` / “保存内存”模式：反思作为学习内容捕获，前置于未来会话。
- pro-workflow 的 `/learn-rule` 命令：将更正记录为显式规则。
- LangGraph 的反思节点：节点对输出打分，必要时导向细化。

它们都源于同一个洞察：自然语言是传递“我从失败中学到的”这一信息足够丰富的介质。

### 何时有效，何时无效

Reflexion 有效时：

- 有清晰失败信号（测试失败、工具出错、答案错误）。
- 任务类别可重复（同类型问题可再次提问）。
- 反思能改进轨迹（动作预算足够）。

Reflexion 无效时：

- 智能体第一次尝试就成功。
- 失败原因是外部的（网络断、工具故障）——反思“网络断了”不利于未来尝试。
- 反思变成迷信——刻板存储偶发异常的叙述。

2026 年需注意陷阱：记忆腐败（memory rot）。反思堆积；部分过时或错误；情节缓存变大，重跑变慢。缓解方式：定期压缩（第 06 课）、反思的 TTL、或独立的睡眠时清理智能体（Letta）。

## 构建练习

`code/main.py` 在一个简单谜题上实现了 Reflexion：生成一个和为目标的 3 元素列表。执行器产生候选列表；评估器检查和；自我反思器写出错误简述。反思存入情节记忆，用于下一次尝试。

组件：

- `Actor`——一个脚本化策略，见到反思后会改进
- `Evaluator.binary()`——基于目标和的通过/失败判断
- `SelfReflector`——生成一行失败诊断
- `EpisodicMemory`——带有 TTL 语义的有界列表

运行：

```text
python3 code/main.py
```

输出显示三次尝试。第 1 次失败，存储反思；第 2 次看到反思改进，但仍失败；第 3 次成功。对比基线运行（无反思）——停留在第 1 次答案。

## 使用方法

LangGraph 提供反思节点模式。Claude Code 的 `/memory` 命令和 pro-workflow 的 `/learn-rule` 将情节缓存外部化为 markdown 文件。Letta 的睡眠时计算让自我反思器异步运行，主智能体保持低延迟。OpenAI Agents SDK 不直接提供 Reflexion；你需要用自定义 Guardrail 拒绝低分轨迹，以及持久化跨运行的内存 `Session` 来实现。

## 部署发布

`outputs/skill-reflexion-buffer.md` 创建并维护带有反思捕获、TTL 和去重的情节缓存。给定任务类别和失败，输出能有效帮助下一次尝试的反思（非泛泛“更小心”）。

## 练习题

1. 将二元评估器换成返回距离度量（离目标多远）的标量评估器。是否收敛更快？
2. 增加反思的 TTL 为 10 次尝试。旧反思在超出该阈值后是有害还是有益？
3. 实现启发式评估器：如果动作重复，则标记尝试卡住。该策略如何与自我反思器交互？
4. 用忽略反思的对抗执行器运行 Reflexion。最简反思提示工程是怎样强制执行器注意反思的？
5. 阅读 Reflexion 论文 ALFWorld 的第 4 节。从概念上复现 130% 成功率提升：与普通 ReAct 的关键差异是什么？

## 关键词汇

| 术语           | 大众说法           | 实际含义                                       |
|----------------|--------------------|----------------------------------------------|
| Reflexion      | “自我纠正”         | Shinn 等，2023 —— 执行器 + 评估器 + 自我反思器 + 情节记忆 |
| 口头强化       | “无梯度学习”       | 在下次尝试提示词前置自然语言反思               |
| 情节记忆       | “每任务反思”       | 针对单任务类别的有界先前反思缓冲               |
| 标量评估器     | “二元成功信号”     | 通过/失败或来自地面真相的数值评分               |
| 启发式评估器   | “基于模式的检测器” | 预定义失败签名（如循环卡住、步骤过多）           |
| 自我评估器     | “LLM 自评分轨迹”   | 无地面真相时的低信号备选，常与工具验证配合使用    |
| 记忆腐败       | “过时反思”         | 情节缓冲充满过时条目；通过压缩/TTL 解决           |
| 睡眠时反思     | “异步自我反思”     | 主路径之外运行自我反思器，主智能体保持高速         |
