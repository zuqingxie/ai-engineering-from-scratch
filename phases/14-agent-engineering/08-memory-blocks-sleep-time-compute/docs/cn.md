# Memory Blocks and Sleep-Time Compute（内存块和睡眠时间计算）（Letta）

> MemGPT 在 2024 年更名为 Letta。2026 年的演进增加了两个想法：模型可以直接编辑的离散功能性内存块，以及在主代理空闲时异步合并内存的睡眠时间代理。这就是如何实现超越单次对话的内存扩展。

**类型：** 构建  
**语言：** Python（标准库）  
**先决条件：** 第14阶段·07课（MemGPT）  
**时间：** ~75分钟  

## 学习目标

- 说出 Letta 使用的三种内存层次（核心、回忆、归档）及其各自的作用。  
- 解释内存块模式：Human block（用户块）、Persona block（角色块）和用户定义块作为一流的类型化对象。  
- 描述什么是睡眠时间计算，为什么它不在关键路径上执行，以及为什么它可以运行比主代理更强的模型。  
- 实现一个脚本化的双代理循环，其中主代理负责响应，睡眠时间代理在回合之间合并内存块。  

## 问题所在

MemGPT（第07课）解决了虚拟内存控制流问题。出现了三个生产环境问题：

1. **延迟。** 每个内存操作都处于关键路径上。如果代理必须进行裁剪、总结或整合，用户等待时尾延迟会爆炸性增长。  
2. **内存腐烂。** 写入数据持续累积。相互矛盾的事实依然存在。检索被陈旧内容淹没。  
3. **结构丢失。** 扁平归档存储无法表达“Human block 总在提示中；Persona block 总在提示中；Task block 每次会话切换。”  

Letta（letta.com）是 2026 年的重写版本。内存块使结构变得明确；睡眠时间计算将合并工作移出关键路径。

## 概念

### 三个层级

| 层级     | 范围           | 存放位置            | 写入者                             |
|----------|----------------|---------------------|----------------------------------|
| Core（核心）    | 总是可见       | 主提示内             | 代理工具调用 + 睡眠时间重写           |
| Recall（回忆） | 会话历史       | 可检索               | 自动回合日志记录                      |
| Archival（归档）  | 任意事实       | 向量+KV+图           | 代理工具调用 + 睡眠时间摄取              |

Core 是 MemGPT 的核心。Recall 是带有驱逐尾部的会话缓冲区。Archival 是外部存储。此划分清晰地解决了 MemGPT 双层载荷问题。

### 内存块

内存块是核心层中的类型化、持久且可编辑的段。原始 MemGPT 论文定义了两种：

- **Human block（用户块）** — 关于用户的事实（姓名、角色、偏好、目标）。  
- **Persona block（角色块）** — 代理的自我概念（身份、语气、约束）。  

Letta 泛化为任意用户定义块：针对当前目标的 `Task` 块，针对代码库信息的 `Project` 块，针对硬约束的 `Safety` 块。每个块具有 `id`、`label`、`value`、`limit`（字符上限）、`description`（便于模型知道何时编辑）。

块可以通过工具界面编辑：

- `block_append(label, text)`  
- `block_replace(label, old, new)`  
- `block_read(label)`  
- `block_summarize(label)` — 对接近限制的块进行压缩。  

### 睡眠时间计算

2025 年 Letta 的新增功能：在后台运行第二个代理，非关键路径。睡眠时间代理处理对话记录和代码库上下文，将 `learned_context` 写入共享块，并合并或失效归档记录。

特点：

- **无延迟成本。** 主响应不必等待内存操作。  
- **允许更强模型。** 睡眠时间代理可使用更昂贵、更慢但无延迟限制的模型。  
- **自然合并窗口。** 在用户不等待时去重、总结、失效矛盾事实。  

这种模式与人类工作方式相符：你做任务后休息一晚，长期记忆会稳定下来。

### Letta V1 和原生推理

Letta V1（`letta_v1_agent`，2026）弃用 `send_message`/心跳和行内 `Thought:` 标记，转而使用原生推理。Responses API（OpenAI）和带扩展思考的 Messages API（Anthropic）在单独通道输出推理，回合间传递（生产环境中跨服务加密）。控制循环仍是 ReAct。思考轨迹是结构化的，而非提示形态。

### 这个模式的问题

- **块膨胀。** 无限使用 `block_append` 会迅速达到限制。应在写入前添加块摘要器。  
- **静默漂移。** 睡眠时间代理重写块时主代理未察觉。为块版本控制并在轨迹中显示差异。  
- **毒性合并。** 睡眠时间代理将攻击者可达内容写入核心。第27课的教训同样适用于睡眠时间代理界面。  

## 构建它

`code/main.py` 实现了：

- `Block` — id、label、value、limit、description。  
- `BlockStore` — 增删查改 + `near_limit(label)` 辅助函数。  
- 两个脚本化代理 — `PrimaryAgent` 负责提供响应，`SleepTimeAgent` 在回合间合并。  
- 显示三回合对话和块写入的轨迹，包含一次睡眠时间总结和使过时事实失效的过程。  

运行：

```text
python3 code/main.py
```

转录展示了分离：主回合快速且产生生数据写入；睡眠通过程紧缩清理。

## 使用它

- **Letta**（letta.com）为参考实现。可以自托管或云端托管。  
- **Claude Agent SDK 技能** 作为块状知识 — 技能是具名、带版本且按需加载的指令块。  
- **定制构建** 供希望控制存储后端的团队使用。遵循 Letta API 规范便于后期迁移。  

## 发布它

`outputs/skill-memory-blocks.md` 生成 Letta 形态块系统，带睡眠时间钩子，支持任意运行时，包括安全规则和引用连接。  

## 练习

1. 添加 `block_summarize` 工具，当 `near_limit` 为真时，使用模型生成的摘要替换块内容。哪个触发阈值能最大程度减少总结调用和块溢出？  
2. 实现睡眠时间归档去重：两个文本令牌重叠度 >90% 的记录合并为一条。仅在睡眠时执行，绝不阻塞关键路径。  
3. 版本控制块。每次写入时记录旧值和差异。暴露 `block_history(label)` 便于操作员调试“为什么代理忘记了 X”。  
4. 视睡眠时间代理为不受信任写入者。修改 Persona 或 Safety 块时需第二代理审核通过后提交。  
5. 将例子移植至使用 Letta API（`letta_v1_agent`）。块方案发生什么变化？原生推理如何改变轨迹形态？  

## 关键词

| 术语             | 常见说法          | 实际含义                                    |
|------------------|-------------------|---------------------------------------------|
| Memory block     | “可编辑提示部分”   | 类型化、持久、LLM 可编辑的核心内存段                |
| Human block      | “用户记忆”        | 关于用户的事实，固定在核心中                           |
| Persona block    | “代理身份”        | 自我概念、语气、约束，固定在核心中                     |
| Sleep-time compute | “异步内存工作”     | 第二代理在关键路径外执行合并操作                        |
| Core / Recall / Archival | “层级”          | 三层内存划分：始终可见 / 会话 / 外部                     |
| Block limit     | “上限”            | 每个块的字符限制；触发摘要                               |
| Native reasoning | “思考通道”        | 提供者级别的推理输出，而非提示级的 `Thought:`              |
| Learned context | “睡眠输出”        | 睡眠时间代理写入共享块的事实                              |
