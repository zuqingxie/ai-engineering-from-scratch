# Tree of Thoughts 和 LATS：深思熟虑的搜索

> 单条链式思维路径没有回溯空间。ToT（Yao 等，2023）将推理转化为带有自我评估的树状结构。LATS（Zhou 等，2024）则将 ToT、ReAct 和 Reflexion 统一于蒙特卡罗树搜索（Monte Carlo Tree Search，MCTS）框架下。24点游戏准确率从链式思维（CoT）的4%提升到ToT的74%；LATS 在 HumanEval 上的 pass@1 达到92.7%。

**类型：** 构建  
**语言：** Python（标准库）  
**先决条件：** 第14阶段 · 01（Agent 循环）、第14阶段 · 03（Reflexion）  
**时长：** 约75分钟

## 学习目标

- 将推理框架定位为搜索：节点是“思维”，边是“扩展”，价值是“多有前景”。
- 实现一个基于标准库的 ToT 风格广度优先搜索（BFS）树搜索并带自我评估打分。
- 扩展到一个玩具版 LATS 蒙特卡罗树搜索循环（选择 / 扩展 / 模拟 / 反向传播）。
- 判断何时搜索能抵消额外的令牌开销（如24点游戏、代码生成），何时单条路径足够（简单问答）。

## 问题所在

链式思维是线性的。如果首步错误，后续步骤基于错误前提。对24点游戏（用四个数字加减乘除组成24点），GPT-4 的链式思维准确率仅4%。模型早期选错子表达式无法纠正。

推理所需的是能够提出多个候选、评估它们、选择有希望的，并在遇到死胡同时回溯的能力。这就是搜索。Tree of Thoughts 和 LATS 是两大经典方案。

## 基本概念

### Tree of Thoughts（Yao 等, NeurIPS 2023）

每个节点是一个连贯的中间步骤（“一个思考”）。每个节点可扩展出 K 个子思考。大型语言模型（LLM）通过打分提示对节点自我评估。搜索可采用 BFS、DFS 或 beam search。

```text
                     (root: "从4 6 4 1中找到24")
                    /               |            \
           ("6 - 4 = 2")    ("4 + 1 = 5")    ("4 * 6 = 24")  <- 评分：高
              /   \              |                  |
          ...    ...          ...                完成
```

自我评估是核心。论文提出三种变体：`确信 / 可能 / 不可能`分类，`1..10`数字评分，候选投票。三种均显著优于链式思维，准确率由4%提升至74%（使用 GPT-4）。

### LATS（Zhou 等, ICML 2024）

LATS 将 ToT、ReAct 和 Reflexion 统一纳入蒙特卡罗树搜索（MCTS）框架。LLM 扮演三重角色：

- **策略(policy)：** 提出候选下一步行动（ReAct风格）。
- **价值函数(value function)：** 对部分路径进行评分（ToT 风格自我评估）。
- **自我反思器(self-reflector)：** 失败时撰写自然语言反思（Reflexion风格），并用其重新种子后续模拟。

环境反馈（观测）与价值函数混合，使搜索受真实工具结果而非仅模型观点影响。论文结果：GPT-4 在 HumanEval pass@1 达92.7%（最先进），GPT-3.5 在 WebShop 平均得分75.9（接近基于梯度微调）。

### MCTS 简要流程

每次迭代包含四个阶段：

1. **选择(select)** — 从根遍历到叶节点，采用 UCT（树的上置信界）。
2. **扩展(expand)** — 通过策略生成 K 个子节点。
3. **模拟(simulate)** — 从子节点使用策略进行 rollout，通过价值函数（或环境奖励）给叶节点评分。
4. **反向传播(backpropagate)** — 沿路径更新访问次数和价值估计。

UCT公式：`Q(s, a) + c * sqrt(ln N(s) / N(s, a))`。第一项体现利用，第二项代表探索。根据任务调整参数 c。

### 代价现实

搜索极度消耗令牌。ToT 在24点游戏中消耗的令牌是链式思维的100至1000倍，LATS亦类似。这代价不菲，应保留搜索于：

- 单一路径明显不足的任务（24点游戏，复杂代码）。
- 计时不急于实时、正确性优先的任务。
- 价值函数廉价且可靠的任务（代码单元测试，数学明确目标）。

任务有唯一正确答案且评估噪声较大时，搜索反而可能找到“高评分”的错误解。

### 2026年定位

大多数生产用 agent 不运行 LATS，而运行基于工具验证的 ReAct（CRITIC，第05课）。搜索主要出现在特定场景中：

- 使用测试作为价值函数的编码 agent（如 HumanEval）。
- 深度研究 agent，探索多条查询路径。
- LangGraph子图中重规划的工作流。

AlphaEvolve（第11课）是2025年的极限示例：代码进化搜索，机器可检验的适应度，突破性的性能提升（56年来的首次4x4矩阵乘优化）。

## 实践构建

`code/main.py` 实现：

- 基于样式化“挑选算术运算符”任务的微型 ToT BFS。
- 同一任务的玩具 LATS MCTS 循环（选择 / 扩展 / 模拟 / 反向传播），采用 UCT 策略。
- 价值函数组合符号分和自我评估分。

运行：

```text
python3 code/main.py
```

输出轨迹展示 ToT 对每个节点扩展三个候选（BFS），LATS 通过MCTS收敛到最佳 rollout。屏幕输出包含两者令牌消耗对比。

1. 运行玩具 LATS，比较 UCT 参数 c=0.1 与 c=2.0，轨迹有何不同？
2. 用噪声更大的打分函数替换价值函数（添加随机抖动）。MCTS 还能找到最佳叶节点吗？它能容忍的信噪比最低是多少？
3. 实现 Beam-Search 版本 ToT（每层保持 top-k），并与 BFS 比较。在紧令牌预算下哪个更优？
4. 阅读 LATS 论文第5.1节。复现 HumanEval 所需的 rollout 数量：达到报告的 pass@1 需要多少模拟？
5. 阅读 LATS 论文关于“何时 LATS 效果较差”的讨论，写一段文字归纳任务形态与搜索策略的决策规则。

## 关键词

| 术语              | 俗称                | 实际含义                                    |
|-------------------|---------------------|---------------------------------------------|
| Tree of Thoughts  | “分支链式思维”       | Yao等 — 带自我评估的思维树节点              |
| LATS              | “大型语言模型的MCTS” | Zhou等 — 统一 ToT + ReAct + Reflexion 的 MCTS|
| UCT               | “上置信界”           | 利用（Q）与探索（ln N / n）平衡的选择公式   |
| 价值函数          | “状态好坏度”         | LLM给分或环境奖励，反馈反向传播              |
| 策略(policy)      | “行动提出者”         | ReAct风格生成器，输出候选下一思考或动作     |
| Rollout           | “模拟路径”           | 从节点到叶的策略漫步，用价值函数评分         |
| 反向传播          | “更新祖先节点”       | 将叶节点得分沿路径传递，更新访问数和Q值       |
| 搜索开销          | “令牌爆炸”           | 在24点游戏中比CoT多100-1000倍令牌，需预算安排 |
